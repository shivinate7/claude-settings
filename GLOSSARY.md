# Glossary

This file gives each workflow thing one name. It holds only the terms that every repo uses. A
repo's own `GLOSSARY.md` holds its domain terms. A repo glossary never defines a term again that
this file defines.

Each row has the term, its meaning, its home and the names to avoid. The home is the rule or
record that defines the term. When a meaning changes, change the home first, then this row. Use
the term, never a name from its "Not" cell. `lint/check_glossary.py` fails a row whose home does not
exist. It also fails a new file path that uses a "Not" name. It fails a line that a change adds,
too, when an identifier, a rule anchor, a record slug or a hook message uses one. It never reads
prose. A "Not" name written `word (this sense)` retires only one sense of an everyday word, such as
`issue`. The check reads it in paths, anchors and slugs; a reviewer reads it everywhere else.

The form comes from the `domain-modeling` skill in
[mattpocock/skills](https://github.com/mattpocock/skills/tree/main/skills/engineering/domain-modeling):
one name for each thing, and a list of names to avoid.

The owner may use any word for a thing (`speak-one-name-per-thing`); the glossary gains no synonyms.

| worktree | A linked git working tree under `.claude/worktrees/`, for one agent. The Agent tool's isolation or the EnterWorktree tool makes it. | `docs/decisions/lanes-start-in-tool-worktrees.md` | — |

| debt | The filed record of a known gap, or of deferred work, that Claude is likely to hit in normal work. Each debt is one file in `docs/debts/`. | `docs/debts/README.md` | — |
| note | A finding that Claude is not likely to hit in normal work. Each note is one line in `docs/debts/notes.md`. | `rule:roles-findings-are-debts-or-notes`, `docs/debts/notes.md` | — |
| guard | A hook rule that refuses, or asks about, one act before the act runs. It stops Claude's mistakes, not an attacker. | `hooks/guard.py`, `docs/decisions/guard-guards-mistakes-only.md` | `gate` |

| fix verifier | The reviewer that verifies one fix. It is a fresh reviewer's read of the diff from a reviewed head to a new head, after any review round. It confirms that a small fix fixes one named finding and adds nothing else. It is a reviewer's read, not a `check` and not a `round` of its own, though its brief may carry the `Round N of 3 (fix check)` form (see fix verifier marker). Every fix verifier runs on sonnet (owner item 444 a). Its PASS merges the head with no further round, unless a guard or check change still owes round 3 (item 402 a, owner, 2026-11-08 06:08 CST). The name is the retrospective session's pick under the owner's leave, 2026-11-10 14:33 CST. Its flag `--fix-check` stays. | `rule:roles-review-cap-three`, `docs/decisions/hold-unsafe-after-round-3.md`, `agents/reviewer.md` | `fix check` |
| record | One file in `docs/decisions/`, `docs/debts/` or `docs/plans/`, or one rule in `CLAUDE.md`. Its slug is its id. | `rule:git-record-own-file-per-kind`, `rule:git-one-record-per-question` | `entry (this sense)` |
| feedback log | The one log of owner feedback for a repo. It replaces the per-session inbox file. | `docs/decisions/session-tiers.md`, `docs/decisions/owner-feedback-inbox.md` | `per-session inbox`, `inbox file` |
| review log | A comment on a PR that holds the review rounds, verdicts and net value for one head sha. It is a PR comment and never a file, so it is not a `record`. Its slug `pr-review-record` stays. Its function `review_record_problem` stays. Its flag `--review-record` stays. | `docs/decisions/pr-review-record.md` | `review record` |
| finding | Anything a reviewer or an audit reports. An open finding becomes a debt or a note. | `rule:roles-findings-are-debts-or-notes` | `issue (this sense)` |
| defect | Wrong behaviour in code or a check. | `rule:outcomes-tests-are-statements` | `bug` |
| round | One review and the fix after it. A change gets at most three. A fix is labelled by the review it answers, `Fix for review N`. Not built: the guard still reads the marker `Round N of 3`, which the builder brief for the fix after review N-1 carries today, on a line that starts with it, or as the leftmost marker in a first line that starts with none. | `rule:roles-review-cap-three`, `rule:roles-third-round-steps-up` | — |
| fix verifier marker | Either of two forms on a reviewer brief. `Fix check` at the start of its first non-blank line, blanks allowed ahead of it, case-sensitive: it lifts any round. Or `Round N of 3 (fix check)` at the start of any line: the guard reads it as the round marker (see round), so it lifts rounds 2 and 3 only. Either form lets that reviewer run Sonnet. Not built: the code still reads these forms; the rename to fix verifier is not built. | `docs/decisions/agent-model-cap.md`, `hooks/shared_names.py` | — |
| audit marker | The first `Audit:` on the brief's first non-blank line, with any text ahead of it. Case-sensitive. The guard lets an `Agent` or `Task` Explore spawn run Sonnet or Opus only with it; any other such spawn that names a model runs below Sonnet, and Opus without it is refused by the Opus ceiling. | `docs/decisions/agent-model-cap.md`, `hooks/shared_names.py` | — |
| guard marker | A line of a reviewer's brief that starts `Guard or check: yes`. It selects the reviewer's `1 guard` round row, so a reviewer may run Sonnet on a guard or check diff, round 1 included. | `docs/decisions/agent-model-cap.md`, `hooks/shared_names.py` | — |
| safety hole | A guard or check that lets through an act that main refuses or asks about. Always both words. | `rule:roles-review-cap-three`, `docs/decisions/hold-unsafe-after-round-3.md` | `hole` |
| refuse | What a guard does when it stops an act. The code wraps Claude Code's own `deny` and `block` values in `refuse()`. | `hooks/guard_core.py`, `docs/decisions/guard-guards-mistakes-only.md` | `block (this sense)`, `deny` |
| owner | The person who owns these repos. The owner makes grants and rulings. An arbiter makes grants and rulings too, each marked as the arbiter's and ranking below the owner's. An arbiter's grants and rulings hold inside its own repo. The owner can overturn either. `CLAUDE.md` speaks as the owner. | `rule:outcomes-grant-covers-named-act`, `docs/decisions/session-tiers.md` | — |
| chat | The reply, or the terminal question box, where a session talks with the owner. | `rule:questions-go-to-owner`, `docs/decisions/questions-go-to-owner.md` | — |
| mailbox | The git store that carries messages between a cloud session and sessions on the owner's computers. One file per message under `mail/<addr>/`; a take moves it to `done/`. | `docs/decisions/session-messages.md` | `inbox (this sense)` |
| override | A prompt from the owner that starts with `override`, or `opus` and a length. The guard then lets a refusal or an ask through, once or for a set time. An Opus override lifts only the Opus spawn refusal. | `docs/decisions/owner-override.md` | `override pass` |
| grant | Leave to do one act, once or standing, from the owner, or from an arbiter marked as its own, for its own repo only. An arbiter's grant never includes Opus. It covers the act it names, never a variant. A merge grant is one kind. Claude Code's own approve button is the platform's word, not a grant. | `rule:outcomes-grant-covers-named-act`, `docs/decisions/session-tiers.md` | `owner word`, `approval` |
| step grant | A grant that triage writes on a lane's roadmap step, in the step's `grants` field. It lifts only the Opus spawn refusal of that lane. | `docs/decisions/agent-model-cap.md`, `docs/decisions/owner-override.md` | — |
| coordinator | The one standing session that runs a repo's build. It starts triage and the batch runner, then the lanes, and talks with the owner. | `docs/decisions/session-tiers.md` | `oversight session`, `primary orchestrator` |
| triage | The standing session that a coordinator starts first, with the batch runner. It is the only writer of the roadmap. It always writes the page. | `docs/decisions/session-tiers.md` | `gatekeeper` |
| page writer | The session that writes the page. Triage always writes it (owner, 2026-11-10 14:30-14:32 CST). In a run with one lane, the lane wears triage's hat and writes it (owner, 2026-11-10 14:33 CST). | `docs/decisions/session-tiers.md`, `skills/waiting-page/SKILL.md` | waiting-page writer |
| page | The repo's one page, that triage writes. It holds the waiting items and the Status tab. | `docs/decisions/questions-go-to-owner.md`, `skills/roadmap/SKILL.md` | `triage artifact`, `roadmap page`, `waiting page` |
| batch runner | The standing session that owns the integration batch, the CI waits, the merge tool runs. It archives each lane after its merge and each lane whose PR was superseded, and archives the idle lanes that `merge --idle-lanes` lists after the integration PR merges. | arbiter | A standing session that is a decider only, one tier below the owner in its repo. It makes rulings and grants, each marked as its own (owner, 2026-11-10 14:23 CST). | topic | The one subject a lane holds. The lane's `cs-topic` tag names it, and the brief's first line names it as `Topic:`. Unrelated work starts a new lane. | `docs/decisions/session-tiers.md` | — |
