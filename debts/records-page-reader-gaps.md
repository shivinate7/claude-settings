# The records-page guard does not read some commit shapes

- **What.** The guard `records-page` reads `git add` and `git commit` calls only. It misses these shapes. (1) `git commit -i` or `--include` with paths: git commits the index plus those paths, but the guard reads only the paths, so a page staged earlier is missed. (2) `git rebase`, `git cherry-pick`, `git am` and `git revert` make commits and are not read. (3) A `sh -c`, `bash -c` or `cmd /c` script is not read. (4) `python -m lint.hook_catalog` does not count as a generator run.
- **Where.** `hooks/guard_merge.py`: `records_page_hit` (the `add` and `commit` filter), `_commit_shape` (`-i` and `--include` carry no meaning) and `_runs_generator` (`-m` and `-c` return False).
- **Decision.** `records-index-at-merge` (one records index page, rebuilt at merge time). Its "Holes, named" section names these gaps. Review round 3 found them.
- **Retire.** `records_page_hit` reads each shape. For `-i`, it judges the index and the paths together. The judge reads the page in each commit that the four commit commands make. The `-c` script text passes through the same reader. `-m lint.hook_catalog` counts as a generator run. One case per shape in `hooks/test_guard.py` shows red on the current code and green after the fix. The owner can first rule which shapes Claude could write by mistake (`guard-guards-mistakes-only`, guards stop Claude's mistakes). The rest stay as named limits.
