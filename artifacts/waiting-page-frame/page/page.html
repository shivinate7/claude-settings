Waiting Page Frame
Mockup · waiting page · Oct 26, 19:45 CDT · template at claude-settings 2ad85de

One frame for every repo, with the repo's own colour as the accent

Every repo's waiting page has the same structure, the same type and the same controls, so you learn it once. The repo shows in one place: a 4px brand band, a monogram, the repo's wordmark face and one accent colour. Pick a repo to see the same page change identity and nothing else. The items are samples.

The same decision in four repos

Identical content and layout. Only the band, monogram, wordmark and accent change. Q Max's orange and the Home app's blue fail 4.5:1 as text on white, so the frame uses a darker ink of the same hue for text and keeps the true brand colour for the band and monogram.

Is it too late? No. One template change fixes every repo at once.

Each repo's page is the same page.html from the claude-settings waiting-page skill, published unchanged. All content lives in each page's database, not in the page. So a new template means republishing that one file to each repo's existing URL: the links stay the same, and the items and answers stay in place. The only repo with a page today is the Home app. With this design the repo's identity also lives in its database (one meta/page record), so the template stays one file and never forks per repo.

One thing to check before the roll-out: that a republish keeps the database. The Artifact tool says the database lives with the artifact's URL, but nobody has measured it on a waiting page. One republish of the Home app's page and a read of its items settles it. Unmeasured until then.

Shared by every repo

Layout and order of sections. Body and heading type (IBM Plex Sans, Plex Mono for numbers). Neutrals, text colours and semantic colours: green for saved, amber for "holds up work". Card, option, note and button shapes. Every word on the page except the repo's name.

Set by each repo

A brand fill for the band and monogram. A text-safe ink of the same hue for numbers, links, the pick tag, the primary button and the focus ring. A dark-theme value. A wordmark face, used for the repo name only. A one-letter monogram. The page title, so each repo's page has its own name in the gallery.

Never set by a repo

Body font, text colour, background, spacing or contrast. A repo's own ground colour (Mail Day Ledger's parchment, for example) bleeds in only as a 4% tint, so all eight pages read the same at a glance. Three repos are blue, so colour alone cannot tell them apart. The name and monogram do that job.

The choices, and why

  1. Uniform frame, accent identity. You move between eight repos' pages. If each looked different you would relearn where the Save button is each time. A fixed frame turns answering into a habit, while the band and wordmark tell you at once which repo you are in. This is how GitHub, Linear and Stripe theme a workspace: one product, a per-workspace colour and logo.
  2. What holds up work goes first. The current page sorts by number only. Here, items that block a running lane come first, with an amber edge and a "Holds up" line that names what waits. Decisions come next, then hands-on tasks.
  3. The recommendation sits above the options. You read "My pick: a, because…" before the choices, so a fast yes takes one look. Gain and lose sit side by side under each option, so you compare across options without reading a paragraph each.
  4. Long context folds. The first two sentences show. The rest opens under "More context". The current cards show every line, which makes a page of 20 items very long on a phone.
  5. One Save for the whole page. Pick on several cards, then "Save 3 answers" in the bar. Each card keeps its own Save as well. The bar always says how many picks are not saved yet, so nothing is lost by leaving.
  6. An answered card becomes a receipt. One green line: what you chose, when (CDT), where it goes, and Change. It stays in place until you reload, so the list does not jump under your finger.
  7. Time and age, in CDT. Each card says how long it has waited ("2 days") and the summary names the oldest. The current page shows the browser's local time with no zone.
  8. Legibility floors. Text at 4.5:1 or more in both themes, measured for each repo's ink. Every control is 40px or taller. Numbers in a mono face with tabular figures, so 9 and 19 line up.

What I would change in the template

In priority order. Nothing in claude-settings is changed by this mockup.

  1. Add an identity record. meta/page.identity: {name, mark, fill, ink, dark, face}. The page reads it, sets the four colour tokens and the title, and falls back to a neutral slate when it is missing. The page computes the ink's contrast on load and darkens it until it reaches 4.5:1, so a bad value cannot ship.
  2. Add a holds field to items. Free text, such as "lane c44 is parked". The page sorts items that have it first and draws the amber edge. The skill's "Add an item" step asks the session to fill it when a lane is waiting.
  3. Move the pick above the options and put gain and lose side by side. A layout change only. The database shape does not change.
  4. Fold long context after the first two sentences.
  5. Add "Save N answers" to the bar, and show the unsaved count. It writes the same answers/<id> records as each card's Save, one by one.
  6. Keep answered cards in place as a receipt until the next load, instead of removing them while you read.
  7. Name the time zone and show age. Format every time with timeZone: "America/Chicago" and "CDT" or "CST".
  8. Raise targets to 40px and shorten the bar to fit one row at 390px.
  9. Change the skill's "Make a repo's page" step: step 3 also writes identity, with the values from this table. Add a step "Update every page": republish page.html to each URL in the repos' extras files.

Portability: yes, port to every repo. The point of the page is that it is the same in each one.
