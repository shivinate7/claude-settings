What it is today

Yes, it is still on main, and it runs in every repo's local Claude Code session, because the install copies it into your user settings. It does not run in these claude.ai project threads: here, the project instructions do the same job by hand (catch every item in a burst, say where each went).

How it works:

  • Open. A message whose first word is fb or fb: starts capture. Every owner message after it is saved, with its time, to a file outside git: ~/.claude/handoffs/<session>.inbox.md.

  • Close. fb done (at the start, or as the last line), or 10 minutes of quiet, or a Sonnet judge that runs in the background on each message and decides it is no longer feedback.

  • Jot gate. A Stop check will not let the turn end until every saved message has item lines in a fixed format: an id, a kind (ruling, task, question, note, standing) and a home. Rulings and tasks must name a tracked file. While capture is open, it reminds you each turn to send fb done.

  • Why it exists. A session acted on the first item of a burst and lost the rest (decision owner-feedback-inbox).

The archaic part is the ceremony, not the goal. Most of the code, tests and debt notes exist to parse two magic words and guess when a burst ends.

What the project has built since

  • Filing at once (o15, tasks and rulings land in tracked files): a session's catches go to the repo's decision, debt or todo files in the same turn. The jot gate already enforces this for fb items.

  • The waiting page (c71, everything waiting on you on one page): one page per repo; your save there counts as your word.

  • A save on the page wakes the session (c99, a visible reply to a save): built, in review. The page sends an artifact comment, and each session watching the page wakes. Unmeasured on a real page so far.

  • The outbox (c98, fewer messages): threads drop notes in a file; triage files them.

A, in more words. The hook stops waiting for fb. It saves every owner message, including ones you send while the session is still working, which is exactly when a burst gets lost. The Stop check asks for item lines only on a real burst: two or more messages in one turn, or one message with several lines or bullets. A plain one-line ask needs no jotting, so normal turns pay nothing. Deleted: fb/fb done, the 10-minute timer, the Sonnet judge, and the edge-case tests and debt notes about how fb done is typed. Kept: the jot format and the tracked-home check, which already work.

B, in more words. Trust the session and a rule, as these project threads already do. Simplest, but your global rules say a rule that can be a check should be one, and this one guards a real incident.

C, in more words. The inbox becomes something you can see and use from the phone. It is the best experience once the page is everywhere, but it depends on two things that are not proven yet. It is an addition to A, not a replacement.

My pick

A now, with C as a later step. A removes all the ceremony you dislike and keeps the one guard that stops a lost burst, with no model calls. Once c99 has run on a real page and repos have their pages, C adds a phone-friendly notes box that feeds the same inbox.

Open question for the build: the exact "long message" line count. I would start at three or more non-blank lines, or two or more bullets, and adjust after a week of real use.
