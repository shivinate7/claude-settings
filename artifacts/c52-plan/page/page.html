How a change lands

The same layers claude-settings already uses (roles-each-layer-proves-once), with threads in place of local agents.

  1. The advisor (this thread or its successor) picks the step and writes its brief into the step's Ask, as today.

  2. The coordinator opens one build thread per lane. Each thread has its own container and branch, so lanes run in parallel without touching your PC.

  3. In the thread, a test-author writes the new cases and shows them red. Then a builder makes them green. Both are subagents of that thread, run one after the other.

  4. A fresh reviewer, a separate thread or subagent that never saw the build, reads the diff. Up to three rounds, as roles-review-cap-three says.

  5. Lanes ready at the same time join one integration PR. CI runs on Linux, Mac and Windows. If a run goes red, the thread fixes the lane or drops it.

  6. Merge through the merge tool, not GitHub's button. merge/merge.py also rebuilds the records page (records-index-at-merge), claims record numbers and deletes lane branches. A button merge skips all three. So you run one command from any local claude-settings session: python merge/merge.py <PR number>. Or the cloud runs it, if gh works here (unknown, the pilot checks).

  7. Your machines pick up the merge at the next session start, through the auto-pull from #568. Then the advisor updates the step, the cull numbers and the brief.

Unknowns and risks

  • gh in the cloud. Unknown whether merge/merge.py can run here. If not, you run the merge, which is the plan anyway.

  • Branch deletes. Unknown whether a cloud session may delete remote branches. The merge tool does that at merge.

  • Two writers on claude-settings. Goal 3 locally and cloud threads at once can collide on files. Cover: the open-files check before each lane, and goal 3's files are known (hooks/guard.py, agents/).

  • Container cost. Each thread is a fresh clone. Cheap for this repo; unmeasured for many lanes at once.

  • Rules written for local sessions. Some claude-settings rules assume local tools: verdict, ListAgents, the handoff path. Cloud threads follow their intent and say where one doesn't fit. Each misfit becomes a note on c52.

  • The advisor's own judgment. If this thread both plans and ships, it can grade its own work. Cover: build threads are separate, and reviews come from fresh readers.
