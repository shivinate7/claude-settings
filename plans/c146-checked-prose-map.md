# c146: checked-prose map

**Brief.** Roadmap step c146, "The map says how the code fits together, in checked prose, in every repo". It comes from shiv's ask of Oct 27 15:28 CDT. All facts about main were checked against `e0f9e2d9` (origin/main, "Merge pull request #723").

**Not read.** banchi's `docs/map.py` and its decision-context are the nearest working example. That repo is not available in this session, so this plan says nothing about how they work. See open question 5.

## 1. Goal

The map is the first thing shiv and the AI read before they answer "how does X work". It does four jobs:

- **Roles.** It says what each file does, in one plain sentence.
- **Homes.** It names the shared home of each capability. A builder then extends that home and does not build a second copy (topic t18, "One home, then variants"; `rule:building-one-home-per-capability`).
- **Key facts.** It records facts such as a wait time, a limit, or the folders a scan skips, so a reader does not dig through code.
- **A check.** A check proves that each fact in English matches the code.

**Is this the right avenue? Yes, on one condition.** Prose that nothing checks rots. Then it misleads the AI with confidence, which is worse than no map. So each fact cites the symbol it describes, and the check reads that symbol's value and fails when the two disagree. The map also refuses an unchecked number in its prose. A map without this check is the wrong avenue, and this plan does not build one.

## 3. Design

The smallest thing that works is one new check, MAP9, in the existing home `map-check.mjs`, plus one new line form. No new tool and no second map.

### The fact line

A fact line is an indented list line under a map line. It starts with a word, never a backtick, so `LIST_ITEM_TOKEN_RE` never reads it as a map line. It ends with ` — ` and one backtick cite:

```
- `lint/find_copies.py` — Lists the copies a child repo holds of claude-settings things.
  - A near-equal file needs 12 significant lines. — `MIN_LINES = 12`
  - A child file over 2 times the parent's lines only quotes it. — `CHILD_GROWTH = 2`
  - Parent files under examples and templates are never copies. — `TEMPLATE_DIRS = {"examples", "templates"}`
  - Starts git with no window, through the one home. — `uses hooks/_nowindow.py:run`
- `skills/plain-english-map/scripts/lib/lazy-typescript.mjs` — Loads typescript for the skill.
  - The skill pins typescript ~5.8.2. — `package.json: dependencies.typescript = "~5.8.2"`
```

**Two cite forms:**

- **Value: `[file: ]SYMBOL = LITERAL`.**
  - With no file, the file is the parent map line's file.
  - `LITERAL` is a JSON literal. `{…}` means an unordered set, and `[…]` means an ordered list.
  - For a `.json` file, `SYMBOL` is a dotted path with `[*]`, the same grammar as `rule_audit.py` → `_walk`.
- **Relation: `uses FILE[:SYMBOL]`.** The parent file imports `FILE`. When `:SYMBOL` is given, the parent file also refers to that symbol.

**A new section, `## Homes`.** Each line has the form `- ` + capability in words + ` — ` + backtick `FILE:SYMBOL`. Example: `- no-window child start — `hooks/_nowindow.py:run``. The AI reads this section before it builds.

### How the check reads a value

The rule `building-scanner-respects-strings` asks for the language's own parser, so each language gets its own reader:

| Source | Reader | Cost |
|---|---|---|
| `.py` | One `python3 -I` child for the whole run. It gets every (file, symbol) pair on stdin, and uses `ast.parse` plus `ast.literal_eval` on module-level `Assign`/`AnnAssign`. Imports and references come from `ast.Import`, `ast.ImportFrom`, `ast.Attribute` and `ast.Name`. A module name resolves to the one tracked file with that base name, which covers `sys.path.insert` imports such as `import _nowindow`. | 1 process start |
| `.json` | `JSON.parse` plus the dotted path | none |
| `.ts .tsx .mjs .js` | The `typescript` parser via `lazy-typescript.mjs`, loaded only when a fact cites such a file. Imports come from `importTargets`. | none extra |
| Any other extension (Swift, SQL, shell) | A line regex `^\s*(let\|const\|var\|readonly)?\s*SYMBOL\s*[:=]` over the `blankComments` text, then a literal parse. This is a stated limit, not a parser. | none |

### What MAP9 fails on (one `[FAIL] MAP9` line, every cause joined by `; `)

1. **The code moved.** Message: `docs/map/lint.md:7 says MIN_LINES = 12, and lint/find_copies.py has 10`.
2. **The prose and the cite disagree.** Each number in the prose part must equal the cited number. For a set or list, each item must appear in the prose. Message: `docs/map/lint.md:7 prose says 15, and its cite says 12`.
3. **The symbol is gone.** Message: `docs/map/lint.md:7: lint/find_copies.py has no module-level MIN_LINES`.
4. **A relation broke.** Message: `docs/map/lint.md:10: lint/find_copies.py no longer imports hooks/_nowindow.py`, or `…imports it but never uses run`.
5. **A home broke.** Message: `docs/map/homes.md:3: home hooks/_nowindow.py:run is not tracked`, or `…has no run`.
6. **An unchecked number.** A digit outside backticks in a map line, a table line, a screen line or a trace step fails, because a number belongs in a fact line. Message: `docs/map/hooks.md:4 holds the number 30 with no cite; move it to a fact line`. This is how the check enforces the condition in section 1.
7. **A reader could not run.** If `python3` is missing or a file does not parse, the result is unknown and reads FAIL. Message: `could not read 3 Python facts: python3 not found`. It never reads PASS.

### Format version and scope

- **Format version.** `MAP_FORMAT_VERSION` goes up to 3, with a no-op upgrade step in `STEPS`. A pinned version 2 copy, such as q_max's, then refuses a version 3 map instead of passing it without reading the facts. That avoids a silent green.
- **Scope.** One new optional key, `mapPaths`: a list of path prefixes that MAP1 and MAP2 cover, defaulting to the whole repo. It lets the pilot start small (open question 1). It is one form for every repo, not a variant for one repo, so it does not break the uniform ruling in t18.

### Out of scope

- Finding a second copy of a capability is not MAP9's job. Copies across repos belong to `lint/find_copies.py` (r5). Copies inside one repo stay a reviewer's call (open question 6).
- In claude-settings, hook roles stay in `docs/catalog.md`. The map adds homes, relations and facts. It does not restate the catalog.

## 5. Cost

- **Process starts per run:**
  - one `node`;
  - two `git ls-files` (`gitLsFiles`, plus the one in `validateMapConfig`), which exist today;
  - one `python3`, only if there are Python facts.
  - New in total: at most one start.
- **Files written:** none. The check only reads.
- **How often:**
  - Once per CI run of the `gates` job: each PR push that is not a draft, each push to main, and the nightly cron `17 3 * * *`.
  - Also when a session runs the skill's check command.
  - Never per commit, per tool call or per session. No hook and no githook are added (`rule:outcomes-mechanize-rules`).
- **Runtime (estimate, step 8 measures it):**
  - Under 1 s for the pilot: about 6 files, 10 facts and 1 python3 start.
  - Plus about 10 to 20 s of `npm ci`, only if MAP8 needs typescript in claude-settings.
  - The map tests add about 10 cases to the existing "Mod and map-skill tests" CI step.
- **Reading cost for the AI:** the map files only, read on demand when a question needs them.

## 6. Port

**Yes, once the pilot has held green through one cull.** The reason is the same as the brief's. A repo's roll-out should carry the map that keeps it honest, and the format must be one format everywhere (t18, uniform ruling Oct 27).

Each roll-out visit (r5, which comes after this step) does four things:

1. It points the repo at the install link, not a copy. q_max deletes `.claude/skills/plain-english-map` (o6 note: it differs in SKILL.md and four scripts), and `lint/find_copies.py` lists it as the checklist.
2. It upgrades the repo's map to version 3.
3. It moves each number in the repo's prose into a fact line.
4. It adds the map check to the repo's CI.

banchi converts its `docs/map.py` facts to the shared form, or the shared form takes banchi's syntax first (open question 5). For a repo in Swift or another language without a parser here, the regex reader is the stated limit.
