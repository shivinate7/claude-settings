# Waiting page c190, part 1: links on an option card

Mockup: `c190-option-links.html`. Screen: `skills/waiting-page/page.html` at 1cc47f01, `optCard` and `buildCard`. Its `#pagecss` is that file's CSS, lines 8 to 284. Its `#newcss` holds only this step's changes, with today's value in a comment. Measured with headless Chromium at 390 and 1280, light and dark. Fonts fall back offline, so a height that depends on text is approximate. `layout.py devices` printed "unknown" for this repo, so the mockup draws the brief's sizes.

1. Row place. A (pick): `<div class="links">` after `.how` and before `.tr`. The link sits under the step it serves ("press Merge"). C: the row sits after gain and lose, just above the pick. Gain of A: the owner reads the step and its link together. Loss of A: gain and lose move down 52px on every card of the item. Gain of C: gain and lose keep their place. Loss of C: the link is far from the step that names it. Pick: A.
2. Tap box. A (pick): `.opt .links a` is `inline-flex`, centred, with a 44px min-height and a 4px gap before the arrow. The text keeps today's `.links` look: 15px, `--acc`, underlined, then the arrow. B: today's look as it is, a link about 23px high. Gain of A: it meets the 44px touch floor in `a11y.md`. A near miss on a 23px link lands on the `<label>` and picks the option. On a task card, the same miss does nothing. Loss of A: the card is 21px taller than with B. Pick: A. Departs from: today's `.links` look (`page.html`, `.links` CSS and the task render in `buildCard`). Not blocking.
3. Row only when needed. `buildCard` adds `olinks` to `.opts` only when some option of the item has links, as `pics` does. Then `.opt` spans 5 rows (6 with `pics`), and a card with no links gets `<span class="nolinks">`, as `.nopick` does today. Gain: rows still line up across cards (measured: `.tr` tops equal at 1280), and an item with no links keeps today's card (189px at 1280, state `none`). Loss: a card with no link carries an empty row and one more 8px gap. Pick: yes.
4. No script stops the pick. By the HTML spec, a press on an `<a href>` inside a `<label>` does not run the label's activation. Measured in Chromium, each size and theme: a tap on the link opens a new tab and leaves the radio unchecked; a tap on `.how` picks the option. Do not add `preventDefault` or `stopPropagation` to the link. The radio's name stays `aria-labelledby` the `.lab`, so the link text is not in it.
5. Link name. The arrow is `<span aria-hidden="true">↗</span>`, and `<span class="sr">, opens in a new tab</span>` follows it. Gain: a screen reader says where the link opens, not "north east arrow". Loss: none measured. Pick: yes. Departs from: task links today end in the text " ↗" (`buildCard`). Use one link helper for both card kinds; the task link then gets the same name. Not blocking.
6. Contrast, measured: the link on `--surface` is 7.06 light and 7.54 dark. On a picked card (`--acc-soft`) it is 6.12 light and 6.52 dark. Each passes 4.5. A brand that sets `--r-ink-*` and `--r-soft-*` is not measured.
7. Pictures and links together: the `#newcss` gives `.opts.pics.olinks .opt` 6 rows. The mockup does not draw that case.
