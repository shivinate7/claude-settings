# Accessibility floor

Each screen meets WCAG 2.2 level AA. The lines below name the parts that the owner's repos check.

| Part | Floor | Source |
|---|---|---|
| Contrast | Text 4.5:1. Large text, a control edge, a focus ring and a state cue 3:1. A reading under the floor stays only by a named ruling. | q_max D-648 (contrast floor); ios-adblock `AdBlockApp.swift` (blue tick for 3:1) |
| Target size | 44 by 44 CSS px on touch. 24 by 24 CSS px for a mouse. On iOS, 44 by 44 pt (Apple HIG). | Owner ruling, 2026-10-11; WCAG 2.5.8; Apple HIG |
| Motion | Reduced motion stops each animation, JavaScript too. Only a busy indicator continues to turn. | q_max D-253 (motion stops when asked); banchi `docs/DESIGN.md` |
| Text size | Web text zooms to 200% and loses no content. iOS text follows Dynamic Type through the accessibility sizes, and a row stacks before it clips. | ios-adblock `AdBlockApp.swift` (`NameAndState`) |

Labels and focus rings are covered by Vercel web-interface-guidelines. The house facts it lacks are in the web checks below.

## CI check, web

Run `@axe-core/playwright` in the repo's Playwright suite. Run it on each changed route, at each
width and theme that the route ships in. Pass is zero violations.

```ts
import AxeBuilder from '@axe-core/playwright'
const r = await new AxeBuilder({ page })
  .withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'])
  .analyze()
expect(r.violations).toEqual([])
```

- The `wcag22aa` tag turns on the `target-size` rule (24 px). In axe-core 4.13 that rule is off
  by default.
- A known violation goes in a list keyed by rule and selector, with an owner and a reason. The
  test fails when a listed entry does not fire, so the list only gets shorter. Source: banchi
  `app/tests/gallery.spec.ts` (`AXE_KNOWN`); q_max D-648.
- Run axe in a real browser. Under jsdom, axe reports contrast as "incomplete", which reads like
  a pass (sillage `CLAUDE.md`).
- A field with only a placeholder passes axe. Assert bound labels in a test (sillage `CLAUDE.md`).
- A name gives the act and its target, such as "Volume up for Kitchen" (home `ios/HomeApp/Views.swift`). Each icon is aria-hidden, so an icon is never the accessible name of anything (banchi `docs/DESIGN.md`, icon set).
- Hand checks, because axe does not read them: a layer keeps focus inside, closes on Escape and returns focus to the control that opened it (banchi `docs/DESIGN.md` UX-090); reduced motion; 200% zoom.

## CI check, native iOS (Swift)

Axe does not apply. Call the XCUITest audit on each changed screen, in a UI test that CI runs on
a simulator with `xcodebuild test`. It needs Xcode 15 and iOS 17 or later.

```swift
func testAccessibilityAudit() throws {
    let app = XCUIApplication()
    app.launch()
    try app.performAccessibilityAudit()
}
```

- The audit reads contrast, hit region, element description, Dynamic Type, clipped text and
  traits.
- No owner repo runs it yet (home, ios-adblock). Its fit there is unmeasured.
- Hand checks: Reduce Motion, VoiceOver order, and each screen at the largest accessibility size.
