# A queued boot holds the Mac lock through its lease wait

- **What.** bin/sim-test takes the Mac lock before it picks a device. It keeps the lock until the device is up and its lease is held. A run that queues for a lease keeps the lock while it waits. So a reuse of a free Duo waits behind it, and exits 1 when that wait passes SIM_TEST_LOCK_WAIT (300 s). A queued boot can wait three times, each up to 300 s: for the lock, then for a `--reuse` lease, then for an own-boot lease when the Duo is down after that grant. Its worst wait before a boot is 900 s, over the 600 s Bash cap. A queued run that must boot after a `--reuse` grant waits twice under the lock, each time up to SIM_LEASE_WAIT. The harm: a free phone sits unused, and a queued boot can outlast the Bash cap.
- **Where.** bin/sim-test: `acquire_lock` (the lock), `take_lease` (the queued take), and `release_lock` after the device is up. The waits sit in bin/sim-lease (`cmd_take`, SIM_LEASE_WAIT, default 300) and in bin/sim-test (SIM_TEST_LOCK_WAIT, default 300).
- **Decision.** `sim-test-is-the-one-boot-path`, the one boot path (ruling 1: the lock is held only while a run picks and boots its device; ruling 2: the lock wait stays under the 600 s Bash cap).
- **Retire.** A case added to `lint/test_sim_test.sh` passes. It shows that a queued run frees the lock before its lease wait, so a reuse of a free Duo does not wait behind it. The queued boot's worst wait must stay under 600 s.
