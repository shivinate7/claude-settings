# The comment narration check misses some history wording and flags some legit lines

**What.** The check has no suppression marker. It flags these legit lines. It flags a line with a hex id (read lint/check_comment_narration.py PATTERNS). It flags "formerly" in domain text, such as "Columns formerly named amt are still read". It flags "changed from a draft to a shipped state". It flags "Previously used tokens are rejected" at a sentence start. It flags "Rows added after review stay pending". It also flags "the old behaviour" before an irregular participle, such as "used by callers". The history phrase pattern names fixed word forms, so it misses other history wording (read lint/check_comment_narration.py HistoryPhrase). It misses "previously" inside a sentence. It misses "Changed from list to set". It misses "Added in response to review". It misses "This used to return None". It misses "the old behaviour" before a past verb with by, for, on, in, at, with or from after it, such as "failed on". It misses a dated history line after until, effective, valid or expires, such as "Until 2026-10-30 this returned None" (read lint/check_comment_narration.py DatedText). It also passes history whose noun is snapshot or run, such as "changed from the old snapshot format to JSON" (read lint/check_comment_narration.py HistoryPhrase). A block moved in from an unscanned file shows as added (read lint/check_comment_narration.py added_lines). An unreadable file does not stop the scan. The other files are read, their hits print, and the run exits 2 as unknown. The JS, TS and Astro part needs npx and the registry, or tsc on PATH (read lint/check_comment_narration.py node_comments). Without them the run exits 3, and code-check goes red (read actions/code-check/code_check.py comment_check). This holds even for a change that only deletes JS lines, since the file is listed before its hunks are read. No test pins a node per-file error row (read lint/test_check_comment_narration.py). No test pins the Astro attribute-expression, is:inline, typed script or void-tag cases (read lint/test_check_comment_narration.py). New vendored code in a pinning repo cannot be cleared. The exclude list may only shrink (read actions/code-check/code_check.py). The shell reader, `shell_comments`, has no parser (read lint/check_comment_narration.py shell_comments). So it misses a comment inside the expansions of an unquoted heredoc body. A `<<` shift outside `((`, `$((` and `a[...]`, such as `let x=1<<2`, reads as a heredoc and exits 2 (read lint/check_comment_narration.py sh_heredoc_bodies). In `ls x[ ; cat <<EOF` the lone `[` opens a subscript. So the heredoc body reads as code and may exit 2 (read lint/check_comment_narration.py sh_code_end). After `[[ (a)]] && ...`, a later `(b)#c` on the same line misses its comment (read lint/check_comment_narration.py sh_code_end). Inside the gloss of a real `round-N` decision id, a round number with the same N passes whatever wording surrounds it (read lint/check_comment_narration.py ReviewRound). An example is "(decision hold-unsafe-after-round-3, fixed after round 3)". The phrase "review round" and the other patterns still flag inside the gloss. zsh files are not scanned (read lint/check_comment_narration.py shell_comments). A `case` after `time -p` or `coproc` reads as a plain word. So its `esac` has no case, and the file exits 2 (read lint/check_comment_narration.py sh_code_end). A `#` after `|` opens a comment, such as in `^(a|#b)`. The rest of the line is skipped.
**Where.** `lint/check_comment_narration.py`, also run by `actions/code-check` in every pinning repo (read actions/code-check/code_check.py).

**Decision.** `none`.

**Retire.** Add a case to `lint/test_check_comment_narration.py` for each missed phrase and each flagged legit line in What (read lint/test_check_comment_narration.py). Each case is red on the current check and green once the check handles it.
