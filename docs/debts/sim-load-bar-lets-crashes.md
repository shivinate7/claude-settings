# The 1-minute load bar of 60 may let Duo crashes through

- **What.** Gap 4 of the sim-lease gaps plan (commit b7bc81daa): three Duo crashes came at 1-minute loads of 58 to 71, on 2026-11-05 between 21:00 and 21:25 CST (Degen coordinator, 2026-11-06). The bar stays at 60 until a Mac measure sets it. The cloud cannot make that measure: it has no Mac diagnostic reports, and the plan found no SpringBoard or PosterBoard report for 2026-11-05 to 2026-11-07. The record the measure would read, state/sim-boots.jsonl, holds no load. Each line has the device UDID, name, device type, runtime, time, and launchd pid and start (`hooks/sim_boot_record.py`, `write_record`). So the step needs a load source before it can run.
- **Where.** `MAX_1MIN` in bin/sim-lease, the 1-minute bar on every grant (60). The boot record is state/sim-boots.jsonl under the config folder, written by hooks/sim_boot_record.py.
- **Decision.** `sim-lease-tool` (ruling 1: a boot needs a 1-minute load under 60).
- **Retire.** Run the Mac step: count SpringBoard and PosterBoard reports in ~/Library/Logs/DiagnosticReports per hour, set each hour's count against that hour's 1-minute load (once a load source exists, see What), set MAX_1MIN from the result, and commit the table. Then `lint/test_sim_load_bar.py` passes: it pins MAX_1MIN to the committed table. That test cannot show a crash-free load. Only the Mac measure can.
