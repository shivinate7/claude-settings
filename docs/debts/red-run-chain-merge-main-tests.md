# The push chain does not judge a commit with no -m after a conflicted merge of main

- **What.** After a conflicted merge of main, the index holds main's incoming test lines. The push chain no longer refuses `git commit --no-edit && git push` or `git merge --continue && git push`. It passes them only because a commit with no `-m` reads as an editor commit: `_note_commit` sets `unreadable`, and `_red_run_found` then reads no hit for the whole push. So the push passes unjudged, as the decision's item 9 limit says for an editor commit. Not covered. The red-run push guard lane (slug red-run-push-guard, PR #3400) has no case for it: tests/guard/s43400-red-run-push.py holds only clean merges, and its pushes name no commit call. Missing: a fixture with a conflicted merge of main whose incoming side adds test lines.
