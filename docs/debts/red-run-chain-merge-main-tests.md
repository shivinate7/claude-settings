# The push chain does not judge a commit with no -m after a conflicted merge of main

- **What.** After a conflicted merge of main, the index holds main's incoming test lines. The push chain no longer refuses `git commit --no-edit && git push` or `git merge --continue && git push`. It passes them only because a commit with no `-m` reads as an editor commit: `_note_commit` sets `unreadable`, and `_red_run_found` then reads no hit for the whole push. So the push passes unjudged, as the decision's item 9 limit says for an editor commit. No case in `hooks/test_guard.py` pins that the merge's incoming test lines are not refused, or that the push passes unjudged. Frequency unmeasured. Claude merges main into lanes often, so it is likely to hit this. Lands with the red-run push guard lane (slug red-run-push-guard).
- **Where.** `hooks/guard_merge.py`: `_commit_paragraphs` and `_note_commit` (the unreadable path), and `_red_run_found` (the no-hit read).
- **Decision.** `red-run-trailer-on-test-commits` (red-run trailer on test commits), item 9 (push time), and item 4 (a merge is not judged; the commits it brings in are). Item 9 lands with the red-run push guard lane (slug red-run-push-guard).
- **Retire.** A new case in `hooks/test_guard.py`, red before the fix and green after. After a conflicted merge of main whose incoming side adds test lines, `git commit --no-edit && git push` passes, and a lane's own untrailered test commit below it is refused.
