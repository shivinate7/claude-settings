# A Windows roadmap fetch can outlive its bound and move the ref

- **What.** The roadmap fetch is bounded at `FETCH_TIMEOUT`, 2 s. On POSIX, `_kill_group` kills the whole process group of the fetch. On Windows it calls only `proc.kill()`, so git's transport child can keep running after the bound. That child can finish later and rewrite `refs/remotes/origin/roadmap` after a reader has judged. Incident: Windows CI job 132404611787 (CI run 43580622870, PR 3253 at head commit f78b3f2984). The case "page-form green: task on a step that names skills/waiting-page" in `hooks/test_feedback_inbox.py` failed. A fixture with the real origin URL made a live fetch, and the ref changed between two cases. The fixture fix is in PR 3253. This debt covers the product bound. Harm: on Windows the 2 s bound does not hold, and a late write moves a ref under a reader. Status: unmeasured. No Windows run reproduces the orphan child. The docstring of `lint/roadmap_ref.py` claims a group kill, and its test, `FetchProcessTests` in `lint/test_roadmap_ref.py`, is skipped off POSIX.
- **Where.** `lint/roadmap_ref.py` (`_kill_group`, `_run_group`, `fetch_roadmap`). `lint/test_roadmap_ref.py` (`FetchProcessTests`).
- **Decision.** Step `roadmap-ref-fresh-before-verdict` (the step that makes a stale roadmap ref fresh before a verdict). No decision names this finding.
- **Retire.** `_kill_group` kills the whole process tree on Windows, with `taskkill /T /F` or a job object. The close needs a case in `lint/test_roadmap_ref.py` that runs on Windows and shows a timed-out fetch leaves no child running. The Linux run skips that case, so only the Windows job proves the close.
