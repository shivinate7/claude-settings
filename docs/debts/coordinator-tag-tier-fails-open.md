# Coordinator tier fails open when the transcript holds no own tag

- **What.** Nothing writes a coordinator role file. `MERGE_ROLES` holds only `batch-runner`, and the coordinator runs no `--role` call. So a coordinator's tier comes only from its own `cs-build` tag in the transcript. `_own_tag_tier` reads the newest `get_session` result for the session's own id, plus the tags the session's own later `set_session_tags` calls added (`own_session_read` with `applied=True` in `hooks/own_session.py`). It returns `''`, and rule coordinator-scope never fires, when the transcript holds neither a `get_session` result nor a `set_session_tags` call for the session's own id. That is the case after `/clear` and with an unreadable transcript. It is also the case for a coordinator whose tag was set by another session, until it runs `get_session` on itself.
- **Where.** `_own_tag_tier` and `_cloud_coordinator` in `hooks/guard.py`; `own_session_read` in `hooks/own_session.py`; `MERGE_ROLES` in `hooks/shared_names.py`. The coordinator role and brief templates are in `skills/project-ops`. They do not tell a coordinator to run `get_session` on itself at start.
- **Decision.** `session-tiers` (the session shapes and their tier guards).
- **Retire.** A coordinator's tier holds from its first judged call, with no tag call or `get_session` result in the transcript. Or the coordinator's start steps run `get_session` first, and a case proves the rule fires then. `hooks/test_guard.py` holds that case.
