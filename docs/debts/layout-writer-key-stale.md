# The page-writer key goes stale at rotation

- **What.** The extras key `page-writer` holds the page writer's session id. Rotation step 5 now writes it, in a PR, so a rotation that runs step 5 names the new writer. The pick guard counts a send to the key id only when the send's result shows delivery. A send to an archived old writer errors, so it no longer counts. Still open: a stale id whose session is still alive accepts the send, so the guard counts that send and passes it, and the question never reaches the page writer. Also open: a rotation that skipped the key step leaves the key on the old writer.
- **Where.** `lint/layout.py` `page_writer_key`, which reads the key. `lint/report_guard.py` `question_problem`, which falls back to the key and counts its send only on a delivered result (`delivered_tool_use_ids`, `lint/_transcript.py`). `hooks/feedback_guard.py` `export_check`, which reads the key to tell the page writer when the transcript names none; a stale key naming this session makes it the writer, and a stale key naming another never exempts a session whose own export run made it the writer. `skills/project-ops/templates/operating-model.md`, rotation step 5, which writes the key. Decision `questions-go-to-owner` (clause "Each page has one writer, and the writer ranks.") and `skills/waiting-page/SKILL.md`, section "The writer", both say the key send counts only on a delivered result.
- **Decision.** `questions-go-to-owner` (each page has one writer, and every question goes to it). Its writer clause names the key and says a rotation updates it. The close rewrites that clause in place.
- **Retire.** A test that goes red while a rotation skips the key write at step 5. No such test is named yet. No test covers the stale-but-alive case, since its send delivers. The closing PR cites the run with `Retire-run:`.
