# The waiting-page-writer key goes stale at rotation

- **What.** The extras key `waiting-page-writer` holds the page writer's session id. No rotation step writes it, so after a rotation it names the old writer. Rotation steps 1 to 5 never write the key. Step 5 sets `writer` in `meta/page`, and that holds a session title, not an id. The pick guard reads the key only when the transcript has no `meta/page` read. A send then goes to the old writer. The guard passes that send, so the question reaches no one while the guard is green.
- **Where.** `lint/layout.py` `waiting_page_writer`, which reads the key. `lint/report_guard.py` `question_problem`, which falls back to the key. `skills/project-ops/templates/operating-model.md`, rotation step 5. Two texts say a rotation updates the key, and none does: decision `questions-go-to-owner` (clause "Each page has one writer, and the writer ranks.") and `skills/waiting-page/SKILL.md`, section "The writer".
- **Decision.** `questions-go-to-owner` (each page has one writer, and every question goes to it). Its writer clause names the key and says a rotation updates it. The close rewrites that clause in place.
- **Retire.** Rotation step 5 also writes the incoming session's id to the key `waiting-page-writer` in the repo's extras file. No retire test is named yet. The debt owes one: a test that goes red while step 5 leaves the key stale.
