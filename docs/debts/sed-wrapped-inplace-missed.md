# A sed behind a `find`, a pipe or a deep quote is still missed

- **What.** Rule `frozen-path` reads sed's operands where `sed` is the command word, past a wrapper (`sudo`, `xargs`, `env`) or inside a `sh -c` script, and reads the script command by command. These forms are still missed. A `find -exec sed -ni 's/a/b/' FILE \;` (`find` is no wrapper the command reader unwraps). A bare `find ... | xargs sed -i` and a bare `find -exec sed -i`, which name no target: the files they edit are never in the command (the coordinator agreed these stay allowed). A feeder behind another pipe stage (`echo FILE | cat | xargs sed -i 's/a/b/'`). A sed fed by a pipe inside a `sh -c` script. A script quoted twice (`bash -c "sed -n \"w FILE\" x"`). A `w` with no space before its file (`sed -n 'wFILE' x`, `sed -ewFILE x`): the file is no word of its own, so no path is read from it.
- **Where.** `_sed_operands`, `_sed_scan`, `_sed_nested_writes`, `_feeds_xargs` and the call site in `_shell_write_hit` of `hooks/guard_frozen.py`.
- **Decision.** `session-tiers` (tier guards, the boundary a session may not cross).
- **Retire.** Read the words after each `-exec` of a `find` as a segment of their own, read a pipe inside a nested script and an escaped quote in one, and split a glued `wFILE` into its own word. Add these cases to `hooks/test_guard.py` (family `frozen`), each refused with rule `frozen-path`: `find . -exec sed -ni 's/a/b/' <frozen hook> \;`, `echo <frozen hook> | cat | xargs sed -i 's/a/b/'`, `bash -c "sed -n \"w <frozen hook>\" x"` and `sed -n 'w<frozen hook>' x`. The suite passes.
