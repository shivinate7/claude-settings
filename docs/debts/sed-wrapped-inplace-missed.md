# A sed behind a `find`, a pipe or a deep quote is still missed

- **What.** Rule `frozen-path` reads sed's operands where `sed` is the command word, past a wrapper (`sudo`, `xargs`, `env`) or inside a `sh -c` script, and reads the script command by command. These forms are still missed. A bare `find ... | xargs sed -i` and a bare `find -exec sed -i`, which name no target: the files they edit are never in the command (the coordinator agreed these stay allowed). A feeder behind another pipe stage (`echo FILE | cat | xargs sed -i 's/a/b/'`). A script quoted twice (`bash -c "sed -n \"w FILE\" x"`). A `w` with no space before its file (`sed -n 'wFILE' x`, `sed -ewFILE x`): the file is no word of its own, so no path is read from it.
- **Where.** `_sed_operands`, `_sed_scan`, `_sed_nested_writes`, `_feeds_xargs` and the call site in `_shell_write_hit` of `hooks/guard_frozen.py`.
- **Decision.** `session-tiers` (tier guards, the boundary a session may not cross).
- **Retire.** Read a feeder behind a second pipe stage. Read an escaped quote in a nested script. Split a glued `wFILE` into its own word. Add these cases to the frozen family (`tests/guard/s18300-frozen.py`), each refused with rule `frozen-path`: `echo <frozen hook> | cat | xargs sed -i 's/a/b/'`, `bash -c "sed -n \"w <frozen hook>\" x"`, `sed -n 'w<frozen hook>' x` and `sed -ew<frozen hook> x`. `GUARD_FAMILY=frozen python3 hooks/test_guard.py` passes.
