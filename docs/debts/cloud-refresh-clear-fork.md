# Cloud refresh skips clear and fork

- **What.** In a cloud session, the refresh hook runs `install.sh --cloud` on `startup` and `resume` only. It does not run on `clear` or `fork`. The cloud `settings.json` also drops the `session_start.sh` entry, because that entry fires on startup. So on `clear` or `fork`, that entry does not run. Every other hook keeps the copy from the last startup or resume. A hook fix on main reaches the session only at its next startup or resume. The `compact` part waits on PR #3188 (adds `compact` to the refresh matcher and case `cloud_compact3`). PR #3188 is not on main yet.
- **Where.** `install.sh`, the cloud refresh hook: `"matcher":"startup|resume"` in the jq that writes `settings.json` (line 1093, beside `HOOK_CMD`). `hooks/test_install_src.sh`, case `cloud_settings1` (line 1959), which asserts that matcher (line 1989). On PR #3188's head (486ea4888), install.sh's matcher is `startup|resume|compact` (line 1093), and case `cloud_compact3` (line 2418) pins `clear` as no refresh and no startup entry. Main's `settings.json`, the `session_start.sh` entry's matcher (line 194), lists `startup|resume|compact|clear|fork`.
- **Decision.** `cloud-start-hooks-run-fresh`, cloud start hooks run the code install.sh just copied. Its line that says the `compact` and `clear|fork` entries "fire after the refresh" is wrong for `clear` and `fork`, because no refresh runs for them. It is also wrong for `compact` on main, whose refresh matcher is `startup|resume` only. PR #3188 adds `compact` and fixes that. The fix rewrites that line.
- **Retire.** The refresh matcher gains `clear` and `fork`, and `compact` too if PR #3188 has not added it. Two cases change with it: `cloud_settings1` (on main) expects the old matcher, and `cloud_compact3` (on PR #3188) expects no refresh for `clear`. The fix flips `cloud_compact3` to expect a refresh and the `session_start.sh` entry to run for source `clear`. The closing PR adds a case to `hooks/test_install_src.sh` that is red on the gap (a cloud `clear` or `fork` source runs the refresh) and green after the matcher fix. The fix lane's test-author writes it. `cloud_settings1` passes today while the gap is open, so no case catches the gap.
