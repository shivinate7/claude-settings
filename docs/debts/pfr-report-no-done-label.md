# A reviewer report with no Done label is not read

- **What.** A reviewer report whose first line is the bare verdict (`FAIL, round 1 of 3, claude-haiku-5-5`, no Done label) is not read, and nor is one that opens with a `Verdict:` prefix and no label. Under a `Done` label alone on its line, a verdict line with trailing text, an em dash or a `Verdict:` prefix is not read. Under a `Done` label alone on its line, a bare `FAIL` with no round or fix check marker is not read either. Read today: a bold or backticked verdict word or whole line, and the same-line forms (`Done: FAIL ...` with trailing text, an em dash or a `Verdict:` prefix) when a round or fix check marker is on the line. In one real lane transcript, 7 of 15 distinct reviewer reports gave no verdict, including the round 1 FAILs of PR 1628 and PR 1801. A push after them is allowed: incident class PR 1467 (push before the FAIL record).
- **Where.** The report reader in `hooks/guard_push_delete.py` (`_DONE_LABEL`, `_VERDICT_LINE`).
- **Decision.** `push-needs-review-record` (a push needs the review record of its FAIL).
- **Retire.** Read the first non-blank report line as the Done line, and match the verdict line as a prefix. A case with each drifted form refuses the push, shown by `hooks/test_guard.py`.
