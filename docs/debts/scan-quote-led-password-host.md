# The export scan passes two database-address forms with a quote-led password

- **What.** Two accepted limits of PR 2372 (branch `export-scan-key-false-alarms`, head `f71e12a0463e89bdcad6124e531fcb2cb870b0c4`). The owner accepted both to merge the PR, which clears about 2,500 false alarms on code text (owner's figure). Claude could paste such a line by mistake from a config or a script.
  - **Limit 1.** A password that starts with a quote or backtick, then `@`, then a host that starts with a quote, brace, bracket, paren or `|`. A dotted template such as `{host}.example.com` is included. Examples: `postgres://admin:'x1y2@{host}/app`, `postgres://admin:"abc@{db_host}/app`, `postgres://admin:"Sup3rS3cret"@{db_host}/app`. Both scans pass these. Owner ruling: waiting-page item 456 a, 2026-11-09 13:09 CST.
  - **Limit 2.** The same quote-led password before an IP host, with a closer after it. The closer is a quote, backtick, paren, bracket, brace or `|`. Examples: `postgres://admin:'Sup3rS3cret'@10.0.0.5"`, `(postgres://admin:'x1y2@10.0.0.5)`. The scan blanks the IP first, so the closer becomes the host's first character, and the host check reads it as code. The shape passes on page text and supporting files. Unlike Limit 1, the JSON scan still refuses it, because that scan does not blank the IP. Owner ruling: waiting-page item 465 a, 2026-11-09 14:58 CST.
  - A quote-led password before a literal dotted or IP host still refuses when no closer follows the host: at the end of the text, or before a port, a path or a space. A dotted host with no quote-led password also refuses.
  - **Wider user part, no owner ruling yet.** A user part with a quote, `|` or `$(cmd)` never matches the URL shape, on any host. Examples that pass: `postgres://o'brien:Sup3rS3cret!@db.example.com`, `postgres://{cfg['user']}:Sup3rS3cret!@db.example.com`. The email shape still refuses some: a dotted host, or an IP host in the JSON scan, when the password ends in a letter, digit or `._%+-`.
- **Where.** `skills/waiting-page/export_page.py`: the `url-credentials` shape in `SECRET_SHAPES`, and its helpers `URL_USER`, `URL_PLAIN_PASSWORD`, `URL_QUOTED_PASSWORD` and `URL_HOST_START`. `VERSION_PIN` blanks the digits after an `@`, IP hosts included. `page_kinds` applies it before the shapes run on page text and supporting files. The JSON scan (`scan`) does not blank.
- **Decision.** `waiting-data-in-repo` (a copy of the page lives in the repo, so the scan runs before any write), plus the owner's answers, waiting-page items 456 a and 465 a.
