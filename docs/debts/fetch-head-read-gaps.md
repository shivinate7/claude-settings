# The FETCH_HEAD read guard has known gaps

- **What.** Gaps a shared checkout can still hit. `cat .git/FETCH_HEAD` is no git read and passes. A fetch that fails before a `;` or `|` read still clears it, since the check reads text, not exit codes. `git -C <other> fetch` then a bare read passes, though the fetch moved another checkout's file. `git fetch` then `cd <other> && <read>` passes for the same reason. An attached `--source=FETCH_HEAD` or `--onto=FETCH_HEAD` is no word the check reads. A backtick text cut by a `;` inside it hides its read. A `$( )` read in a heredoc body is cleared by any fetch in the command, even one after it. A fetch and a read in one command still share a window another agent can fetch inside, so the check narrows the race and does not close it. `git pull` then a read is refused though the pull fetched: an over-refusal, not a miss. So is a quoted `"FETCH_HEAD)"`. The value flags `-S` and `-e` skip the ref in every verb, so `git merge -S FETCH_HEAD` and `git revert -e FETCH_HEAD` pass.
- **Where.** `fetch_head_read_hit` in `hooks/guard_merge.py`, rule `fetch-head-read`.
- **Decision.** `fetch-head-shared-race` (a FETCH_HEAD read must follow its own fetch).
- **Retire.** Refuse a `cat` of the `.git` file with the same remedy. Read the `-C` directory of a fetch, and each `cd` after it, against the read's. Read `--source=` and `--onto=` values. Walk a backtick text whole, as a `$( )` text is walked. Judge a heredoc body's `$( )` text at its command's place. Count `git pull` as a fetch. Scope `-S` and `-e` to log, diff and show, as `-m` and `-F` are scoped per verb. Cases for each pass: `hooks/test_guard.py`.
