# Time finder misses some real date and zone reads

- **What.** `lint/find_time_pinned.py` lists a date or zone read only when no time is given. A local-zone read of a fixed time still depends on the machine's zone, and the finder passes it: Python `time.localtime(EPOCH)`, `time.ctime(EPOCH)`, `datetime.fromtimestamp(<fixed>)` and `.astimezone()`. The Swift scan has no calendar category: `Date()`, `Calendar.current` and `TimeZone.current` pass, and a `Date()` in an assert is listed only as elapsed-assert. Real tests hold these forms: fixed-time zone reads in `hooks/test_guard.py` and `hooks/test_decision_watch.py` here and in banchi's `harness/tests/t7`, and `Calendar.current` in home's `ios/HomeAppTests`. `lint/test_find_time_pinned.py` pins `time.localtime(EPOCH)` and `time.ctime(EPOCH)` as clean today. Forms that only a reviewer probe wrote are in note `find-time-pinned-probe-forms`.
- **Where.** `lint/find_time_pinned.py` (`PY_CALENDAR_NOW`, the calendar scan, the Swift scan) and `lint/test_find_time_pinned.py`.
- **Decision.** `test-practices` (P5: an assert never reads the real date or zone).
- **Retire.** The finder lists each form above as calendar, the fixed-time zone cases move from clean to listed, and a red case for each shows it.
