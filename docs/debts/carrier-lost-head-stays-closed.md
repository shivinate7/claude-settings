# An open carrier that lost its head keeps its carried PR closed

- **What.** An open carrier that moves off the head of a PR it carried never reopens that PR. This happens when the carrier is force-pushed off that head, such as a stacked lane PR rebased onto the base without the lane under it. A dropped lane does not reach this gap: a batch never carries a lane it freezes at its current head, and a drop rebuilds the batch head without the lane. Accepted for now: a fix would add reads on each wake.
- **Where.** `merge/merge.py`, `reopen_lines`. It reopens a carried PR only when the carrier closes unmerged, and a lane drop leaves the carrier open. The same rule is in `skills/ci-hygiene/SKILL.md`, step 8: "A Carried note reopens only when R closes unmerged."
- **Decision.** `session-tiers` (session roles), replaced-drafts bullet. Its scope add, owner ruling 2026-11-09 21:29 CST, says a carried PR "reopens if the carrier is dropped". The bullet's reopen rule fires only when the carrier closes unmerged, so a carrier that stays open and moves off the head does not reach it.
- **Retire.** A new case in `merge/test_close_replaced.py`, red before the fix and green after: an open carrier that no longer holds the carried PR's head reopens that PR.
