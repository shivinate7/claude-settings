- desktop-delivery-marker: a desktop send's result text holds its delivery state. `(delivery: delivered;` counts as delivered (DESKTOP_DELIVERED in `lint/_transcript.py`). `(delivery: queued;` (DESKTOP_QUEUED) marks a send its session holds and has not run: it counts only with a same-turn one-time check-in or a later reply from the target (`_queued_to` in `lint/report_guard.py`). Any other state, such as undelivered, does not count. Two queued wordings were measured in local desktop transcripts, "that session is holding it" and "behind other work". The code reads only the marker, never the wording after it. The form is measured, not documented: no vendor document states it. If the app changes the text, a delivered send stops counting, which fails on the safe side. A failed desktop send whose error text names an act (such as `git push`) counts as a failed try of that act in `failed_tries` (`lint/report_guard.py`), as the older send tool does. Seen: 2026-11-25 x1
