# Hook, judge, mod and skill catalog

This page says what each hook, judge, mod and skill in this repo does. A script writes it. Do not edit it by hand.

Run `python3 lint/hook_catalog.py` to write the page again. CI runs `python3 lint/hook_catalog.py --check`. The check fails when the page is stale or a source text is empty.

Where each text comes from:

- A hook runs a script. Its text is the first paragraph of the script docstring, or the leading comment block of a shell script. A script that runs under more than one flag or event needs a `Modes:` paragraph in its docstring. Each row takes the line for its flag or its event. A hook whose command is inline shell has no script, so its text is one line in `lint/hook_catalog_inline.json`. The key is the event and matcher, then a short hash of the command. A changed command fails the check until a person reviews its summary.
- A judge is a prompt hook that a model answers. Its key is the first sentence of the prompt. Its text is the rest of the prompt, up to the standard clause that blocks only on a clear breach.
- A mod is an enabled mod from this repo. Its text is the intro of its `README.md`. A mod with no README takes the `description` in its `plugin.json`, and must hold a `SOURCE.md`, which says where it came from. The page omits that file's text.
- A skill is a folder under `skills/`. Its text is the `description` in its `SKILL.md` frontmatter.

Model and effort come from the model table (decision `agent-model-cap`, the model per role). A hook with no row in that table calls no model, so its row says "no model". A judge takes the `model` field of its prompt hook, and a prompt hook has no effort field. A skill has no model pin, so its row says "no model" and effort "none". The model table has no row for a mod, so a mod row says "not listed". A mod may still call a model.

## Mods

| Key | Kind | Event | Matcher | If | Model | Effort | What it does |
|---|---|---|---|---|---|---|---|
| `mods/token-weather` | mod | - | - | - | not listed | not listed | A live forecast of the context window, drawn above the prompt: a weather icon, the fill percentage, and a chart of the last turns. |
| `mods/desktop-statusline` | mod | - | - | - | not listed | not listed | Status band above the prompt in the Claude Desktop app's Code tab: folder, git branch and state, session age, prompt count and cost, 5-hour and weekly plan usage limit meters with reset countdowns, last-turn model, duration and cache hit rate, idle time against the prompt-cache TTL, compactions, and running agents. Toasts at 80% and 95% of a usage limit. Draws only on the desktop surface, so a CLI statusLine is left alone. |
| `mods/plain-diff` | mod | - | - | - | not listed | not listed | A mod. It adds one command, `/plain-diff`. It draws nothing else. The command opens a pane. The pane lists each changed file. Each file has a short note in plain English above its diff. The note says what changed and why it matters. |
| `mods/session-board` | mod | - | - | - | not listed | not listed | A mod. It adds two commands. `/board` shows the local sessions and agents and what each one is doing. `/safe-stop` checks that a session has no running work before you stop it. It also refuses a question box while the session's own work runs. It draws nothing else. It calls no model. |
| `mods/decision-watch` | mod | - | - | - | not listed | not listed | A mod. It runs the decision watch on each completed turn (`turn.complete`) with this session's own model login. It replaces the Stop hook row. It never refuses a turn. A FLAG or UNKNOWN verdict shows in the session as a toast. An ALLOW verdict shows nothing. Each config notice shows as its own toast, marked `Decision watch notice:`. |

## Skills

|---|---|---|---|---|---|---|---|
| `skills/ci-hygiene` | skill | - | - | - | no model | none | Use when a session creates or edits CI config (GitHub Actions, workflow files, .github/workflows, other CI files), or when the user says CI is slow, queued, or flaky, or says "ci-hygiene". Not for ordinary code edits. Keeps CI fast, cheap, and trusted. |
| `skills/compliance-check` | skill | - | - | - | no model | none | Use when the user asks how well a repo follows the global rules, or says "compliance check", "audit this repo against CLAUDE.md", or "bring this repo into shape". | `skills/design-explore` | skill | - | - | - | no model | none | Use before the builder on a lane that explores a screen, a new screen or a redesign. | `skills/design-review` | skill | - | - | - | no model | none | Use after a change to a screen in a repo that has screens. Runs two blind design reviews of the changed pages, then compares them with the repo's design records. Its Mockup set check also flags a set of explore mockups that all keep today's structure. | `skills/fresh-prose` | skill | - | - | - | no model | none | Use when a session writes or updates a README, docs, CLAUDE.md, agent files, or decision records, or when the user says "stale docs" or "fresh-prose". Makes prose hard to go stale, by binding each claim to a check. |
| `skills/impeccable` | skill | - | - | - | no model | none | Use when the user wants to design, redesign, shape, critique, audit, polish, clarify, distill, harden, optimize, adapt, animate, colorize, extract, or otherwise improve a frontend interface.
