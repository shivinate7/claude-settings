# bin/sim-lease is the one simulator queue and lease on a Mac

## The rulings

One tool, `bin/sim-lease`, holds the Mac-wide queue and lease for phone simulators. It replaces the Mac sim gatekeeper session as the thing that grants a boot. The gatekeeper (a session) reads `sim-lease status` and need not stay awake. The mistake it stops: a session boots a phone simulator outside the gatekeeper's one queue, or over the load bars.

1. Owner rulings, degen `shared-sim-lease`, 2026-11-02 13:49 to 14:47 CST, as `skills/ios-apps/SKILL.md` ("Sharing the Mac") cites them. One phone simulator boots at a time. The two Duos may run together when the load allows. The 18 Pro never runs beside a Duo. A boot needs a 5-minute load under 100. Slot 2 needs a 5-minute load under 60 and slot 1 in use. Each boot needs a 1-minute load under 60. The next in line takes the first slot to free.
2. `sim-lease take --device duo|pro --pid PID [--udid]` joins one FIFO queue and waits for its turn. Only the first fresh waiter is granted. Each poll of a waiting take stamps `seen` on its queue entry, the epoch seconds from env `SIM_LEASE_NOW` when set, else `time.time()`. A waiter whose `seen` is older than `SIM_LEASE_SKIP` seconds (default 30, unmeasured: no incident gives the real gap between polls) is stale and is passed over, so a stopped take cannot block the queue. Example: a killed `sim-lease take` child under a live `sim-test`. Basis: owner, 2026-11-02 14:31 CST, a busy session's turn passes to the next session that answers. A stale waiter keeps its place; its next poll makes it fresh again, ahead of every later waiter. It prints the slot (`1`, `2` or `pro`), or with `--udid` that slot's device UDID from `SLOT_UDID`, and exits 0. At the wait limit (`SIM_LEASE_WAIT`, default 300 s) it exits 1 with one stderr line that names the holders and the load. `--pid` is required on `take` and `give`; a usage error, a missing `--pid` included, prints one usage line on stderr and exits 2.
3. Limits on every grant: 5-minute load under 100, 1-minute load under 60. Duo takes slot 1, or slot 2 only while slot 1 is held and the 5-minute load is under 60. Pro is exclusive both ways. The load is read from `sysctl -n vm.loadavg` only.
4. `bin/sim-test` takes a lease on every run, after its lock and the cap check (owner, 2026-11-07 12:31 CST, page item 336, option a; before it, a reuse took none). An own boot takes the lease for its role (`--device duo` by default, else `pro`; it boots the UDID from `take --udid`) before `simctl boot`. A reuse of a booted device takes the lease of that device's slot: `take --device duo|pro --reuse UDID --pid PID` finds the slot by a reverse lookup of the UDID in `SLOT_UDID`, and a UDID outside `SLOT_UDID` is slot `other`. A reuse skips the load bars, waits while another live pid holds that slot, and is still granted in queue order. A held `other` lease counts as held for the pro-exclusive rule. `sim-lease status` names each lease's `udid`, so it names the user of every booted phone. `--reuse` may repeat: one take then waits for whichever of those devices' slots frees first (the grant logic stays in `bin/sim-lease`, one queue entry, tried in the order given). A duo run reuses a booted Duo only when no other live lease holds its slot (`sim-lease status`). With both Duos booted and each leased by another live pid, it does not stop at the cap check: it queues with `--reuse` for both, reuses the Duo that frees first (if its holder shut it down, the run boots it only under an own-boot lease, within the load bars), and exits 1 at the lease wait limit with no boot and no xcodebuild. Otherwise it takes a fresh lease (slot 2 under the load bars) and boots that slot. So two Duo runs go together when the load allows (owner, 2026-11-02 14:23 CST; coordinator, 2026-11-07, one Mac lock held only while a run picks and boots its device, and the slot's lease after that). The Mac lock covers only the pick and the boot. The lease guards the slot until the shutdown and the give. After the grant of an own-boot take, a re-scan may find a reusable device. When it is the device of the granted slot, the run keeps that lease. Otherwise the run gives that lease back and takes `--reuse` for the device's slot. The lease is given back after the shutdown and before the lock is freed, if the run still holds the lock, on every exit, INT and TERM too. A `--hold` run keeps its lease for the whole hold.
5. Recovery does not depend on the holder ending well (`verification-recovery-independent-of-state`). Each call reaps a lease or a waiter whose pid is dead, or whose `ps -o lstart=` start time differs from the one recorded at take (a reused pid). Only a `ps` that exits 1 means dead: a ps error keeps the entry. `ps` runs with `TZ=UTC`, so a start time does not change with the caller's `TZ`. A holder that dies never has to give.
6. State: `<config>/state/sim-lease/leases.json`, under `fcntl.flock` on `lock` in the same folder, written through a temp file and `os.replace`. `<config>` is `$CLAUDE_CONFIG_DIR`, else `~/.claude`.
7. No-op: when `uname -s` is not Darwin, or `CI` or `GITHUB_ACTIONS` equals `true`, `take` prints `none` (with `--udid` too) and exits 0, `give` exits 0, and no file is written. On Darwin, a no-op `take` also prints one stderr line saying no lease was taken. Any other value, `false` or empty, is not a no-op. So CI runs and Linux hosts are never queued.
8. Cost: per call, one `uname` and one `ps` per recorded pid. Take and status add one `sysctl`; a waiting take adds one `sysctl` and one `ps` per recorded pid each `SIM_LEASE_POLL` seconds (default 2). Each of its polls writes `leases.json` with the new `seen`. Otherwise it writes `leases.json` only when the content changes, plus the empty `lock` file. No daemon, no timer, no log.
9. Time limit (coordinator pick, 2026-11-07, 1800 s, unmeasured: no incident gives a real run length). `take` stamps `granted` on each lease, the epoch seconds from env `SIM_LEASE_NOW` when set, else `time.time()`. A live holder renews: `sim-lease renew --pid PID` stamps `granted` with now and exits 0 when PID holds a lease, else 1 (a no-op host: 0, as `give`). So `SIM_LEASE_MAX` (default 1800) counts the silence since the last renew, not the run. On every `take`, a lease silent for more than `SIM_LEASE_MAX` seconds is dropped, so the next waiter gets its slot, and `live_leases` treats it as not live. A lease with no `granted` does not expire. `bin/sim-test` renews every `SIM_TEST_RENEW` seconds (default 60) while its child or hold runs (decision `sim-test-is-the-one-boot-path`, ruling 11, bounds the run itself). The mistake it stops: a lease expiring while its run lives, so run B takes the slot and run A's cleanup shuts the device down under B. Cost: one `sim-lease` process and one `leases.json` write per renew.

Test: `lint/test_sim_lease.py` (slots, load bars, queue order, the stale waiter, reaping by dead pid and by changed start time, give, usage, no-op, concurrent takes, Renew, LiveLeases, PsError) and cases 47 to 50 of `lint/test_sim_test.sh` (lease held at boot, released after the run and after TERM, refusal at load 100 boots nothing, reuse path takes its slot's lease) and case 105 (a renew keeps a run's lease past `SIM_LEASE_MAX`), case 106 (a lost lease is named once) and cases 107 and 108 (a queued reuse grant whose Duo is down takes an own-boot lease under the load bars). Both use shims for `uname`, `sysctl` and `ps`.

Not proven here: there is no Mac in the cloud. The real `sysctl -n vm.loadavg` text, the real `ps -o lstart=` format on macOS and a real `simctl` boot under the lease are untested here. The shims write those formats as the tool expects them. The shell-macos CI job runs the sim-test suite on a Mac, but with shimmed load and `ps`.

Not covered: a SIGKILL of `sim-test` skips its EXIT trap, so its simulator (a Duo or the 18 Pro) stays booted while its lease is reaped. The next `sim-test` run reads the booted list after its grant: the same role reuses the device, the other role refuses (debt note `sim-test-sigkill-leaves-sim-booted`). An `xcodebuild -destination` boot skips the lease, and the route rule refuses it (decision `sim-test-is-the-one-boot-path`, ruling 5). A simulator MCP `launch` of a shut-down device is allowed only to a session that holds a live lease for that device. The guard reads `leases.json` through `live_leases` and `SLOT_UDID` in `bin/sim-lease`.

Basis: owner rulings (degen `shared-sim-lease`, 2026-11-02 13:49 to 14:47 CST), and the standing need that a session never boots over the load bars. Landed: 2026-11-04.
