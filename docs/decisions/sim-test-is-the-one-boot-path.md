# One lock makes sim-test the one boot path on a Mac

## The rulings

Each Mac boots simulators through `bin/sim-test`, under one lock. Ruling 5 routes or refuses the other boot paths.

1. One lock per Mac. `bin/sim-test` takes the lock folder `<config>/state/sim-test.lock`. `<config>` is `$CLAUDE_CONFIG_DIR`, else `~/.claude`. It takes the lock with one atomic `mkdir`. It writes its pid into a file named `pid` inside the folder. It holds the lock for the whole run: boot, tests and shutdown, or the whole hold (ruling 9). It releases the lock on every exit, INT and TERM too. Reason: with a lock around the boot alone, run A can shut down a simulator that run B reuses.
2. A second run waits. While the lock is held, `sim-test` prints one line that names the holder pid. It checks the lock every 2 seconds. When the holder ends, it takes the lock and runs as in rule 1. It waits at most `SIM_TEST_LOCK_WAIT` seconds, default 300, which stays under Bash's 600 second cap. At that limit it exits 1, naming the holder pid. It boots nothing and runs no tests.
3. A lock whose pid is not alive is taken over. `sim-test` renames the lock folder to a name unique to itself. Only one rename wins. The winner removes the folder, then retries `mkdir`. A run whose rename loses removes nothing. A lock folder with no pid file counts as held for 60 seconds, then as dead and taken over the same way.
4. Guard rule `simulator-boot-bypass` (the bypass rule, in `hooks/guard.py`) refuses a session's direct boot. It refuses:
   - `simctl boot`, through `xcrun` or bare;
   - a Simulator.app open: `open -a Simulator`, `open -a Simulator.app`, `open` of a path that ends in `Simulator.app`, or `open -b com.apple.iphonesimulator`.

   The remedy names `sim-test`. The owner's override lifts the rule. The bypass rule is judged before `simulator-boot-cap` (the boot cap) and `simulator-boot-twin` (the reuse rule). So those two judge only `xcodebuild -destination` and the simulator MCP `launch`.
5. The other boot paths. They are judged after the boot cap and the reuse rule, so those still name the booted devices first. The owner's override lifts each.
   - Guard rule `simulator-boot-route` (the route rule) refuses an `xcodebuild -destination` that names a shut-down simulator. For action `test`, the remedy is `sim-test` with the same arguments, which tests on the Duo whatever device the destination named (ruling 8). For any other action, the remedy is `-destination 'generic/platform=iOS Simulator'`, which boots nothing.
   - Guard rule `simulator-boot-lease` (the lease rule) refuses an MCP `launch` that names a shut-down device, unless the held-lease allow applies. The remedy names `sim-test`. A launch of a booted device is judged by the device rule below. Reason: a phone simulator boots only through a lease, since the Mac holds one shared simulator for all repos (Degen rule `shared-sim-lease`, owner, 2026-11-02 13:49-14:47 CST; applied here by the coordinator, 2026-11-03 19:36 CST).
   - Guard rule `simulator-device-lease` (the device rule) refuses every simulator MCP call unless the payload's `session_id` holds a live `sim-lease` for each device in `device` and `udid` (coordinator ruling, 2026-11-08 11:19 CST, defaults a and b). It covers `launch`, `tap`, `screenshot`, `appearance`, `swipe`, `type` and any other action, and uses the same lease test as the held-lease allow below. Gap it closes: on 2026-11-08 10:43-10:50 CST a lane kept tapping the 18 Pro and switching light and dark mode after its `sim-test --hold` lease ended.
     - A name matches the simulator list by the one name match the lease rule uses: no case, no outer spaces, a UDID or a device name. A name that matches several devices needs every one held.
     - A non-launch call that names a device no simulator holds is refused. A call with no device (absent, empty or not a string) is refused unless the session holds a live lease for every booted device, and at least one. A launch of a name no simulator holds stays allowed.
     - A launch meets the boot cap, the reuse rule and the lease rule first, unchanged. The device rule then judges a launch of a booted device. A device the lease rule found held is not read again.
     - It fails open where the device list cannot be read, as the other simulator rules do: no janitor beside `guard.py`, no `xcrun`, or an unreadable list. The owner's override lifts it.
     - The refusal names the role of the device that lacks a lease (coordinator pick, 2026-11-08 12:15 CST, upheld 12:17 CST): a UDID in slot pro gets `sim-test --device pro --hold`, any other `sim-test --hold`. The slot map is `SLOT_UDID` in `bin/sim-lease`. It never names the refused device as the remedy.
   - The held-lease allow. The lease rule allows the launch when the calling session holds a live `sim-lease` whose slot maps to the launched device's UDID (basis: owner, Degen `shared-sim-lease`, 2026-11-02, applied by the coordinator's pick, 2026-11-04 03:18 CST). The launch then boots under a lease that `sim-lease` granted. The tests:
     - The session is the hook payload's `session_id`. It must equal the lease's `session`. An empty one on either side never matches.
     - A lease is live by `sim-lease`'s own test (`is_live`, which `State.reap` also calls): its pid is alive and `ps -o lstart=` gives the start recorded at take. A queue place is no lease.
     - The slot maps to a device through `SLOT_UDID` in `bin/sim-lease`: `1` is Duo 1, `2` is Duo 2, `pro` is the iPhone 18 Pro (`skills/ios-apps/SKILL.md`, Phone simulators). It is compared with the UDID of the device the launch resolved to, never with the name. A name that resolves to several shut-down devices needs every one of them held.
     - The boot cap and the reuse rule judge first, so a lease never lifts either.
     - Any failure to load `bin/sim-lease` or to read `leases.json` keeps the refusal. The guard loads `bin/sim-lease` by path and calls `live_leases()`, which takes no flock, writes nothing, and does not consult the CI no-op.
     - No duplicate: `bin/sim-test` keeps no UDID. It reads the granted device from `sim-lease take --udid`, which prints the `SLOT_UDID` entry, and the slot of a reused device through `take --for-udid`.
6. Record. `sim-test` writes one `sim-boots.jsonl` line for the device it booted, through `hooks/sim_boot_record.py --record` with the UDID the lease granted, the one it then shuts down. A reused device gets no line, so the sweep never stops an owner-booted device. Reason: a `sim-test` stopped by KILL skips its cleanup, and the sweep stops only recorded devices.
7. Cost: one `mkdir`, one pid file and one folder removal per run. A boot adds one python3 start, one `simctl list` and two `ps`. A lease take writes `take.out` in the lock, and the scan after the grant runs one more `simctl list`. A waiting run reads the lock every 2 seconds, up to `SIM_TEST_LOCK_WAIT`. A hold adds no process, and holds the lock for at most 900 seconds. No new long-lived process. The device rule adds one `simctl list`, one `leases.json` read and one `ps` per lease to each simulator MCP call the list can be read for. It reads no lease when the cap, the reuse rule or an unlisted name refuses first. A launch the lease rule found held reads the lease once, not twice. The reader is this rule. It writes no file.
8. The Duo is the default. `sim-test` runs on the Duo (`--device duo`); `--device pro` runs the 18 Pro (owner, 2026-11-02 13:17 and 15:03 CST, `docs/plans/sim-standard.md` on commit f6109e51). It names a device by role, never a fixed UDID (owner, 14:47 CST): it keeps no UDID, and `sim-lease take --device <role> --udid` grants one to boot, and `--for-udid` grants the slot of a device that is already booted. It reuses the first booted device of its role, and holds the lease of that device's slot for the whole run (coordinator ruling, 2026-11-08 12:17 CST, option A). The run takes it with `sim-lease take --device <role> --for-udid <UDID>`, which obeys the queue, the slot's holder and the pro/duo exclusion, skips the load bars, and waits up to `SIM_LEASE_WAIT`. It gives the lease back on every exit. When the scan after a granted take finds a reusable device, the granted slot goes back first. A reused device in no slot, or a `none` (CI): one stderr line, and the run goes on with no lease (lane picks, 12:36 and 12:38 CST). A slot kept past the wait by another live holder: exit 1, nothing booted or run, and one stderr line names the holder's pid and session (coordinator ruling, 12:37 CST). Reason: the device rule (ruling 5) refuses MCP calls on a device the session holds no lease for. One phone kind at a time (owner, 2026-11-02 13:51 CST): a duo run with only a non-Duo iPhone booted, or a pro run with only a Duo booted, boots nothing, runs nothing and exits 1. It shuts down no device it did not boot. A no-op lease (`none`) on an own boot boots and runs nothing and exits 1. A `simctl list` that fails exits 1 with no boot. After the lease is granted, under the lock, it reads the booted list again. It reruns the reuse, cross-role and cap checks before it boots, because a holder that died can have left its device booted. A device now reusable is used, and the lease goes back for the reuse lease above. A boot that fails shuts nothing down. The take runs in the background, so INT and TERM act at once.
9. The hold. `sim-test --hold [--for S] [-- CMD ARGS...]` boots or reuses the device as in ruling 8 and keeps it for S seconds (default 300, max 900) under the lock and the crash watch, without xcodebuild. It exports `SIM_TEST_UDID`. With `-- CMD`, CMD runs as its child and the exit code is CMD's (124 on timeout). With no CMD it waits, and a session runs it in the background so its MCP calls on the device pass the device rule. A reused device's hold keeps the lease of its slot as in ruling 8. Reason: no route kept a Duo booted for design shots (owner, 2026-11-03 16:44 CST, same plan). The hold holds the Mac-wide lock for its whole length, so S is capped at 900. Cleanup is a test run's: stop the child, shut down only what it booted, give the lease, free the lock.

Test: a second run waits and takes the lock when the holder ends. At the wait limit it exits 1, naming the pid, with no boot. A raw `simctl boot` is refused.

Incidents:
