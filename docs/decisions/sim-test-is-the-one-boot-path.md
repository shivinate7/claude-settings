# One lock makes sim-test the one boot path on a Mac

## The rulings

Each Mac boots simulators through `bin/sim-test`, under one lock. Ruling 5 routes or refuses the other boot paths.

1. One lock per Mac, held while a run picks and boots its device. `bin/sim-test` takes the lock folder `<config>/state/sim-test.lock`. `<config>` is `$CLAUDE_CONFIG_DIR`, else `~/.claude`. It takes the lock with one atomic `mkdir`. It writes its pid into a file named `pid` inside the folder. It holds the lock only while the run picks and boots its device. It frees the lock once the device is up and the lease is held, for a reuse and a hold too. The lease then guards the slot until the shutdown and the give. It releases the lock on every exit, INT and TERM too, if it still holds it, but only while the pid file names this run. A holder is live by `ps -p PID`, never by `kill -0`, which reads EPERM as dead. A take-over puts a moved folder back only while no lock exists, and removes it when another run has re-created the lock. Reason: the two Duos may run together (owner, 2026-11-02 14:23 CST; the coordinator's pick of 2026-11-07). The one Mac lock covers only the pick and the boot; the slot's lease guards the device after that. The lease stops run A from shutting down a simulator that run B reuses: a duo run reuses a booted Duo only when no live lease holds its slot (ruling 8), and run A shuts its Duo down before it gives the lease.
2. A second run waits. While the lock is held, `sim-test` prints one line that names the holder pid. It checks the lock every 2 seconds. When the holder ends, it takes the lock and runs as in rule 1. It waits at most `SIM_TEST_LOCK_WAIT` seconds, default 300, which stays under Bash's 600 second cap. At that limit it exits 1, naming the holder pid. It boots nothing and runs no tests.
3. A lock whose pid is not alive is taken over. `sim-test` renames the lock folder to a name unique to itself. Only one rename wins. The winner removes the folder, then retries `mkdir`. A run whose rename loses removes nothing. A lock folder with no pid file counts as held for 60 seconds, then as dead and taken over the same way.
4. Guard rule `simulator-boot-bypass` (the bypass rule, in `hooks/guard.py`) refuses a session's direct boot. It refuses:
   - `simctl boot`, through `xcrun` or bare;
   - a Simulator.app open: `open -a Simulator`, `open -a Simulator.app`, `open` of a path that ends in `Simulator.app`, or `open -b com.apple.iphonesimulator`.

   The remedy names `sim-test`. The owner's override lifts the rule. The bypass rule is judged before `simulator-boot-cap` (the boot cap) and `simulator-boot-twin` (the reuse rule). So those two judge only `xcodebuild -destination` and the simulator MCP `launch`.
5. The other boot paths. They are judged after the boot cap and the reuse rule, so those still name the booted devices first. The owner's override lifts each.
   - Guard rule `simulator-boot-route` (the route rule) refuses an `xcodebuild -destination` that names a shut-down simulator. For action `test`, the remedy is `sim-test` with the same arguments, which tests on the Duo whatever device the destination named (ruling 8). For any other action, the remedy is `-destination 'generic/platform=iOS Simulator'`, which boots nothing.
   - Guard rule `simulator-boot-lease` (the lease rule) refuses an MCP `launch` that names a shut-down device, unless the held-lease allow applies. The remedy names `sim-test`. An MCP `launch` of a booted device is a drive, judged by ruling 12. Reason: a phone simulator boots only through a lease, since the Mac holds one shared simulator for all repos (Degen rule `shared-sim-lease`, owner, 2026-11-02 13:49-14:47 CST; applied here by the coordinator, 2026-11-03 19:36 CST).
   - The held-lease allow. The lease rule allows the launch when the calling session holds a live `sim-lease` whose slot maps to the launched device's UDID (basis: owner, Degen `shared-sim-lease`, 2026-11-02, applied by the coordinator's pick, 2026-11-04 03:18 CST). The launch then boots under a lease that `sim-lease` granted. The tests:
     - The session is the hook payload's `session_id`. It must equal the lease's `session`. An empty one on either side never matches.
     - A lease is live by `sim-lease`'s own test (`is_live`, which `State.reap` also calls): its pid is alive and `ps -o lstart=` gives the start recorded at take. A queue place is no lease.
     - The slot maps to a device through `SLOT_UDID` in `bin/sim-lease`: `1` is Duo 1, `2` is Duo 2, `pro` is the iPhone 18 Pro (`skills/ios-apps/SKILL.md`, Phone simulators). It is compared with the UDID of the device the launch resolved to, never with the name. A name that resolves to several shut-down devices needs every one of them held.
     - The boot cap and the reuse rule judge first, so a lease never lifts either.
     - Any failure to load `bin/sim-lease` or to read `leases.json` keeps the refusal. The guard loads `bin/sim-lease` by path and calls `live_leases()`, which takes no flock, writes nothing, and does not consult the CI no-op.
     - No duplicate: `bin/sim-test` keeps no UDID. It reads the granted device from `sim-lease take --udid`, which prints the `SLOT_UDID` entry.
6. Record. `sim-test` writes one `sim-boots.jsonl` line for the device it booted, through `hooks/sim_boot_record.py --record` with the UDID the lease granted, the one it then shuts down. A reused device gets no line, so the sweep never stops an owner-booted device. Reason: a `sim-test` stopped by KILL skips its cleanup, and the sweep stops only recorded devices.
7. Cost: one `mkdir`, one pid file and one folder removal per run. A boot adds one python3 start, one `simctl list` and two `ps`. A lease take writes `take.out` in the lock, and the scan after the grant runs one more `simctl list`. A duo run adds one `sim-lease status` read per scan. A waiting run reads the lock every 2 seconds, up to `SIM_TEST_LOCK_WAIT`. While the child or the hold runs, the renew adds one `sim-lease` process and one `leases.json` write per `SIM_TEST_RENEW` seconds (default 60). A hold holds the lease, not the lock, for at most 900 seconds. No new long-lived process. The held-lease allow adds one `leases.json` read and one `ps` per lease, only on a booting MCP launch that the cap and the reuse rule passed. It writes no file.
8. The Duo is the default. `sim-test` runs on the Duo (`--device duo`); `--device pro` runs the 18 Pro (owner, 2026-11-02 13:17 and 15:03 CST, `docs/plans/sim-standard.md` on commit f6109e51). It names a device by role, never a fixed UDID (owner, 14:47 CST): it keeps no UDID, and `sim-lease take --device <role> --udid` grants one. It reuses the first booted device of its role. One phone kind at a time (owner, 2026-11-02 13:51 CST): a duo run with only a non-Duo iPhone booted, or a pro run with only a Duo booted, boots nothing, runs nothing and exits 1. It shuts down no device it did not boot. A no-op lease (`none`) boots and runs nothing and exits 1. A `simctl list` that fails exits 1 with no boot. After the lease is granted, under the lock, it reads the booted list again. It reruns the reuse, cross-role and cap checks before it boots, because a holder that died can have left its device booted. A device now reusable is used. It keeps the lease when it is the device of the slot just granted. Otherwise the run gives that lease back and takes `sim-lease take --reuse` for the device's slot. A duo run reuses a booted Duo only when no other pid's live lease holds its slot, read from `sim-lease status`. With each booted Duo leased, it takes a fresh lease (slot 2 under the load bars) and boots that slot (owner, 2026-11-02 14:23 CST; coordinator, 2026-11-07). A boot that fails shuts nothing down. The take runs in the background, so INT and TERM act at once.
9. The hold. `sim-test --hold [--for S] [-- CMD ARGS...]` boots or reuses the device as in ruling 8 and keeps it for S seconds (default 300, max 900) under its lease and the crash watch, without xcodebuild. It exports `SIM_TEST_UDID`. With `-- CMD`, CMD runs as its child and the exit code is CMD's (124 on timeout). With no CMD it waits, and a session runs it in the background so its MCP launch finds the device under the held-lease allow. Reason: no route kept a Duo booted for design shots (owner, 2026-11-03 16:44 CST, same plan). The hold keeps its lease for its whole length, so S is capped at 900; it frees the Mac lock once the device is up, as a test run does. Cleanup is a test run's: stop the child, shut down only what it booted, give the lease, free the lock if it still holds it.
10. The reset. Every run (own boot, reuse and hold) reads the device's appearance after the device is known and before xcodebuild or the hold, and sets it to light when it is not. A Duo run also reads the fold (`hinge -d UDID get`, which prints an angle in degrees) and closes it (`hinge -d UDID close`) unless the reading is the word `closed` or a number of 1.0 or less. The line shows the old reading. One stderr line names each change. With `hinge` not on PATH, one stderr line says the fold was not checked, and the run goes on. It never uninstalls and never erases. The mistake it stops: a run stopped early, or the last holder, leaves the phone dark or open, and the next run's results are suspect (incident, 2026-11-07 12:05 to 12:09 CST, a Degen re-check left Duo 1 dark). Cost: one `simctl ui` read per run, and one more call when it sets; a Duo run adds one `hinge get`, and one `hinge close` when the fold is not closed. Not checked: the text the real `hinge get` prints beyond the angle and the word `closed`.
11. The run limit (coordinator pick, 2026-11-07, unmeasured). A run whose `xcodebuild` child is still running after `SIM_TEST_MAX_RUN` seconds (default 1800; text that is not whole seconds counts as the default) stops the child, prints one stderr line, and exits 124. It then cleans up as a hold does: it shuts down only what it booted, gives the lease, and frees the lock if it still holds it. The 1800 s default is unmeasured: no incident gives a real run length. A hold keeps its own limit, `--for`. The mistake it stops: a hung `xcodebuild` keeps its lease and its device for good. Cost: one `$SECONDS` read per poll.
12. The drive lease (coordinator ruling, 2026-11-07 16:13 CST, from the owner's 2026-11-02 simulator rulings). A session drives a booted phone only under its own live lease for it. Guard rule `simulator-drive-lease` (the drive rule) refuses a drive of a booted device when the calling session holds no live lease that covers it. The reason names `sim-lease take` and `sim-test --hold`. The owner's override lifts it. The mistake it stops: a session drives a phone that another session's run holds. The harm: the 2026-11-07 11:55 CST incident, where a Home review folded, darkened and tapped Duo 1 during a Degen run, so both results were suspect and the review lost 7 tries.
    - A drive is one of three calls. One: a simulator MCP call whose action is not `screenshot`, `describe` or `list`; an MCP `launch` of a booted device is one. Two: `hinge -d UDID open|close|half|<degrees>`, also with `-t N`. Three: `xcrun simctl <verb> UDID|booted`, for the verbs `ui`, `openurl`, `install`, `uninstall`, `launch`, `terminate`, `push`, `privacy`, `status_bar`, `location`, `addmedia`, `keychain`, `pbcopy`, `spawn`, `shutdown` and `erase`. For `shutdown` and `erase`, `all` names every booted device. The read set is never judged: those three MCP actions, `hinge` get and posture, `simctl io`, `list` and `get_app_container`, and `simctl ui <device> <setting>` with no value, which reads the setting. With a value it is a drive. A boot stays with the boot rules. The rule finds a drive through `_sim_commands`, the one walk of the simulator rules, so a quoted text and a comment are no drive.
    - The hold rule. Inside `sim-test --hold [--for S] -- CMD` the lease does not exist yet. So a drive in CMD must target `$SIM_TEST_UDID` (also `${SIM_TEST_UDID}`) inside a single-quoted `sh -c '...'` or `bash -c '...'` script. Only there does it survive the caller's shell until the hold exports it, so a double-quoted or unquoted one is refused. A drive that names a device is allowed when this session holds a live lease for every booted phone the name resolves to. Any other target is refused with `simulator-drive-lease`, unless it is a single-quoted `$SIM_TEST_UDID`. The caller's shell expands `"$SIM_TEST_UDID"` before the hold exports it, so the reason names the working form: `sim-test --hold -- sh -c 'hinge -d "$SIM_TEST_UDID" open'`. A read in CMD is not judged. Cost: a hold drive that names a device reads `simctl list` once per call, shared with the boot and plain drive checks. When the list cannot be read, the boot check, the call site and the hold check each try it, so a call reads it up to three times. Process only: coordinator, 2026-11-08 08:34 CST. It applies ruling 12 (the drive lease), whose main line is "a session drives a booted phone only under its own live lease". Basis: owner, Degen `shared-sim-lease`, 2026-11-02. Reason for the change: the text-only check refused the lease holder, a false alarm. Reason for the hold: the coordinator's 2026-11-07 16:13 CST ruling, that every session leases the shared phone before it uses it.
    - `booted` names every booted device, so each needs a lease. A name judges each booted device it resolves to. A shut-down or unknown device is the boot rules' job. A call that names no device is not judged.
    - The lease test is the held-lease allow of ruling 5 (`sim_lease_holds`), extended: a lease covers a device when its slot maps to the UDID, or, for slot `other`, when its `udid` field is that UDID. Any failure to read stays False, so the refusal stands.
    - The boot rules judge first (`simulator-boot-cap`, `simulator-boot-twin`, then the route and lease rules), so a launch of a shut-down device keeps its boot refusal. With no `xcrun`, or a device list that does not read, the rule allows outside a hold, as the boot rules do. Inside a hold, a drive that names a device or `booted` is refused, since no lease can be checked.
    - Cost: one `simctl list` (two when it cannot be read) and one `leases.json` read, one `ps` per lease, only on a call matched as a drive. A call the rule does not match reads nothing. The list read is shared with the boot rules when both run. It writes no file and starts no process that outlives the call.
    - Test: `GUARD_FAMILY=simulator python3 hooks/test_guard.py`, the `drive:` cases (refused with no lease, under another session's lease, a dead, queued or expired lease, or a lease for another device) and the `lease allow:` and `control:` cases (the reads, the holder, a shut-down device, a quoted text, no simctl). `hooks/mutate_guard.py` holds one mutant per arm.
    - Not built, and a Mac step: the real simulator MCP action names. The read and drive sets use the names in the cases (`screenshot`, `describe`, `list`, `tap`, `swipe`, `launch`); an action the tool does not spell that way is judged a drive, except the three read names. Read the tool's schema on the Mac and fix the sets.

Test: a second run waits and takes the lock when the holder ends. A second duo run beside a leased Duo boots the other slot's Duo (cases 98 to 100 of `lint/test_sim_test.sh`). A renew that finds its lease gone is named once, and a run queued behind two leased Duos boots a shut-down Duo only under the load bars (cases 106 to 108). At the wait limit it exits 1, naming the pid, with no boot. A raw `simctl boot` is refused.
