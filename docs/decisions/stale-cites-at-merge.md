# A PR that removes a name also fixes each prose line that names it

## The ruling

The ste-lint CI step refuses a pull request that leaves stale prose of one kind. The kind is a tracked Markdown line that names a repo file or a Python name bound at module level that the same PR deleted, renamed or moved. A line that cites a script flag the same PR removed from that script is stale too. `lint/stale_cites.py` is the check. `actions/ste-lint/run.sh` runs it in scope `changed`, before the markdown-only exit, so a code-only PR is checked too. Every repo that pins the ste-lint action gets it when its pin moves.

Owner, 2026-11-01 16:30 CST, in chat to triage: "make it a standing thing that stale prose never makes it anymore".

- Codes: STALE001, a path the range removed. STALE002, a name cited as "`file.py` `name`" (backticked name) or "(file.py name)" on one line, where `name` was bound in that file at base and is not bound at head. A bare word after a path is never a cite. Python is read with `ast`. `lint/stale_cites.py` `names_in` walks each module-level statement, also inside a module-level if, try, with, for, while or match, never inside a def or class. In those statements, py-facts `defined_names` (`skills/plain-english-map/scripts/lib/py-facts.py`, the one home) finds each def, class, import and assignment to a plain name. `lint/stale_cites.py` `target_bindings` adds each name in a tuple, list or starred assignment target, a for target, a with-as target and a walrus target. A def directly in a module-level class counts too. A def nested in a function does not. A name that moved but is still bound in the file (`f = h`, a re-import) is not removed. JavaScript and shell names are not checked. A cite of a name in such a file (`.mjs`, `.js`, `.cjs`, `.ts`, `.sh`) that the range touched prints `stale-cites: unknown, <md path>:<line> ...` and keeps the exit 0. It prints only when the range also removes a path, a Python name or a flag, since only then is Markdown read. A range that touches only `.mjs`, `.js`, `.cjs` or `.ts` files prints nothing and passes, with no added git start and no Markdown read. STALE003, a flag cited as `script --flag` inside one backticked code span, where the range removed that flag from that script. A `~/.claude/<path>` cite resolves to `<path>` at the repo root. A Python flag is an `add_argument` string literal, read with `ast`. A shell (`.sh`) flag is a whole-word `--token` in the file. A flag only named in a docstring or comment was never declared. A span that cites no script (`git push --force`), and a script that never held the flag (a shim whose target holds the flags), never fire.
- Scope: the lanes after `stale-names-bound` follow `docs/plans/pointer-system.md`. This branch builds `stale-names-bound` and `stale-flags`. The coordinator's picks of 2026-11-03 19:48 CST set the rules for the planned lanes. A value cite matches the code as written, Python only, and a JavaScript value reads "unknown". The reverse list (code that nothing in prose cites) is report-only, never a finding, the same form as decision `claude-md-change-is-flagged` (a CLAUDE.md change is reported, never held).
- Readers: `scan()` runs a list of readers (`READERS` in `lint/stale_cites.py`), one per check. The later lane `value-cites` adds one entry.
- Only names the range removed count. A line already stale at base, for a name the range did not touch, never fires. So the check is never red on work the PR did not do.
- A path matches only at a path boundary. `mods/session-board/hooks/lib.mjs` does not match `hooks/lib.mjs`.
- Left out: `docs/records.md` (generated at merge), each file `.ste-lint-exclude` names, and a line marked `<!-- ste-disable-line STALE001 -->`, `STALE002` or `STALE003`. A record that names a removed file on purpose takes the mark.
- Each Markdown file is read as committed at head, never from the working tree, through the same `git cat-file --batch` process. A byte that is not UTF-8 reads as a replacement character and the file is still checked.
- A base that does not resolve (a shallow clone with no history) is unknown, not a finding. The check prints `stale-cites: unknown, ...`, names fetch-depth 0, and exits 0, so a repo that pins the action and checks out shallow is not red at its pin move (owner-lane call, 2026-11-01).
- `FAIL=false` is honored: the findings print and the step exits 0.
- Findings have their own exit path. The STE split script makes a finding on an untouched line report-only, and every stale line is untouched by design.
- A touched `.py` file that does not parse at base or head is unknown the same way: `stale-cites: unknown, <file> ...`, and it alone keeps the exit 0.
- Cost, per ste-lint changed-scope run (each PR CI run and each `bin/ste-changed` call): one `python3` start. Git starts 3 (`rev-parse`, `merge-base`, `diff`) when the range removes or renames no path and touches no `.py` or `.sh` file. A touched `.py` or `.sh` file adds one `git cat-file --batch`, which the name reader and the flag reader share. A removed path, name or flag adds `ls-tree` and reads the Markdown through that `cat-file`, so 5 at most. Each tracked Markdown file is read once, and only when a path, name or flag was removed. A touched `.py` file also loads the py-facts script once, in-process (importlib, no start, no `.pyc`). It writes no file and starts no lasting process. `CostTests` in `lint/test_stale_cites.py` proves it.
