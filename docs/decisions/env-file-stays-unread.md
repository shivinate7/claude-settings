# The environment file stays unread

## The ruling

No session reads, writes or commits the contents of an environment file. The user manages that file, and its values stay out of the session.

The guard refuses a write tool call that names the file. The settings deny list refuses a Read or Edit call on it. In a shell command the guard refuses only the forms it reads. A runner is read for its child (below). Outside a runner, `bash -c "cat .env"`, `sh -c "source .env && npm test"` and `eval "cat .env"` allow. Lane `env-file-shell-c` owns that gap.

A runner may load the file into its own process with its loader flag. The guard stops node, bun and deno given the file when they run inline code (`-e`, `-p`, `--eval`, `--print`, deno's `eval`) or a script read from stdin (`-`, a pipe, a heredoc, a here-string or a `<` file). That code can print the variables. It does not catch deno's `run -`, which reads stdin after the word `run`.

The guard also stops uv, docker, podman, npm, npx and pnpm given the file when the child command they start prints its environment. It reads these children: `env`, `printenv`, any `python -c`, and inline node, bun or deno code. A `perl`, `ruby`, `awk`, `gawk`, `mawk` or `nawk` child prints when code names the environment (`perl -e 'print %ENV'`, `$ENV{KEY}`, `ruby -e 'p ENV'`, `ENV.to_h`, an awk loop over `ENVIRON`). It also prints when its code holds a shell string that prints: `system("env")`, `exec`, `spawn` or `popen` over a string, a backtick pair, `qx(env)`, `%x(env)`. The code is each perl or ruby `-e` value (also `-ne`, `-pe`), awk's program word or `-e` value, and a here-string (`_script_code`). It is read as the shell hands it on. A script name, its arguments and a file name are not code (`ruby script.rb ENV`, `awk '{print}' ENV.txt` run). A bare word `ENV` is text (`perl -pe 's/ENV/prod/'` runs), except ruby's `p ENV`, where it is the constant. In a ruby string literal it is text (`puts "the ENV var"` runs), and in a `#{...}` it is code. Any child but a shell prints too when a word names `/proc/self/environ`, `/proc/<pid>/environ`, `/proc/$$/environ` or a glob of the pid (`/proc/*/environ`). The exceptions are `ls`, `test`, `[`, `[[`, `echo` and `printf`. A longer name is another file (`/proc/self/environ_x`). A docker or podman `compose config` or `compose convert`, and `docker-compose config`, print the resolved values, so they are children too, unless a listing flag follows (`--services`, `--volumes`, `--profiles`, `--images`, `--hash`, `-q`). A listing flag may be glued to a value (`--hash="*"`). `compose up` is not. A python or shell child with no script word and stdin fed is also stopped. Stdin is fed by a pipe, a heredoc, a here-string or a `<` file. `npx`, `npm exec`, `npm x`, `pnpm exec`, `pnpm dlx` and `bun x` children are read the same way: `npx node -e "..."` is inline code. `bun x` is read only as the exact word `x`, so `bun ./x` is a script. One reader, `_child_starts`, finds the children. One judge, `_child_prints`, reads each.

A wrapper before the child is read through to the command it runs: `timeout <n>`, `nice [-n x]`, `sudo [-E] [-u x]`, `time`, `stdbuf ...`, `env VAR=x`, and `exec`, `command`, `builtin` and `nohup`. `uv run timeout 5 env` is the child `env`. `env VAR=x` with no command prints, so it is the child, and so is `env > out.txt`, where a redirect follows.

A shell string is `sh`, `bash`, `zsh` or `dash` with `-c "<s>"`, or npm, npx or pnpm with `-c "<s>"`. The guard reads the string as the child shell gets it, with one reader of a shell word (`_shell_word`), shared with the perl, ruby and awk code. Pieces quoted apart join: `'it'\''s'` and `'it'"'"'s'` are both `it's`. In double quotes the parent drops the backslash of `\$`, `` \` ``, `\"` and `\\`. It judges it segment by segment, with the same reader as the shell form (`_env_flat`). Each `$(...)`, backtick pair and `<(...)` in a segment is cut out by `_substitutions` and judged as a command of its own, in any quote (`cd "$(env)"`). A real `#` comment hides its text (`ls # $(env)` runs); a `#` in quotes does not. A line break or `;` starts a segment, and a lone quote does not hide the segments after it. A group or clause word before the command is read through: `{`, `(`, `!`, `if`, `then`, `else`, `elif`, `do`, `while`, `until`. A segment is refused in five cases. A redirect and its target are no argument (`set > f`). It names an environment file as the shell form refuses. Its command is a printing child: `env` or `printenv` (also after a wrapper or a group word, and as a substitution), a nested `sh -c` that prints, any nested `python -c`, or a perl, ruby, awk or `/proc/.../environ` child above. Its command is `set` with no argument. Its command is `export` with no argument or with `-p`, or `declare` or `typeset` with `-p`, or with no name to set (bare, or `-x`). With `-f` or `-F` they print functions only, so `declare -pf` runs. `compgen` prints names, not values, so it runs. Or its command is `echo` or `printf` and it expands a `$` variable. A substitution is no variable: `echo $(date)` and `echo $((1+2))` run, `echo $(env)` is refused for the `env` in it, and `echo $(echo $X)` is refused for the `$X` in the inner echo. A `$` in any other segment is an ordinary argument, so `docker run ... sh -c "cd $APP_DIR && npm start"` runs. Any other string is allowed too, so `docker run ... sh -c "npm start"` runs. A `$( )` in a double-quoted shell string runs in the parent shell, before the runner loads the file, so it sees none of the file's values: `uv run --env-file F bash -c "echo $(printenv HOME)"` runs. An escaped `\$(env)` in the same string runs in the child, so it is refused. ACCEPTED LIMIT (note `env-parent-expansion-is-code`): the parent's output is the child's code, so `sh -c "$(cat script)"` is not read.

A docker or podman child is the `--entrypoint` program, else the word after the image. An empty `--entrypoint ""` is no program. `docker container run` and `podman container run` read as `run`.

Each runner has a list of value flags and a list of bool flags. The docker, uv, pnpm and bun lists are read from the tool's own help (`docker run --help`, `uv run --help`, `pnpm help exec`, `bun x --help`). The npm lists are `npm exec --help` plus npm config flags chosen by hand (`--registry`, `--loglevel`, `--color` and the like). A value flag owns the next word. A bool flag owns none. An npm or pnpm bool also owns a next word that is exactly `true` or `false`, since nopt reads it as the flag's value (`npm exec --dry-run false env` runs env). npm's `--color` is a bool that also owns the literal `always`, so `npm exec --color always env` runs env and `npm exec --color env` runs env. Every `--no-*` flag is a bool unless the value list names it.

Only a flag missing from both lists is read both ways. It may own the next word, so the guard tries that word as the image or child. It then goes on past each option and its possible value, to the next word that follows no such flag (`--foo X --bar alpine env`, `--cap-add X --cap-add Y img env`, `pnpm exec --foo env`). The child of npx, `pnpm dlx`, `npm exec` and `npm x` is found the same way (`npx env`, `pnpm -r exec env`). pnpm's `-r` and `-w` are bools there, and npm's `-w` takes a value. `--` ends a runner's options, so the word after it is the child (`pnpm exec -- env`). A program's own arguments are not tried (`uv run -q pytest -k env`, `uv run --exact pytest -k env`), except after a flag missing from both lists (below) and npm's `-c`. An `npm exec -c` child is its string. Quote marks on a child word are ignored. pnpm reads no flag after `exec`, and `pnpm exec -c echo` fails. The guard still reads a flag there as a flag, so it refuses a form that fails and prints nothing, which costs nothing.

Gaps remain, each a note (`env-script-shell-string-forms`, `env-script-file-unread`, `env-runner-child-runner-unread`). Perl and ruby shell strings are read in the forms above only. The guard does not read a script file, so a script the session wrote can still print the variables. A runner started as a child is not read for its own child (`uv run --env-file F npx -c env`).

Two false alarms remain. A flag missing from both lists may own the next word. After it, `env` or `printenv` as the program's first word or after the program's own option is tried as the child and denies (`uv run --foo pytest env`, `uv run --foo pytest -k env`). A program's `-c` after such a flag reads as pnpm's shell string (`pnpm exec --foo jest -c env`). The guard cannot tell a bool from a value flag (note `env-child-unlisted-flag`). An `echo` or `printf` segment that expands any `$` variable refuses, even one that holds no secret (`sh -c 'echo $PORT'`; note `env-echo-variable-any-name`).

One scope covers every form: a write tool call, a shell command and a Read call. A name is any basename that starts with `.env`, except `.env.example`. The guard's forms read one shared basename matcher in guard_env (`names_env_file`).

Shell form. `judge_shell` calls `env_refusal` and `env_heredoc_refusal`. A name is a word whose basename is in the scope above. A glob that could match a name counts as the name (`_glob_could_name_env`).

- Refused: a redirect onto the file. A shell variable that holds its path, because the guard cannot follow a variable to its use. The file given to a command that is not a runner. Any other command that the guard reads as one that would read, write or commit it.
- Allowed: an existence check (`ls`, `test`, `[`, `[[`). `echo` and `printf`, where the name is text. The message or body value of `git commit` and `gh pr create`. A runner in `ENV_LOADER_COMMANDS` (node, npm, npx, pnpm, bun, deno, uv, docker, podman, and their variants) given `--env-file` or `--env-file-if-exists`, except that node, bun and deno given the file must run a script file, not inline code or a stdin script. A runner that starts a child command (uv, docker, podman, npm, npx, pnpm) must not start one that prints its environment, or a shell string that does (`ENV_CHILD_REASON`).
- Substitutions (`$(...)`, backticks, `<(...)`) are judged as commands of their own, at any depth up to `ENV_MAX_DEPTH` (64). A deeper nest is refused. The substitutions in an unquoted heredoc body are judged (`env_heredoc_refusal`). A quoted heredoc body is text.

Write form. In `judge`, a write tool call (Write, Edit, MultiEdit or NotebookEdit) whose target name is in the scope is refused (`is_env`). It reads the same matcher as the shell form.

Read form. The guard does not judge Read. It returns early for Read and Grep. The settings deny list refuses a Read call on a name that starts with `.env`, at any depth. It refuses an Edit call on the same names. Its `!` carve-outs keep `.env.example` readable and editable. That reading of the `!` carve-outs comes from Claude Code's permission docs. It is not measured.

The printed refusal names no file. It names the shape of the access (`ENV_REDIRECT_REASON`, `ENV_VARIABLE_REASON`, `ENV_RUNNER_REASON`, `ENV_INLINE_REASON`, `ENV_CHILD_REASON`, `ENV_CONTENTS_REASON`, `ENV_DEPTH_REASON`, `ENV_TOOL_REASON`) and a remedy (`ENV_ADVICE`). The log holds the file name, for a person to read.

Known false alarms: debt `env-file-rule-false-alarms` (the env-file false-alarm debt). The guard refuses `ag -f` and `ack -f`, where `-f` is a boolean flag, `grep -r --exclude=.env`, and `rg -t py .env`. All four are safe. None reads a file's contents.

Why: the user's own secrets must not enter the session. `.envrc` is in the scope for the same reason. The guard stops Claude's mistakes, not an attacker's form (`guard-guards-mistakes-only`, a guard stops mistakes, not an attacker).

Risk: likely risk (`building-guard-needs-incident`: a guard or check needs a mistake Claude has made or is likely to make in normal work). A session would likely read a `.env` or `.envrc` file while it debugs. No incident is on record. Landed 2026-09-16, the env-file rule. The guard_env module has held the rule since 2026-10-13.
