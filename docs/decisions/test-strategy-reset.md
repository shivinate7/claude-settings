# Tests prove outcomes, run where their subject lives, and never fail on runner speed

## The ruling

A test must not fail on runner speed. CI runs a job only when its suites' files change, runs OS-independent suites on ubuntu only, and splits a near-cap job's slowest suite by family (a `ci-hygiene` step).

1. A skipped test reports SKIP with a count, never PASS. The fail-closed test list comes from the guard modules on disk.
2. No test times a run on a local device. Fixed sleeps and wall-clock bounds are in P5 of decision test-practices (no sleep or clock in a test). One test
   checks that the code follows a speed best practice, such as a count of calls or cache hits.
3. One shared set of fixtures: one git template, and one fake each for `gh`, `claude` and `xcrun`.
4. The pure-parse guard families run in one Python process. The cases that need a real hook process stay as subprocess cases.
5. A test stays only when it names the real failure it catches: a wrong allow or deny, lost work, a stuck merge, or a wrong record (test-practices P2, red run). A test that pins a known finding
   becomes a debt, not a test.
6. A merge of look-alike tests keeps one row for each item in a guard's list, each part of its pattern, and each filter. A row that alone
   fails when that item goes stays.

## Where CI runs a suite

- Each CI job runs only when a file that its suites read changes.
- OS-independent suites and pure lints run on ubuntu only: rule audit (suite and lint), record slugs, mod version bumps, landed dirs, agent models, STE lints, zizmor.
- The ruling census suite stays on every OS: it tests macOS `/var` symlinks and Windows backslash and `normcase` paths.
- Suites that touch paths, processes, shells, launchd, schtasks, symlinks or encoding run on every OS. When unsure, a suite stays on all OSes.
- The macOS job runs only the suites that touch the OS. The `install.sh` tests run on Linux and macOS: `checks-merge-install` runs them on Linux, where cloud sessions install, and `shell-macos` runs them on macOS (R63, owner pick a, 2026-11-12 15:55 CST: keep both runs). Windows keeps its own Git Bash run.
- macOS runs once per batch (R61, owner pick b, 2026-11-12 15:29 CST). A push to main starts no macOS runner: `shell-macos`, `checks-macos` and `checks-macos-b` skip it at job level, since a step-level skip still starts a runner. A pull request and a manual run still start them. `checks-macos` runs one mac-tagged slice of the guard suite (`GUARD_TESTS=macos-slice`, no shard) and `checks-macos-b` runs no guard step.
- Until the nightly was dropped (owner, 22:19 CST Nov 12), it skipped when main's head had a green push run of `checks.yml` and the newest completed nightly was green. The `nightly-skip` job decided (`.github/scripts/nightly-skip.py`), and `scope` waited on it, so a skip reached every job through `needs`. Nothing was cancelled: a cancelled run reads UNKNOWN and blocks merges. A failed read ran everything. The newest completed nightly decided, so a skipped green nightly never superseded a red one.
- Linux and Windows run each suite once per integration PR, on the integration PR run (R62, owner 2026-11-12 15:55 CST: "A for sure, B seems good too"). `checks-windows-rest` runs in two parallel jobs, `checks-windows-rest` and `checks-windows-rest-2`. Each is capped at a provisional 60 min. Each suite runs in one of them. The split is a bandaid, since the cost is Windows process start. On a ready pull request the Windows guard shards, the Windows merge shards and both rest jobs run in full whatever the scope flags say. A draft runs none. A push and a manual run keep their flag rules. The full shards are held, not dropped: the owner worries that untagged cases act differently on Windows. The Windows slice steps are gone, since shard 1 runs on a ready PR. Every other job runs on a ready PR under its scope flags, as on any PR. The exception is a ready PR from a `batch-*` branch (the integration PR). It sets every scope flag on (`ci-scope.sh`), so its run is the all-flags run. The janitor sweep mutation steps of `checks-macos` and `checks-windows-sweep` also run on a ready PR, on the sweep flag alone. Only the platform flag is ignored. That is the lane's choice, following triage's 17:53 CST Nov 12 message on step `ci-linux-windows-once`; no ruling record holds it. The `push-skip` job (`.github/scripts/push-skip.py`) skips a push to main only when two things hold. The push commit's tree equals the tree of a `batch-*` PR head. That head's ready run passed `all-jobs-passed`, and every check of that run concluded `success`, so each suite ran its tests on the same tree. The job reads those check runs, not the `checks.yml` run's conclusion. A draft run skips every job and concludes success. A run still queued or in progress is not green. `scope` waits on `push-skip`, so a skip reaches every job through `needs`. The run is a completed success, and nothing is cancelled. A failed read of any kind runs everything. The lane touched-tests checkouts fetch depth 50 and deepen until the base and head share a merge base.
- `concurrency` cancels superseded runs on pull requests only. Push and manual runs finish.
- Step names that `lint/rule_audit.py` reads do not change. The macOS guard step is the one rename: it is now "Guard fixture suite (macOS slice)", because its shard is gone, and no audit row cites it (`lint/rule_mechanisms.json`).
- When a CI job nears its time cap, split the slowest suite's subject by family into its own job, and give the measured CI time before and after. This is a step of the `ci-hygiene` skill (owner, 2026-10-17 23:46 CDT).
- CI has no nightly schedule (owner, 2026-11-12 22:19 CST). 45 nightly runs since Sep 30 found nothing the push runs had not. A manual run stays through `workflow_dispatch`. Jobs that run only on `schedule` are now dead. They stay until a cleanup after the integration-PR lane merges. That cleanup keeps `.github/scripts/nightly-skip.py`, because `push-skip.py` loads it as the one reader of the runs API. The newest schedule run on main, run 43207729611, is green, so the red-main check reads that group green until a later schedule run. The drop should land before the next fire. macOS on main now runs only on a manual run. The 45-run basis predates the macOS cut (R61), so it does not cover macOS. A push run never clears a red schedule run, because it skips the macOS jobs.

Reason: a slow Windows runner failed a PR on tests its change did not touch. Fixed sleeps cost time, and macOS CI minutes went to suites
that do not touch the OS. A duplicate run costs minutes for no new verdict.

Accepted risk: a defect in an OS-independent suite that shows only on macOS or Windows is not caught. Unmeasured.

Accepted risk (R61): the full guard suite no longer runs on macOS at all. Every event that starts a macOS job (a pull request or a manual run) runs the mac-tagged slice, and a push to main runs no macOS job. With the nightly dropped, no macOS job runs on main unless someone starts a manual run. The integration PR run is the only macOS run, and main's tree matches it only when push-skip saw equal trees. A macOS-only guard defect outside the slice reaches main and is not caught. Unmeasured. The slice's tag comes from the darwin arms in `hooks/` (`MACOS_REACH` in `hooks/test_guard.py`, held to the arms by an ast scan).
Accepted risk (R62): a push whose tree a green integration PR head already has runs no job. A `batch-*` ready PR runs every scope flag, so that run was the all-flags run, and a push skip rests on it. `all-jobs-passed` fails on a skipped needed job. But a job can succeed while a flag skipped the test steps inside it, and the job conclusion hides that. The only guard is the all-flags arm of `ci-scope.sh`. The skip also reads each check's own conclusion: every check must have concluded `success` on that head (owner-relayed 22:07 CST Nov 12, third reviewer's measured case, a docs-only batch whose suites skipped). The checks are the jobs `all-jobs-passed` needs, minus `scope`, `push-skip`, `nightly-skip`, `ci-done` and `all-jobs-passed`, read from `checks.yml` by `lint/all_jobs_passed_rules.py` and held to it by `lint/test_push_skip.py`. The read takes job conclusions only, not steps. A step skipped inside a green job is still accepted risk. Unmeasured. The full Windows suites and the sweep mutation steps now cost every ready PR run time they did not cost before. Unmeasured.
Cost of `nightly-skip`, dead since the nightly was dropped: two runs reads per nightly (two `GET` calls on the Actions runs API), unmeasured. It starts no process beyond its own job, writes no file and sets no timer.
Cost of `push-skip`: one pull request list read per push, and per integration PR head two reads, unmeasured. Those two are its commit and one page of its check runs, up to 100. The page now holds every job of the head, not only `all-jobs-passed`. The job also reads the workflow file once from the checkout, unmeasured. It starts no process beyond its own job, writes no file and sets no timer.
