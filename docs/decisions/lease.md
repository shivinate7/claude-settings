- **Cost.** Each count is an upper bound on git starts. A read (`read`, `holds`, `show`) starts `ls-remote`. If the sha is new to this process, it also starts `fetch` and then `log`. A `fetch` that exits with an error is retried once, so a read starts `fetch` at most twice: at most 4 git starts in all. On a repeat call for a sha seen in this process, or for a missing ref, it starts only `ls-remote`. A command-line call is a new process, so its sha is always new. The cost test `test_holds_starts_git_at_most_three_times_then_at_most_twice_for_the_same_sha` in `hooks/test_lease.py` pins at most 3 on a first call and at most 2 on a repeat, both on a clean fetch. The retry tests pin at most two `fetch` starts, not the total. A take starts `config` at most once, when it has a holder. Each of at most three tries starts a read. If no live lease is there, the try starts a push: at most 6 starts (`remote get-url --push`, `for-each-ref` before the push, `mktree`, `commit-tree`, `push`, `for-each-ref` after), and one `update-ref -d` for each new tracking ref, started only then. A failed push adds at most one more read. A give back starts a read, and a push only when the lease is live and held by the caller: at most 6 starts, and one `update-ref -d` for each new tracking ref, started only then. A failed push adds at most one more read. A lift starts `ls-remote` for the sha, then a push: at most 6 starts, and one `update-ref -d` for each new tracking ref, started only then. A failed push adds one more `ls-remote`. A lift makes at most three tries and never reads a record, so it starts no `fetch` or `log`. Each guarded act (a push to the record branch, or a Stop check that needs the page writer) makes a `holds` call. Those guards are not built. No timer, no long-lived process. Writes: a read that fetches writes the local git ref `refs/lease-read/NAME` in the repo the tool runs in, and stores the fetched objects in the repo's object store. Each push stores its record commit in that object store. A read's fetch writes no remote-tracking ref. A push goes to the remote's push URL and carries a second remote of that URL on the push command only, so git finds no unique remote and writes no remote-tracking ref (reported for git 2.56, unverified). The fallback push by remote name, used when the URL cannot be read, writes one. The tool deletes a new one after the push; a tracking ref that was there before is left as git moved it, to the pushed record.

## Built

- **The tool**, `hooks/lease.py`: take, give back, lift and show. A lease is the ref `refs/heads/lease/NAME` on the remote. A take is one force-with-lease push.
- **The record form.** A commit with an empty tree. Its message lines are `lease NAME`, `holder:`, `repo:`, `taken:` and `roster:`. A give back or a lift pushes a released record with `expires: 0`, and never deletes the ref. A taken record has no `expires` line.
- **The holder id.** A cloud id `cse_X` maps to `session_X`. A cloud value of another shape gives no id and never falls through to the local id (`hooks/override.py` `session_id_in`, `hooks/lease.py` `holder_id`; test `hooks/test_lease.py::test_a_malformed_cloud_value_gives_no_id_and_never_falls_through`). With no cloud value, the local session id (`CLAUDE_CODE_SESSION_ID`) is used, else none. `holder_id` also takes a hook payload's id, used only when no env id is set; the CLI passes none (`hooks/lease.py` `main`). With no id, take and give back refuse (`hooks/lease.py` `main`).
- **The bounded read.** All git calls of one read share 10 seconds (`hooks/lease.py` `READ_BUDGET_S`). In a push, the commit and the push share 30 seconds counted from the start of the push, and each other git call of the push has its own 30-second limit (`hooks/lease.py` `_push_record`, `PUSH_TIMEOUT_S`). A read that fails, or runs past its time, is unknown and never free.

**Not built:** every guard that reads a lease; the roster's local ids; roster removal; the page button; the merge lock's move into the family (the merge lock still uses `refs/heads/merge-lock/<base>`); the merge-role lease; and the removal of the role file (`write` in `hooks/session_role.py` still writes it).

The merge tool's lost-work list does not skip lease branches, so it can list one, if its newest commit is at least 6 hours old (`merge/merge.py` `LOST_WORK_DONE_HOURS` = 6) and no open pull request names it; state f names the coordinator as owner (`merge/merge.py` `lost_work_branches`, `merge/merge.py` `LOST_WORK_OWNER`). Until the list skips lease branches, nobody leans on a lease.
