# The owner acts where he reads; he never hunts for what he must act on

## The ruling

Owner, 2026-10-28 13:01 CDT (waiting-page gripe on item 47): when an item asks the owner to act, everything he needs sits on the item. He never searches for the page to press on or the file that holds a command.

- An option or step that asks him to press in a web app (GitHub, a pull request, a `home#374` ref, Settings) carries a link to that exact page. The link sits on the option that presses; a task carries `links` on the item. A `#374` ref needs a url with `/pull/374` or `/issues/374`. Rule `style-press-has-link` holds the text.
- A step never sends him to a file for a command, and never holds one. Owner, 2026-10-30 14:47 CDT (item 78 note): the command comes as PowerShell and Mac. The task's `command` field is `{powershell, mac}`: a PowerShell 5.1-safe block and a bash or zsh block. The page shows one closed disclosure per shell, each with a Copy button, PowerShell first on Windows. The step says "paste the command below". Rule `style-command-in-item` holds the text.
  - A stored `command` that is one string, from before this ruling, shows as one block with no shell label, so a bash line never shows under a PowerShell label. The guard refuses a new write of one.
- Guard rule `press-link` (`hooks/question_form.py`, run by `hooks/guard.py`) refuses an `ArtifactData` set or update to `items` whose option (label and how, read together) or task steps (joined; the title names the page when the steps name none) have a press verb and a web marker. A press verb is press, click or tap (but not "press on", and not the page's own Send, Mark done or Take my pick, or "this item" but for "this item's"), an imperative approve, merge, hit or turn on (`you` may come first), or "mark" a PR or `#N` "ready", or "mark ... ready on" a ref. A web marker is GitHub, a PR, a pull request, a `#N` ref (not "item #N" or "step #N"), or Settings as a page name. It refuses when no link goes to the page.
  - The rule covers a press the owner makes (coordinator ruling, 2026-11-01 21:14 CST, process-only; the lane orchestrator ruled the label rule below, process-only). The guard reads an option's how, or a chat option's description outside Gain and Lose. A clause there is a press the session makes when the session is its subject and names no `you` and no owner who acts: "the owner", "Shivam" or "he" as subject of a present or future press or act verb (press, click, tap, approve, merge, hit, turn on). Only a modal, an -ly word, or then, also, first or now may stand between (lane orchestrator ruling, process-only, from this rule's scope). "As the owner asked", "after Shivam's OK", a past act ("after he has merged the base PR", "after the owner approved the plan") and a press of the page itself ("after he hits Send", "after Shivam approves this item") ask for nothing and stay allowed (lane orchestrator ruling, process-only). A clause ends at a comma, `;`, `:`, `(`, a spaced dash, a sentence stop, a newline, or `then`, `and`, `but`, `so`, `or`. Example: "After the pick, the session merges PR #374." Only that clause is excused. The clauses left are joined with `;` and read as one text. So a press in another clause, such as "then press Merge", still needs a link, and "Mark the PR (#12) ready for review" stays a press across its break. The label is always read. A label that asks for a press, such as "Approve on GitHub", is an owner press. It is excused only when each press verb in it is a verb that a session clause also holds. The guard reads the text only, and no item field says who presses. A task's steps are read as before.
  - A `#N` ref needs a url with `/pull/N` or `/issues/N`. An unnumbered press passes with any link.
  - It skips an update with `steps` and no `links`: the stored links are not visible.
- Guard rule `command-in-item` refuses a task set or update whose steps, joined, say "the command in/from <file>", or say "its command" with a file named. A `command` on the item does not excuse these two. It also refuses "run/copy/paste the command" with a file named, when the item has no `command`; "the command below" never matches. It also refuses a `command` that is not both `powershell` and `mac` as non-empty strings. It refuses a `powershell` block with `&&`, `||`, `<<`, `<<<`, `/dev/null` or `export`, since PowerShell 5.1 has none of them. It refuses a step whose backtick span or fence holds a shell line. A span with a chain, an operator or two lines, is a shell line when one segment plainly runs a command. The command word is read past `VAR=value`, `env`, `time`, `sudo` and `$(`. It counts when it is in `SHELL_PROGRAMS`, is a hyphenated cmdlet such as `get-process`, or is a lowercase word with an argument, such as `grep -n x`. A span with no chain is a shell line as follows. Its command is a Verb-Noun cmdlet, bare or at an absolute path. Its verb must be an approved PowerShell verb (`PS_VERBS`), so `ConvertTo-Json x` is a shell line. Or its command is a `SHELL_PROGRAMS` program with an argument. Or its command is a lowercase word whose second word is a flag (`grep -r x`). The last case does not apply when that word is a determiner or other prose determiner (the, a, an, this, its, your, that, these, those, each, every, my, our, some), as in `the -x flag`. Controls such as `grep -r x`, `chmod +x f` and `ok --force` stay shell lines. Plain text is no command: `foo|bar` with no space, `title; subtitle`, a `//` line, and a table row that starts with `|`. A `./` or `../` path is a shell line when an argument follows it or its name has no extension. A path that ends in `.sh`, `.ps1`, `.py`, `.bat` or `.cmd` is a shell line when a run verb comes before it or a fence holds it. At an absolute path, the cmdlet's verb must be an approved PowerShell verb (`PS_VERBS`, the Get-Verb list) there too, so `/opt/bin/Get-Thing` is a shell line and the folder `~/Documents/Claude-Settings` is text. An absolute path starts with `/`, `\`, `~`, `$HOME` or a drive such as `C:`, with `/` or `\` after the prefix, as in `C:/tools/Get-Thing`, `C:\tools\Get-Thing`, `$HOME/bin/Get-Item` and `~\Get-Item`. The path may follow `&` or a `VAR=value`, `sudo` or `env` prefix, as in `& C:\tools\Get-Thing`. A relative path such as `docs/Read-Me` or a URL is text. It does not judge a decision.
- Both rules judge only a call whose `url` is this repo's waiting page (`layout.waiting_page`). Both are built against the named incidents below. They landed 2026-10-29; the shell checks of `command-in-item` landed 2026-10-30.
  - Cost: no new process. They run inside the guard process that every `ArtifactData` call already starts. They write no file unless they deny.
  - Known limit: the guard reads words, not meaning. A press verb outside the list (such as enable auto-merge, select or close) passes. An unnumbered press passes with any link.
- Owner, 2026-10-31 14:55 CDT (see Incidents): "shivinate7 should be the default unless if it's a repo that shivinate7 doesn't have access too of course". The act: a gh command handed to the owner opens its block with `gh auth switch -u <login>`. The login is shivinate7 by default, and ssemwal-cdc only where shivinate7 has no access. The switch is the first gh line. A `# open Git Bash` comment and the `cd` may come before it. Rule `output-never-hand-off-doable-step` keeps the `cd` first.
- Guard rule `gh-login-switch` (`hooks/question_form.py`, run by `hooks/guard.py`) refuses a waiting-page task whose `command` runs a gh command other than `gh auth ...`, with no `gh auth switch -u <known login>` before it. It also refuses a command that names `shivinate7/` when a gh command other than `gh auth ...` runs after a switch to `-u ssemwal-cdc`. A switch to ssemwal-cdc with no gh command after it passes. Each shell in `command` is judged on its own, with its own reader, and needs its own switch: `powershell` by PowerShell rules, `mac` by bash rules. A `str_replace` on `command` is judged on its `new_str`, with one excused edit (the next line). The guard cannot see the stored command. The text is read as bash, or as PowerShell when only PowerShell can read it. The known logins are `GH_DEFAULT_LOGIN` (shivinate7) and `GH_FALLBACK_LOGIN` (ssemwal-cdc), in `hooks/shared_names.py`. The Stop reply judge (`hooks/reply_judge.py`) gets the same rule for chat blocks. It is a sampled model, not a guard. Built against the 2026-10-31 incident below. Landed: 2026-10-31.
  - A `str_replace` on `command` is excused from the missing-switch reason only, when it only changes a gh command the item already had. That means `old_str` holds a gh command, `new_str` holds no more, and neither holds a `gh auth switch`. The switch the stored command keeps still stands. Every other reason is judged on `new_str` as for a full write. An edit that adds a `shivinate7/` repo name is refused, because the stored login may be ssemwal-cdc.
  - Cost, as designed: no new process. It runs inside the guard process that every `ArtifactData` call already starts. It writes no file unless it denies.
  - Known limit: no check knows which repos shivinate7 can reach. So it does not judge a switch to ssemwal-cdc on another owner's repo.
