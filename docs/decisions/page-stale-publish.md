# A waiting page behind main is not published

## The ruling

Every republish of a waiting page is main's `skills/waiting-page/page.html` with the live `designData` and roadmap blocks kept, never the live page's own code (decision `questions-go-to-owner`, skill `waiting-page`, "Keep the page on main's code"). A session that publishes from an older file puts old page code on the page the owner reads. The guard now refuses that publish, and a stamp lets the next session start say when the page is behind.

- Guard rule `page-stale` (`hooks/guard.py`, `page_stale_hit`) judges an `Artifact` call that publishes this repo's waiting page.
  - It judges only a call with no `action` or `action` publish, no `asset: true`, a `file_path`, and a `url` with the same artifact id as `layout.waiting_page` of the cwd's repo (`layout.is_waiting_page_url`, called by `question_form.waiting_page_root`; the `/artifact/` and `/code/artifact/` forms, a trailing slash and a query compare equal; a bare `.../artifact/` names no page). Any other call, a read, a list, an asset upload or a publish of another page, leaves before it loads `stale_pages`.
  - It loads `stale_pages.py` from `skills/waiting-page/` beside the hooks folder, else from the config folder. It gets main's `page.html` with `find_template(None)` and compares with `matches`, the one home of "current". The designData body, the roadmap block and the title text are ignored, so a page that `stale_pages.py --write` built passes.
  - Behind: it denies. The reason says to read the live page, run `stale_pages.py --page <saved live page> --write <out>`, and publish `<out>`. It names no forbidden target.
  - Unknown (main unreadable, the file unreadable or empty, `stale_pages.py` missing): it allows and logs one `noted` line under `page-stale`. The rule fails open.
  - Untouched template: a republish (a `url` is set) of main's page with its own title text and its `designData` and roadmap blocks all equal to main's (`stale_pages.carries_data`, read from the same `page.html`, white space ignored) is refused. It would drop the live page's data. The reason gives the same remedy as Behind, plus the exit when the live page is itself untouched and `<out>` is refused again: set the `<title>` of `<out>` to "<repo> Cockpit" (owner ruling, 2026-11-02 11:12 CST) and republish. A page that `--write` built has its own title and passes. A first publish, with no `url`, never reaches this check.
  - Current and carrying data: it allows and writes the stamp, `<git common dir>/waiting-page-built`, holding the full 40-hex blob sha of main's `page.html`. The sha comes from `stale_pages.read_origin_main`, which already parses it: the one home of "main's page version". No constant and no copy of the template exists.
- The page-built stamp `roadmap/data/meta/page-built.json` on the record branch (`origin/roadmap`) is the stamp that survives a fresh clone. Its shape is JSON `{"blob": ..., "at": ...}`.
  - `blob`: the 40-hex git blob sha of `skills/waiting-page/page.html` at `origin/main` at the republish. It is what `stale_pages.read_origin_main` returns as its sha (`git rev-parse origin/main:skills/waiting-page/page.html`). It is written only from a real republish: a stamp for a build that did not happen would hide a stale page.
  - `at`: the republish time, ISO 8601 with the US Central offset, such as `2026-11-15T01:23:00-06:00`. It is informational: no reader reads it.
  - Writer: triage, at each republish, after the publish succeeds. `skills/waiting-page/stale_pages.py` only reads it (`git show origin/roadmap:roadmap/data/meta/page-built.json`). A missing branch, a missing file, text that is not JSON and a `blob` that is not 40 hex all count as missing.
- `hooks/session_start.sh` runs `stale_pages.py --session-line <toplevel>` in a repo whose extras file names a page. Two stamps hold main's blob sha at the last publish: the page-built stamp and the local stamp. If either equals main's blob sha, it prints nothing. If at least one stamp exists and none equals it, it prints one line naming the page as behind. If the page-built stamp is missing or unreadable, the line is what it was before that stamp existed: the local stamp against main's blob sha, behind when they differ, silent when equal. If neither stamp exists, it prints nothing: an unread state is never reported as behind. A repo with no page in its extras prints nothing. Stamps that exist with an unreadable main print nothing.
- After a merge that changes `skills/waiting-page/page.html`, the merge tool prints one line that says to republish each live page and to put `republished: <pages>` or a reason in the report. When the changed paths could not be read, it prints an `UNKNOWN` line that names the file. Both are report-only: the exit code does not change.
- Incident class: likely risk (rule `building-guard-needs-incident`). Claude is likely to republish a page from a stale saved copy in normal work, and the page's data and Status tab were lost that way before. Landed 2026-11-01.
- Cost:
  - `guard.py` already starts on each call of its matcher (unmeasured: no test counts the starts). The matcher now also names `Artifact`, so it starts once per `Artifact` call (unmeasured). A read or a list exits before the heavy imports.
  - Every `Artifact` call also runs the session-home record step that every guard call runs (`session_home_keep`): one path walk and one small file read, and one write only when the record is missing or changed (unmeasured).
  - Per waiting-page publish: one python import of `stale_pages`, one read-only git process (no fetch, no network), one file read, one stamp file write (unmeasured).
  - Session start: one python start and at most two read-only git processes (`git show` of the record in the repo, and the read of main's `page.html` in the claude-settings clone), only in a repo with a page (unmeasured). Any other repo pays one grep.
  - Merge line: no process. It reads the changed-path list the merge tool already read.
  - The writer's wake pass (`stale_pages.py --page ... --items`): 0 gh processes without `--items`; with it, one gh process per open item with `waits`, at most 50, each ended or killed at 30 s before the next. No file written, no timer, no process left running (`test_stale_pages.py` proves the call counts).
  - No timer, no new long-lived process, no new log beyond the one `noted` line on unknown or on a failed stamp write (unmeasured).
- Known limit: that the `/artifact/` and `/code/artifact/` forms with one id name one page is unmeasured.
- Known limit: a first publish with no `url` passes. So does a republish by the same `file_path` with no `url`: it redeploys to the same url, unjudged.
- Known limit: the stamp is written at PreToolUse, so a publish that then fails still stamps. A stamp write that fails logs one `noted` line under `page-stale`.
- Known limit: the session-start line compares blob shas, not `matches`. A `page.html` edit that `matches` ignores (title text, white space) prints the line until the page is republished.
- Known limit: the rule never fetches. A stale local `origin/main` makes an old page read as current, and a newer page as behind.
- Known limit: an `ArtifactData` write is not judged by this guard. It writes items, not page code.
- Known limit: a fresh cloud container with no page-built stamp on `origin/roadmap` has no stamp, so its session start is silent until triage's first write. The merge tool's republish line is what carries cloud sessions meanwhile.
- Known limit: the page-built stamp is only as current as the last republish that triage recorded. A page republished by hand, with no stamp written, reads as behind or as the older version until triage writes it. The local stamp can still silence the line when it equals main's blob sha.
- Known limit: the merge tool's republish line is report-only and prints after the merge call. A merge whose outcome is unproven (the call could not run) stops in the tool's unproven stop and prints no republish line.
- Known limit: the local stamp records the last allowed publish from this clone, not the live page. A publish from another machine, or by hand, moves the page without moving the stamp.
