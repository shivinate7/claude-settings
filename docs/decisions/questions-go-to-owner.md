# Questions go to the owner

## The ruling

Owner, 2026-10-26: a session with a question brings it to the owner. The question names what the session does meanwhile, or that it waits. The session keeps working on what does not depend on the answer.

- **Take a pick that can be undone** (roadmap step c102, take undoable picks; 2026-10-27). A question whose pick rule `parallelism-keep-going` lets the session take with no question is not asked. The session takes the pick and names it under Done. That rule holds the exceptions: a pick that cannot be undone, a change to the owner's goal, work in another repo, and a wait for the owner's grant that another rule makes. Incident: a mailaudit report asked "link the waiting page now with a folder move, or later"; later changed nothing and could be undone. The Stop reply judge (`hooks/reply_judge.py`) notes such an Input Needed item and never blocks (decision `reply-judge-samples-never-refuses`).
- **A picture in each option** (owner, 2026-10-27 12:10 CDT): "Some of your questions on your artifact need pictures. You should in general put a mockup image inside each option card on the waiting page first. No links to folders." A decision whose options differ in how something looks carries one mockup per option, shown inside that option's card, before it is added. Every option carries one, and the page warns on an option without one (owner, 2026-10-27 23:40 CDT). A tap on the picture opens the viewer (owner, 2026-10-27 12:13 CDT). A link to a folder or another artifact does not count. Skill `waiting-page` ("Add a design") holds the format.
- **Read standing grants first** (owner, 2026-10-27 15:51 CDT; roadmap step c148, port keeps behaviour). Before it asks, a session reads the repo's CLAUDE.md for standing grants. A grant the owner gives in chat lands in the repo's CLAUDE.md or the merge tool's config, never only in a hand-off. Incident: an orchestrator asked the owner to merge in a repo with a standing merge grant. Record `port-keeps-behaviour` holds the rule for a port.
- **Every question is vetted, with no route around it** (owner, 2026-11-01 18:48 CST). When the owner retired the advisor, he also said that every question still gets vetted before it reaches triage. He allows the advisor back if it beats the in-session checks, but a check must exist. The Oct 26 retirement (roadmap step c51, PR #578) recorded no promise. It recorded only the gap, as debt `settled-question-unchecked`: no check runs on a question that a record settles. Now every question is checked against past rulings before the owner or the waiting page sees it. `hooks/call_judge.py` checks the question box and a page item write. `lint/report_guard.py` checks a question in a chat reply: an Input Needed label, or a prose line that ends in `?`. A relayed lane question is one of these. The search, `question_form.past_rulings`, reads decision records, debts and roadmap step notes. A model refuses a question that a ruling settles or explains, when no `Based on (ruling)` line cites that ruling, and names the ruling. A check that cannot run refuses once. The question then carries an `Unvetted: <reason>` line, so the owner sees that no check ran. Why hooks, not the built-in advisor: a session calls the advisor only when it chooses, so a question can skip it. A hook runs on every route. The hook's judge is a separate model with no session context, given the rulings. Measured 2026-11-02: one Sonnet call on the 165 KB index took 2.8 to 4.9 s (4 runs). The advisor's catch rate is unmeasured. Incidents, 2026-11-01: page item 145 asked the Oct 28 keep-the-apps ruling again. Item 133 asked the Oct 27 milestone-runs ruling again. A lane asked whether ci-job-caps means "about 2x" or "under 80%". Two open chat questions shared keys a/b, and the owner's "a" was misread. Decision `question-form` holds the mechanism and its cost.
- **A ruling with no record is invisible to the check** (owner, 2026-11-09 19:35 CST, relayed by the coordinator; roadmap step `past-ruling-reads-newer-ruling`, the judge reads a newer ruling). The past-ruling check reads decision records, debt records and roadmap step notes only. It never reads chat or closed page items. A ruling that sits only there cannot be seen, so the check refused a question that an older record seemed to settle. The check was right for what it read. The fix is to file each ruling to its question's record at once, inside the first 800 characters of that record's ruling (rule `output-answer-has-a-home`, an answer has a home): the check reads only that much, so a ruling added deep in a long record is not seen. Whether a `Based on (ruling)` line that cites an unfiled ruling passes the check is unmeasured, and the code does not make it pass (`hooks/call_judge.py`, item 8, the past-ruling item of the judge's list, passes only a ruling the judge was shown). Step `past-ruling-reads-newer-ruling` proposed that the check read chat and page rulings; that stays open and would widen the check, so it needs the owner's grant (rule `outcomes-stale-decision-protocol`, a stale record is proposed to the owner and waits for the grant).
- **No outside advisor.** The terminal advisor (a session named `advisor-` and a short suffix, started from its own config folder on Windows) is retired. No rule, hook or report label sends a question to it.
- **The built-in advisor.** `advisorModel` in `settings.json` stays. It is a second opinion that a session calls on its own work, and it sees only that session's conversation. It answers no question for the owner and decides nothing, so it lifts no guard and grants no override. It is not the question check: the hooks above are.
- **The waiting page** (owner, 2026-10-26). One page per repo or project holds every item waiting on the owner, from every session (ruling 1a). A save by the owner on that page counts as the owner's grant for the item it answers (ruling 2a). The terminal question box stays in a repo with no waiting page (ruling 3a; narrowed 2026-11-01, see "Same turn to the page"). Under the owner's 2026-10-28 15:10 CDT ruling, the box no longer links the page: the box opens before any item exists. Skill `waiting-page` holds the protocol. A "none of these" answer whose note gives a clear direction closes the item. The note becomes a roadmap step, or a todo record where there is no roadmap, and the item is not asked again (owner, 2026-11-01 17:44 CST; roadmap step `none-with-note-is-direction`, a direction closes a "none of these" answer).
- **Same turn to the page** (owner, 2026-11-01 23:31 CST, pick a). Every question for the owner goes to the page writer in the same turn it is asked. An owner answer in chat closes the page item. There is no clock: the 5-minute chat-first wait is gone (owner, 2026-11-01 23:31 CST, pick a). No record shows that an expiring timer costs less than it saves, so rule `outcomes-mechanize-rules` (turn rules into checks) allows none. A session that is not the writer sends the question to the writer, which writes the item. A lane's question goes to its parent instead (see "A lane never writes the waiting page"). If the owner answers before the item is written, the writer writes it closed, with the answer and its time in `context`. The owning session then files the answer to its home and writes `receipts/<id>`, as "Route and close" step 1 says. The writer never writes receipts. So every question and answer ends in the page's record.
  - **Mechanism.** The Stop report guard (`lint/report_guard.py`) blocks a reply whose Input Needed offers a pick or asks a yes/no. It passes only when the same turn sent the question to the writer or wrote a page item. With nothing running, the question box passes only in a repo with no waiting page (owner, 2026-11-01 23:31 CST, pick a). In a repo with one, the box passes nothing, and the send to the writer passes by itself. A send counts when it goes to the writer id, read from `meta/page` in the transcript, in any session. A send to `@parent` counts only in a lane: a session whose own `get_session` record has a parent id or the tag `cs-build:lane`. In an owner-facing session it reaches no one. The first reply from a send's target is its ack and starts no turn; a later message from that target starts one. Gap: a new question in that first reply is read as an ack (debt `lane-ack-skips-every-reply`). A repo with no page is not blocked; the guard prints a systemMessage instead, unless the turn opened the box.
  - **Incident** (2026-11-01 23:26 CST). The old check passed a promise to send later, and nothing checked the send.
  - **Cost.** No file. The guard reads the transcript it already reads. The extra reads come only on a turn that asks with no send to the writer. In a session with a remote id, that turn imports the own-record reader and reads the transcript once more, which also decides whether a send to `@parent` counts (unmeasured). A lane reads no layout; an owner-facing turn with no counted send reads it once (unmeasured).
  - Gap: a session with no Stop is not checked.
- **No box while work runs** (ruling 3b, which narrows 3a). Owner, 2026-10-26, waiting page item 30: questions should not hang, so the session "gets back to orchestrating". Triage read that as this design, on roadmap step c84; the owner asked for the outcome, not this text. While an agent, a lane or a background command of this session runs, or starts in the same response, the session opens no question box. It asks in its reply, keeps orchestrating, and reads the answer at its next turn. Under the owner's 2026-11-01 23:31 CST ruling, every question goes to the page writer in the turn it is asked (see "Same turn to the page"). With nothing running, the box passes only in a repo with no waiting page; in a repo with one, the send to the writer passes by itself. Why: a box stops the session until the owner answers, and its running work does not stop. A UI session waited on a box while its agents ran on, filled the disk and crashed. Its brake ran only once the owner answered. No record shows a saving for an expiring timer, so rule `outcomes-mechanize-rules` allows none (timer ruling `timer-allowed-when-cheaper`). A hook cannot close a box already on screen. A repo with no page asks in the reply or the box only.
- **A lane never writes the waiting page, unless it wears triage's hat in a run with one lane.** A lane puts its question in its report. A lane also sends the question to its parent with `send_message` in the same turn. The Stop report guard blocks a lane reply whose Input Needed offers a pick or asks a yes/no unless the same turn sent it to its parent or the writer. A box, a page link or a promise to send later does not pass. A lane's own chat is not a route to the owner. Triage writes the item with the asking session as `owner`, and routes the answer to the lane or its next try. The spawn judge (`hooks/call_judge.py`) flags a brief that tells a lane to write an item, and passes one that forbids it.
- **Each page has one writer, and the writer ranks.** The writer is triage (owner, 2026-11-10 14:30-14:32 CST). In a run with one lane, the lane wears triage's hat (owner, 2026-11-10 14:33 CST). The page names it in `meta/page` as `writer`. A repo may also name its session id in the extras key `page-writer`, which the pick guard uses when the transcript has no `meta/page` read. The key send counts only on a delivered result. A rotation updates it. Every other session sends its question to the writer, which writes the item. A lane sends its question to its parent in the same turn, and triage writes the item. Not built: the route from a lane to triage. `owner` stays the session that asked. The fact tiers stay the base and are never written by hand. Inside a tier the writer sets `rank` (an integer, lower first), judged against every open item on the page. It re-ranks when it adds, updates or closes an item. A close by another session needs no re-rank. The writer re-ranks at its next add or update. The page sorts by `rank`, then by age for items without one. A group sits at its best member's rank.
- **The page runs main's code** (owner, 2026-10-29 14:47 CDT; roadmap step wp-republish-on-template): a live page ran old page code, because its writer kept the live page's code and swapped only the mockups. "ensure u and all my other repos know to do that proactively." The writer checks its page against `skills/waiting-page/page.html` on claude-settings main at each wake, and every republish is main's page with the live `designData` kept. `skills/waiting-page/stale_pages.py --page` is the one check. It runs on demand at a wake, with no timer.
- **Answer on the page, not in a comment thread** (owner, 2026-10-28 02:44 CDT): "you don't reply in just Claude replies for the waiting on you artifact (given that artifacts can be torn down and remade) instead you gotta just revise the questions with whatever your reply adds". A session answers a comment on the waiting page by rewriting the item it is about, never by a thread reply: a rebuilt page drops its threads. The session says in one line in the session what it changed.
- **Owners read their own answers** (owner, 2026-10-26). Each waiting item names its owning session. That session reads, routes and closes the item at each wake. No session relays an answer as text. A session that acts on another's item reads the answer itself (decision `relayed-grant-read-from-page`, a relayed grant is read from the page).
- **The report.** The labels are Done, Deviations, Input Needed, Next. `lint/report_guard.py` refuses any other label.
- **The message check.** The two judges in `hooks/sendmessage_state.py` treat every receiver as a peer.
