# One question form, one guard, for the chat box and the waiting page

## The ruling

Owner steer, 2026-10-30 12:50 CDT: a question to the owner has one form and one guard, for the chat question box (`AskUserQuestion`) and for a waiting-page item write. Rewrite the guards as one; never add chat guards beside the page guards.

- The form. A decision on the page (in `context`), or a chat question with two or more options (in the question text), has these lines in this order:
  - `Goal: <the goal, in the owner's terms>`
  - `Problem (<stake>): <the problem in one plain sentence, and why it needs his word>`. The stake is one of `goal`, `money`, `risk`, `rule`, `cannot undo` (constant `OWNER_STAKES`). A stood pick (`stands: true`) may write `Problem: <text>`.
  - one to three `Based on (<kind>): <one premise>` lines. The kind is one of `PREMISE_KINDS` in `hooks/precompact_handoff.py` (decision `premise-format`).
- Each option states its gain and its loss: a page option has non-empty `gain` and `lose` fields; a chat option's description holds `Gain: <text>` and `Lose: <text>`.
- A widening option carries the mark and is never the pick: `widens: true` on the page, never in `pick`; in chat, the words "Goes against your ruling: a repo changes to fit a shared tool, never the tool to fit a repo" in its label or description, and no `(Recommended)` in its label (decision `uniform-over-variants`).
- A press in a web app carries a link: `links` on the page, an `https://` url in the option's description in chat (decision `act-in-place`).
- Code checks the lines, their order and the marks. `hooks/question_form.py` is the one home: `item_hit` for a page write, `chat_hit` for a chat box, and `page_item_hit`, the one filter of which `ArtifactData` writes are item writes of this repo's waiting page. `hooks/guard.py` calls `item_hit` through that filter and refuses a hit. `hooks/call_judge.py` calls `chat_hit` before any model call and refuses with the rule it names. Both places then get the same model review (owner ruling, 2026-11-01 11:51 CST). A chat box that passes goes to the question judge model. So does a page write of a decision that passes `item_hit`, is not closed, and carries `options` or `context`. So does a page write of a task (kind task, or any write that carries `steps`, since steps are task-only) that passes `item_hit`, is not closed, and carries `context`, `steps` or `options`. So does a `str_replace` on `context` that passes `item_hit`. The `ArtifactData` `str_replace` `field` is one top-level string key, so only `context` occurs in practice: it never reaches `options` or `steps`, which are lists (note `page-judge-dead-fragment-fields`). A task adds one rule to the seven items, the whole-unit rule: a step that tells the owner to replace text quotes the whole unit it replaces (the whole line or value) and shows the line after the change in full. Its incident is waiting item 99 (2026-11-01): the step said to change `GUARD_SHELL_SKIP=` to `GUARD_SHELL_SKIP=tree` while the real line was `GUARD_SHELL_SKIP= scripts/guard-shell.py --hook`, and following it dropped the script call. A `str_replace` is judged on its `new_str` alone, never `old_str`, as a fragment: the prompt tells the model to judge only plain words, unexplained ids and pointers outside the item (items 3 to 6), and never to flag a missing line or option. Both get the seven items of its prompt (decision `question-reviewer-agent-hook`). The model keeps only what code cannot decide.
- Rule ids. These refuse as `question-form`: a missing Goal, Problem or Based on line, lines out of order, and a Based on count outside one to three. So do a kind outside `PREMISE_KINDS` and an option with no gain or no loss. A Problem line that is bare, or whose stake is outside the set, refuses as `owner-judge` (decision `owner-judge-test`). The older rules keep their ids: `port-question`, `uniform-pick`, `press-link`, `command-in-item`, `gh-login-switch`, `task-names-check`. They run first, in that order, then the form.
- A stood pick and a port carry the full form. A stood pick may omit the stake. A port still needs its Departs from line.
- Update semantics are the page guards' own. An update is judged for the fields it carries (`context`, `options`, `pick`, and `steps` for a task). A closed item passes the form. A `str_replace` on `context` that removes a Goal, Problem or Based on line is refused.
- Text. Rule `style-question-form` in `output-styles/shiv-stylisms.md` holds the form and names `hooks/question_form.py`. The skill `waiting-page` points to that rule.
- Every question is vetted against past rulings (owner rulings, 2026-11-01 18:48 CST and 18:55 CST; incidents: waiting item 145 re-asked the 2026-10-28 keep-the-apps ruling, and item 133 and a `ci-job-caps` question were written without the 2026-10-27 rulings). `question_form.past_rulings(text, repo_root)` returns `(candidates, unknown)`: one index line per decision and debt record (`decisions/<stem>` or `debts/<stem>`, the whole `## The ruling` section, white space collapsed, 800 characters; a record with no such heading gives its body after the title), including the claude-settings checkout's decisions (`guard_pointer.pointer_checkout`); plus the 30 step-note ruling units of the `roadmap` ref (`roadmap/data/steps/*.json`, fields `note` and `why`, a sentence with Ruling, owner or shiv and the sentence after it) that share the most words with the question. Closed page items are always unknown, because a hook cannot call the Artifact tool and the decision records carry those rulings. A step ruling that shares no word with the question is missed (known limit).
- The judge prompt has an eighth item (`PAST_RULING_ITEM` in `hooks/call_judge.py`): refuse a question that asks what a listed ruling already decides, or whose premise a standing decision already explains, unless a `Based on (ruling): ...` line names that ruling. The candidates ride the one existing model call, after the reply line. The reason must start with a listed id. Code checks the cited id against the ids shown (`question_form.ruling_cite`); a refusal that cites a `decisions/..` or `debts/..` record not shown has no usable verdict and takes the Unvetted path.
- Unvetted, not silence. A model error or timeout, or a source that exists but fails to read (git error, bad JSON, unreadable file), refuses the question once, and the remedy says to add the line `Unvetted: <reason>` (the question text in the box, `context` on the page, the reply in chat). A question that carries that line passes with no model call. An absent source (no `docs/decisions`, no `docs/debts`, no `roadmap` ref) is not unreadable: it allows, with one stderr line `past-ruling search unknown: <sources>`, because refusing on absence would refuse every question in a repo with no roadmap branch, and a guard that cries wolf is spent.
- A coordinator relays a lane's question in its reply, so neither gate above sees it. `lint/report_guard.py` (the Stop hook) runs the same check on a Stop whose reply holds Input Needed or a prose line (outside code fences) that ends in `?`: one Sonnet call of 15 s through `decision_watch.invoke_model`, with the same candidates and item 8. A verdict that refuses stops the Stop with rule `past-ruling`; the report_guard Stop timeout in `settings.json` is 35 s. The same hook refuses rule `question-keys` when two questions under Input Needed, in one reply or with an assistant reply since the last human message, use the same option key with different option text (incident: two open questions both keyed a and b, and the owner's "a" was misread). The remedy: give each question its own keys, such as 1a/1b and 2a/2b (`question_form.key_overlap`). That check calls no model.
- Cost of the past-ruling check: no new process or file besides one git process (`git cat-file --batch`, never a fetch) per judged question, only on the path that already makes the model call; a call that makes no model call runs no git process. A non-question `ArtifactData` call still exits before it imports `question_form`. The prompt grows by about 165 KB (the decision index, measured on the 2026-11-01 records branch) plus up to 30 step sentences. In `lint/report_guard.py` the cost is one git process and one Sonnet call per Stop with Input Needed or a prose question, and none on any other Stop. `hooks/test_call_judge.py` and `lint/test_report_guard.py` prove it.

Risk kind: likely risk, with a named incident. A session writes a question with no problem line or no stated premise in normal work.

Incident:

- 2026-10-30, waiting item 92: a decision with a Goal line and no Problem line, no Based on line, and a widening option not marked `widens`. The old guards passed it.

Landed 2026-10-30.

Cost: no new long-lived process and no file written. `hooks/question_form.py` loads inside the guard process for a waiting-page write, and inside the call judge process for a question box or a page write. Per `ArtifactData` call there is one python start of `call_judge.py`. It exits before any heavy import unless the action is `set`, `update`, `str_replace` or `batch`. It makes one model call (Opus, capped at 60 s) only for an item write on the page that passes `item_hit`. The write carries `options` or `context` (a decision), or `context`, `steps` or `options` (a task). Or it is a `str_replace` on `context` or `options`. A batch makes one call for all its writes, task items included, so a task item in a batch adds no call of its own. A lone task write costs one Opus call; the bound stays one call per `ArtifactData` call. The whole-unit replace rule reaches a task's `steps` and `context` on a set or update. A `str_replace` reaches only the top-level string field `context`. These make no model call: a read, a delete, a write to another collection or page, a receipt or an answer write, and a closed item. So do an `item_hit` hit, a `str_replace` on another field, and an update with none of those fields, such as a title-only write. A call with no write on collection `items` exits before it imports `question_form`. `hooks/test_call_judge.py` proves it. A chat box that fails the code guard makes no model call.

Known limit: code reads words. An unmarked widening option, a false stake and a premise that does not match its kind pass. The question judge model and the reply judge read what code cannot. A `str_replace` is judged on its fragment only, so a fragment cannot be flagged for a line or option it leaves out.
