# Checkpoints keep the handoff current

## Ruling

Auto-compact drops detail. These rules keep the handoff and plan current across a compaction, in every repo that uses claude-settings.

1. The compact window is read in Claude Code's order. First, env `CLAUDE_CODE_AUTO_COMPACT_WINDOW`. Then `modelSettings.<model>.autoCompactWindow`: the exact key first, else any key that equals the model once a trailing `[...]` tag and a `-YYYYMMDD` date are stripped from both. `<model>` is the model on the last main-chain assistant entry with token usage. Then top-level `autoCompactWindow`. Then the default, 500,000. `settings.json` sets `"autoCompactWindow": 500000`, a token count, as the repo default. E is the window minus min(max output tokens, 20,000) in Claude Code 2.1.316 (code read 2026-11-01); item 2 uses the window minus 20,000. The hard trigger is E minus 13,000; a percent P lowers it to min(floor(E × P / 100), E − 13,000). An earlier summary point, 0.8 × E by default, applies only when remote flags turn it on. In a cloud session with P set and a window of exactly 200,000, a remote experiment can raise P. Measured, live in a cloud session on 2026-11-01: on a 500,000 window, `/context` shows only the hard trigger, 467,000. With the flags on, that window compacts near 384,000 (0.8 × E). On a 100,000 window, with the variable unset or at 80, compaction started at the same point, between 60.6k and 65.8k. That matches 0.8 × E = 64,000, so the remote flags were on for that run. To set a window for one session, launch it with env `CLAUDE_CODE_AUTO_COMPACT_WINDOW`; it writes nothing. Do not use `/autocompact`: it saves every value, even 500000 and auto, to user settings as `modelSettings.<model>.autoCompactWindow` (measured 2026-11-01, Claude Code 2.1.316; picked by the coordinator, 2026-11-01 17:45 CST).
2. Owner, 2026-11-01 19:27 CST: the checkpoints follow Claude Code's own compaction trigger, so the last one fires before compaction in cloud, desktop and terminal sessions. The threshold mirrors Claude Code 2.1.316 (`compact_threshold`): E = window - 20,000; threshold = min(E - E x f, E - 13,000). Claude Code compacts at the second term and starts an early summary at the first; the hook takes the lower, since what an early summary keeps is not read. f is the summary fraction from Claude Code's cached flags in the Claude config file (`summary_fraction`: the `tengu_amber_moleskin` table, then `tengu_amber_rokovoko`, then 0.2). `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` = p lowers the second term to E x p / 100, as in Claude Code (cloud sessions set 80: 384,000 on 500k). The env window accepts a `k` or `m` suffix and is clamped to 100,000-1,000,000; a settings window counts only as an integer in that range. The hook cannot read the session's live `autocompact_state`, so it reads the same cached flag. Measured on 500k: `autocompact_state.threshold` 441,600 with the override at 92 and 384,000 with it at 80 (2026-11-01); the override differs per cloud session, so the hook reads it live. The session updates its handoff at message checkpoints, while it has full context. Messages = the last usage sum minus the first turn's usage sum, a proxy (record `hook-inputs-carry-token-counts`). The room is the threshold minus that first turn. The checkpoints: 200k messages, then every +150k below the top, then a last one at the top. The top is the room minus 50k, or minus half the room when the room is under 100k. With no room left, the top is the room minus 50k. A step under 75k below the top is dropped, the 200k one too. A session with no messages never gets one. After each compaction, auto or manual, it rewrites the handoff whole: what is true now, nothing appended. It updates the plan file too, when it works from one and the plan's state changed. Cost: one read of the Claude config file at each Stop; none at PreCompact; no process start, no file written beyond the existing state. Known gap: a model window smaller than the settings window is not read (debt store notes).
3. After compaction, a short message reorients the session. `settings.json` sets `"idleCompaction": false`, so a session never compacts only because it sat idle (owner, 2026-11-01 19:27 CST: "we should also do B where we turn it off in our own settings for cloud and desktop app sessions"). Claude Code 2.1.316 reads that key and names it in its own idle-compaction notice. A resumed long session after an idle gap then re-sends its context without the prompt cache, at a higher token cost; the owner took that cost.
4. It must work in the desktop app with no other login. No second `claude -p` with its own command-line login. So no mode of `hooks/precompact_handoff.py` calls a model.
5. The handoff is per session and outside git: `~/.claude/handoffs/<session_id>.md`. A repo's own handoff.md is a project document, changed only by PR. Reason: a scratchpad handoff was lost when something outside the session deleted that folder, and a shared, committed handoff would conflict on every PR. Rulings still go to tracked homes at once. The handoff is not in `state/handoff/` beside the digest, because `hooks/guard_frozen.py` freezes `state`.
6. Every mode fails open: on any error it logs and exits 0. PreCompact never refuses compaction. The Stop nudge refuses once at each new checkpoint and stays silent after a compaction and when `stop_hook_active`.
7. `hooks/precompact_handoff_prompt.md` tells the session how to rewrite the handoff. It uses the path the reorient message names, never a scratchpad or temp folder. It rewrites the whole file and never appends or makes a dated copy. Reason: patching let sessions append block after block, and rulings with no home sank under them.

Owner, 2026-10-13 11:20 CDT: the reorient and re-read hooks live in claude-settings. Each is a Python hook registered in `settings.json`, with a red test first. The /safe-stop entry point into `precompact_handoff` stays stable.

8. **Reorient after /clear or a fork.** SessionStart has the sources `clear` and `fork`, with no previous session id.
   - On `clear`: a SessionEnd hook with reason `clear` writes a pointer, the old session id and the project directory. SessionStart reads the newest pointer for the same directory and names that handoff. A /clear pointer whose session has no handoff names none.
   - On `fork`: no pointer is read, because a pointer can name an older cleared session. The hook names the newest handoff for the same directory, which is the parent's.
   - A session's project directory is recorded each time a handoff hook runs for it (nudge, PreCompact, SessionEnd).
   - With nothing found, it says so. The session reads the named handoff and rewrites its own handoff from it.
   - At SessionStart reorient, stale pointers and `.dir` and `.reread` files are swept after 30 days (`STALE_AGE`, Claude Code's default `cleanupPeriodDays`). A malformed pointer is swept in every directory. A pointer with no handoff is swept only in the current directory. A failed pointer delete is logged.
   - After compaction, the reorient message ends with the owner feedback inbox note. After /clear or a fork, it has none.
9. **Re-read check after compaction** (`hooks/reread_check.py`).
   - PostCompact sets the session's flag. A PreToolUse Read of the session's handoff clears it. A Read inside an agent (payload has `agent_id`) never clears it.
   - While the flag is set and the handoff exists, the PreToolUse guard (`hooks/guard.py`, rule `handoff-unread`) refuses each call it judges from the main session. The refusal covers the guard's PreToolUse matcher in `settings.json`: shell, file writes, Agent, Task, Skill, Workflow, and the others listed there. Tools outside that matcher are not refused: Read, Grep, Glob, MCP tools not listed there (MCP writes), SendMessage and Monitor. A call whose payload has `agent_id` (made inside an agent) passes.
   - The guard calls `unread_handoff` in `hooks/reread_check.py`. An owner override lifts the refusal. A failed import writes no guard.log line, so only the Stop net is left. If the import fails, the guard allows.
   - The Stop refusal stays as the second net. While the flag is set and the handoff exists, it refuses once per turn and names the handoff path. It exits on `stop_hook_active`, so it cannot loop.
   - Guard basis: named incident. 2026-11-01 17:23 CST: a triage session rewrote its handoff and worked a turn after compaction before it read the handoff. The Stop refusal caught it only at turn end. Owner, 2026-11-01 17:35 CST: the slip should not be possible. Landed 2026-11-01.
   - Cost: on each guarded call, the guard loads `reread_check` and `precompact_handoff` (two module loads) and checks the flag file once. A second check, for the handoff file, runs only while the flag is set. No file is written on a call it allows; a refusal writes its guard.log line. No process starts. `hooks/test_guard.py` proves the flag check, the writes and the process starts; the module loads are unmeasured.
10. **Premises.** The handoff holds a Goal line and a `## Working premises` section, right after the rulings with NO HOME YET (step 4 of the prompt file). The reorient message lists the premises to check: after compaction every one but a `ruling`, after /clear or a fork every one. A handoff with no premise line gets "no Working premises section" and a pointer to step 4. The prompt file's "Check premises" step says to check a weak or stale premise before acting, then rewrite its line. The line format and the source kinds: `premise-format`. The Stop nudge points at step 4 and copies no section list.
11. **Digest from the last rewrite** (owner, 2026-11-01 19:27 CST). The PreCompact digest holds the user and assistant text written after the session's handoff file was last written (its mtime), at most 200,000 characters, newest kept. With no handoff file, the last 60,000 characters. A `## Refused acts` section follows: one line per tool result that a hook or permission refused after that time, at most 50. Reason: after the 2026-11-01 compaction, a session retried acts refused before it, because tool results were in neither the digest nor the handoff.

12. **A Claude Code update that changes compaction is caught** (`cc_version_check` in `hooks/precompact_handoff.py`; owner, 2026-11-01 19:27 CST). Items 1 and 2 rest on facts read from one Claude Code build. An update can change them with no sign, so the build is checked at each startup.
   - Recorded: the facts in `hooks/cc_compaction_baseline.json`, read from 2.1.316. They are the version and the defaults of `idleCompaction` and `autoCompactEnabled`. Next are which of the four compaction settings the schema holds, which of the two compaction env vars the code reads, and the summary fraction default, 0.2. Two more are the blocking margin, 13,000, and the output reserve, 20,000. The margin is the `/context` buffer: the window minus the reserve minus 13,000 is the hard trigger. The window loses the lesser of max output tokens and the reserve. The `version` fact alone is not a change.
   - Source: the installed binary, read in-process. It is the file at env `CLAUDE_CODE_EXECPATH`. When that variable is missing or cannot be read, it is `claude` on the env `PATH`, followed through its link to the real file: cloud start hooks can lack the variable (seen in 2.1.317, and in 2.1.319: the start hook of session_013NEJL2jvi3nNNTGHcbPbNL printed "CLAUDE_CODE_EXECPATH is not set" on 2026-11-06, while its Bash tool had it). The binary is read by anchor strings: setting keys, env names, a flag name (`tengu_amber_rokovoko`) and a property name (`maxOutputTokens`). Never a minified name. A minified name is only followed to its own declaration, `var|let|const NAME=<number>` or `,NAME=<number>`: the nearest one before the anchor, else the nearest after it. A bare `NAME=<number>` elsewhere is an assignment and is skipped. The blocking margin is the identifier in the last `)-NAME:void 0,` match within 2500 bytes before the `autocompact_buffer` id. The output reserve is the identifier after `.maxOutputTokens,` that ends in `)`.
   - Why stale-proof: a lost anchor reads "unknown". One gap remains: a name read from its declaration has no distance bound, so a non-literal declaration can resolve to a same-named number elsewhere (note cc-facts-unbounded-decl). "unknown" on one side only is a change and prints a line, so a build that drops an anchor is reported, not skipped. "unknown" on both sides is no change. A binary that cannot be read, by the variable or on the `PATH`, prints one "unknown" line per version, naming what was tried. A baseline that cannot be read raises before the cache is written, so the next start reads the binary again.
   - Blind spot: remote flags (the summary fraction table, `tengu_peppy_gosling`) are not in the binary. The check catches code defaults only. Item 1 keeps the measured live values. In a cloud session, `get_session` with no session id returns `external_metadata.autocompact_state`: effective window E, threshold and source. The session reads it on demand. A hook cannot call it. Its threshold field is the override term of item 2, E x p / 100, measured in 2 cloud sessions on 2026-11-01 with E = 480,000. With `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` = 80 it read 384,000. With 92 it read 441,600. Both sessions cached f = 0.15. The cloud sets that variable per session, so the field can differ between sessions.
   - Reader: the session that sees the line names it under Input Needed in its report. Then claude-settings triage (the line names this item and step `cc-update-behavior-diff`) re-reads the build, and updates the baseline and items 1 and 2.
   - Cost: process starts 0. The binary is read once per new binary, about 3 s on the 328 MB 2.1.316 (measured: 0.5 s read, 2.5 s scan). Files written: 1, `<config dir>/cc-behavior.json`, per new binary, and 0 otherwise. The cache holds one entry per binary path, up to 8, so two apps with two paths do not evict each other. How often: each startup reads the cache and stats the binary once. When the variable gives no readable file, it adds one `PATH` lookup, one link resolve and one stat. Nothing runs on a timer. With neither `CLAUDE_CODE_EXECPATH` nor `AI_AGENT` set, the check is silent and makes no lookup: CI and tests have neither.

13. **Recovered line after compaction.** Basis: likely risk, landed 2026-11-01: a standing session with no rotation limit may lose rulings in compaction. Owner asked to watch it (waiting-page item 109, pick b: no rotation limit, and a way to see if that should be revisited). What it does: the report guard (`lint/report_guard.py`, a Stop hook) finds each compaction by its `compact_boundary` record in the transcript. After a compaction it refuses each report that lacks a line `Recovered: <rulings or facts recovered>` or `Recovered: none`, or a line `Handoff gave: <facts the handoff supplied that the summary did not>` or `Handoff gave: none`, until each lands. Each line is tracked alone. The lines belong under Deviations. The guard accepts them in the report blockquote where the label starts an item: at line start, after a report label, or after "; " or ". ". A mid-sentence "recovered:" does not count. A reply after the compaction that holds a line ends that demand. A bare `Recovered:` takes the lines below it as its items; with nothing below, the line is missing. While the Recovered demand is pending, each item of the Recovered line (split on ";" outside parentheses) names its source as a whole word: git, page or digest. An item that starts with "none" or "nothing" needs no source. Handoff gave items need no source. Triage counts the Handoff gave lines at each roadmap review, to show how often the handoff gave something. The outcome lane for PR #982, handoff checkpoints below the compaction threshold, reads these counts later. Cost: no new log, file or process; it reads the transcript the hook already reads. It applies to every session that compacts, because the hook cannot know the session tier. Ruling home: the `session-tiers` record. Triage's reading side is prose with no check.

14. **A handoff keeps its required sections** (roadmap step `handoff-sections-kept`). Basis: its own mistake, 2026-11-08: a script edit cut a handoff after "Where things stand" and nothing checked until compaction. What it does: step 4 of the prompt file holds one marker line, `<!-- handoff-sections: A | B | ... -->`, the one list of required sections; no code copies it. `missing_sections` in `hooks/precompact_handoff.py` reads it from the installed prompt at run time and fails open: no prompt, no marker or an unreadable file gives none. The guard (`handoff-sections`, in `hooks/guard.py`) refuses a Write, Edit or MultiEdit to a session handoff whose resulting text lacks one, and names the missing sections. The Stop `--nudge` blocks once per handoff mtime for a handoff that lacks one, and keeps that mtime in the existing `<session>.nudge.json`. Cost: reads on demand inside processes already running. No new log, hook, file or process start. One small read of the prompt file and of the handoff per guarded Write or Edit to a handoff path, and per Stop.

Reason for items 8 and 9: after /clear or a fork a session started blind. After compaction a session could work a turn before it read its handoff. The guard refuses that work at each call it judges. The Stop refusal catches a turn that ends unread. Reason for item 10: a compaction summary and an old handoff hold beliefs with no source.

A handoff is a short-term note. It is never a ruling's only home (`memory-is-never-a-rulings-only-home`).
