# Checkpoints keep the handoff current

## Ruling

Auto-compact drops detail. These rules keep the handoff and plan current across a compaction, in every repo that uses claude-settings.

1. The compact window is read in Claude Code's order. First, env `CLAUDE_CODE_AUTO_COMPACT_WINDOW`. Then `modelSettings.<model>.autoCompactWindow`: the exact key first, else any key that equals the model once a trailing `[...]` tag and a `-YYYYMMDD` date are stripped from both. `<model>` is the model on the last main-chain assistant entry with token usage. Then top-level `autoCompactWindow`. Then the default, 500,000. `settings.json` sets `"autoCompactWindow": 500000`, a token count, as the repo default.
2. Owner, 2026-11-01 19:27 CST: the checkpoints follow Claude Code's own compaction trigger, so the last one fires before compaction in cloud, desktop and terminal sessions. The threshold mirrors Claude Code 2.1.316 (`compact_threshold`): E = window - 20,000; threshold = min(E - E x f, E - 13,000). Claude Code compacts at the second term and starts an early summary at the first; the hook takes the lower, since what an early summary keeps is not read. f is the summary fraction from Claude Code's cached flags in the Claude config file (`summary_fraction`: the `tengu_amber_moleskin` table, then `tengu_amber_rokovoko`, then 0.2). `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` = p lowers the second term to E x p / 100, as in Claude Code (cloud sessions set 80: 384,000 on 500k). The window values accept a `k` or `m` suffix. The hook cannot read the session's live `autocompact_state`, so it reads the same cached flag. Measured on 500k: 384,000 (f 0.2, 2026-10-28) and 441,600 (f 0.08, 2026-11-01). The session updates its handoff at message checkpoints, while it has full context. Messages = the last usage sum minus the first turn's usage sum, a proxy (record `hook-inputs-carry-token-counts`). The room is the threshold minus that first turn. The checkpoints: 200k messages, then every +150k below the top, then a last one at the top. The top is the room minus 50k, or minus half the room when the room is under 100k. With no room left, the top is the room minus 50k. A step under 75k below the top is dropped, the 200k one too. A session with no messages never gets one. After each compaction, auto or manual, it rewrites the handoff whole: what is true now, nothing appended. It updates the plan file too, when it works from one and the plan's state changed. Cost: one read of the Claude config file at each Stop; none at PreCompact; no process start, no file written beyond the existing state. Known gap: a model window smaller than the settings window is not read (debt store notes).
3. After compaction, a short message reorients the session.
4. It must work in the desktop app with no other login. No second `claude -p` with its own command-line login. So no mode of `hooks/precompact_handoff.py` calls a model.
5. The handoff is per session and outside git: `~/.claude/handoffs/<session_id>.md`. A repo's own handoff.md is a project document, changed only by PR. Reason: a scratchpad handoff was lost when something outside the session deleted that folder, and a shared, committed handoff would conflict on every PR. Rulings still go to tracked homes at once. The handoff is not in `state/handoff/` beside the digest, because `hooks/guard_frozen.py` freezes `state`.
6. Every mode fails open: on any error it logs and exits 0. PreCompact never refuses compaction. The Stop nudge refuses once at each new checkpoint and stays silent after a compaction and when `stop_hook_active`.
7. `hooks/precompact_handoff_prompt.md` tells the session how to rewrite the handoff. It uses the path the reorient message names, never a scratchpad or temp folder. It rewrites the whole file and never appends or makes a dated copy. Reason: patching let sessions append block after block, and rulings with no home sank under them.

Owner, 2026-10-13 11:20 CDT: the reorient and re-read hooks live in claude-settings. Each is a Python hook registered in `settings.json`, with a red test first. The /safe-stop entry point into `precompact_handoff` stays stable.

8. **Reorient after /clear or a fork.** SessionStart has the sources `clear` and `fork`, with no previous session id.
   - On `clear`: a SessionEnd hook with reason `clear` writes a pointer, the old session id and the project directory. SessionStart reads the newest pointer for the same directory and names that handoff. A /clear pointer whose session has no handoff names none.
   - On `fork`: no pointer is read, because a pointer can name an older cleared session. The hook names the newest handoff for the same directory, which is the parent's.
   - A session's project directory is recorded each time a handoff hook runs for it (nudge, PreCompact, SessionEnd).
   - With nothing found, it says so. The session reads the named handoff and rewrites its own handoff from it.
   - At SessionStart reorient, stale pointers and `.dir` and `.reread` files are swept after 30 days (`STALE_AGE`, Claude Code's default `cleanupPeriodDays`). A malformed pointer is swept in every directory. A pointer with no handoff is swept only in the current directory. A failed pointer delete is logged.
   - After compaction, the reorient message ends with the owner feedback inbox note. After /clear or a fork, it has none.
9. **Re-read check after compaction** (`hooks/reread_check.py`). A PostCompact hook sets a flag for the session. A PreToolUse hook on Read clears the flag when the path is the session's handoff. A Stop hook refuses once per turn while the flag is set and the handoff file exists, and names its path. It exits on `stop_hook_active`, so it cannot loop.
10. **Premises.** The handoff holds a Goal line and a `## Working premises` section, right after the rulings with NO HOME YET (step 4 of the prompt file). The reorient message lists the premises to check: after compaction every one but a `ruling`, after /clear or a fork every one. A handoff with no premise line gets "no Working premises section" and a pointer to step 4. The prompt file's "Check premises" step says to check a weak or stale premise before acting, then rewrite its line. The line format and the source kinds: `premise-format`. The Stop nudge points at step 4 and copies no section list. A Read inside an agent (payload has `agent_id`) never clears the re-read flag.
11. **Digest from the last rewrite** (owner, 2026-11-01 19:27 CST). The PreCompact digest holds the user and assistant text written after the session's handoff file was last written (its mtime), at most 200,000 characters, newest kept. With no handoff file, the last 60,000 characters. A `## Refused acts` section follows: one line per tool result that a hook or permission refused after that time, at most 50. Reason: after the 2026-11-01 compaction, a session retried acts refused before it, because tool results were in neither the digest nor the handoff.

Reason for items 8 and 9: after /clear or a fork a session started blind. After compaction nothing checked that it read its handoff. Reason for item 10: a compaction summary and an old handoff hold beliefs with no source.

A handoff is a short-term note. It is never a ruling's only home (`memory-is-never-a-rulings-only-home`).
