# A brief's claim about main carries the probe that showed it

## The ruling

Rule `brief-claim-has-probe` in `hooks/guard.py` refuses an Agent or Task brief to a builder or a test-author that claims what main passes or refuses for an input. Main here is main, origin/main or "today". The verbs are passes, allows, accepts, refuses, rejects and blocks. The brief passes when it carries the probe that showed the claim. Its home is `brief_claim_gaps` in `hooks/guard.py`, beside the other brief checks (`marker_scan`, `builder_third_round`). Layer: the coordinator's order, 2026-11-07 CST, after the incident below. Review rounds 1 and 2 of PR #1664 (this rule's PR) found thirty edges the first builds missed or wrongly refused; they are closed here.

- The mistake (2026-11-07 16:08 CST, PR #1581): a test-author brief said main passes `globalHotkey: Ctrl+Alt+2` and "password: none for guests and visitors". Main refused all of them. The brief was written from memory of main. The builder narrowed the rule to match, and the narrowing let through secrets that main refuses. A fix check caught it before merge.
- The harm: an agent builds to a false picture of main. The error is shipped as a test or a rule, and it looks reviewed because the brief said so.
- An input: a backtick span, a double-quoted string, or a single-quoted string that opens after a non-word character. A double-quoted string that holds backticks is one quoted data span, so a quoted case text such as `"main refuses 'X'"` written with backticks is data, not a claim. A lone quote or an apostrophe (`Don't`) opens nothing. A lone backtick reads to the line's end.
- A claim, active form: `main` or `origin/main` (a backticked `main` is still the word) with the verb next to it, or one adverb between (still, also, now, today, currently, already, even, always, never). Or "today" followed by it, they, guard, hook, rule or check, then the verb. "The main session" and "the main checkout" have no verb next to main, so they are no subject. "Today the builder passes ..." names no subject from that list, so it is a time word. The inputs are those after the verb, else every input in the clause.
- A claim, passive form: `X` is refused on main, `X` refused by main, `X` passes today. The inputs are those before the verb.
- Verbs: passes, allows, accepts, refuses, rejects, blocks, and their -ed forms. A negated verb counts: `does not`, `doesn't`, `did not` or `didn't` before pass, allow, accept, refuse, reject or block. So does `lets X through`, and `doesn't let X through`.
- Clause scope: a claim clause ends at ", so", ", and" or ", then". "origin/main passes CI, so run `verdict pytest` first" claims nothing about `verdict pytest`.
- A claim split from its inputs: a claim clause with no input of its own may say both, all, them, it, each or these. It then takes the inputs of the sentence right before it, or of the whole run of list lines right before it. A claim clause with no input that ends with `:` takes the inputs of the list lines after it.
- Fenced text is read for claims. A claim in a fence after `Cases:` counts.
- A path is a locator, not an input, when it follows in, at, from, under, inside, within or `via` and has no space and holds `/` or `.`.
- A `Must deny:` or `Add a case:` line is read like any other line. Its case text is data when it is double-quoted (see input). An unquoted claim on it, such as `(main allows 'x: y' today)` with backticks, is read.
- A claim sentence with no input names nothing to probe and is not judged.
- A probe for an input: a command line that holds the input as the whole text between quotes, or as the whole line, with a result line right under it. A longer input that merely contains it (`git push --force` for `git push`) is another input. The command line stands on a line of its own, in a fence, in backticks, or after `$ `. It starts with python, python3, git, verdict, bash, sh, node, npm, npx, pytest, gh, grep, rg or jq. Any number of these prefixes may come first: `cd <dir> &&`, `echo ... |`, `NAME=value`, `time`. The result line is the next non-blank line, or text after the closing backtick on the same line. The input may stand in the result line the same way. A line that holds a claim is a claim first, so a claim line is never its own probe. A command with no result line, or a result line with no command, is no probe.
- Scope: the roles `builder` and `test-author`, on an Agent or Task call. A reviewer, Explore, designer or any other role passes. A Workflow `agent()` call is not read.
- The scan is one pass over the lines. A claim on any line, line 30 and later too, is read.
- The refusal names every input with no probe, and the remedy: add the command and its result, or drop the claim. It names no forbidden target.
- The override lifts it (`owner-override`). It is not in `never_lifted`: the owner may mean the brief as it stands.
- Accepted limits: a claim in other verbs (`denies`, `fails`) or other words (`on the main branch`) is not read. Other negations (`won't`, `isn't refused`) and a passive "let through" are not read. A referent looks back one sentence or one run of list lines, never further, and not past a clause break in its own sentence ("Fix 'X', and main refuses it." names nothing). A list of three joined by ", and" loses its last item to the clause break. A claim written inside a double-quoted string that holds backticks is data, and a stray double quote (an inch mark) can open such a span. Only the four probe prefixes above are read. A command that reads its input from a file, with no quotes around the input and no result line that quotes it, is no probe: put the input on the command line in quotes. No case pins that a referent after a list takes every list line, not only the last one. These are forms Claude is unlikely to write by mistake (`guard-guards-mistakes-only`).
- Cost: pure text work inside the guard call already running. No process start, no file written, no log line beyond the refusal's own.

Protected by the `brief-claim:` cases in `hooks/test_guard.py` (28 deny, 22 allow, 50 in all), red before the rule landed. The mutants in `hooks/mutate_guard.py` labelled `brief-claim:` break each edge once.
