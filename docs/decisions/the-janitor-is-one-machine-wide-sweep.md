# The janitor is one machine-wide sweep

## The ruling

The sweep deletes a local branch that holds no unique work. It also removes a spent worktree.

- **One copy, in `janitor/`.** The subject is the machine: the liveness oracle reads `~/.claude/sessions`, and worktrees sit under many repositories. Five copies are five things that can each be wrong about one machine. The directory joins `landed-dirs.txt` and `CONFIG_FROZEN_DIRS` in `hooks/guard_frozen.py` in the same change. A session must not rewrite a program that deletes branches.
- **Parent and child.** The parent ships the branch and worktree tiers. They run git and the liveness oracle (`git_reads.worktree_live_session`). A child repository keeps its own process tier and service teardown, because they name its own files, servers and launchd labels. This repository ships the guide for writing one. Banchi keeps its own tier 2 until the owner names its removal. Two generic process tiers live here. `find_loose_processes` is report only, and runs only in the scheduled job and a person's run. `find_dead_rooted` stops only a proven orphan that the current user owns.
- **Stale registrations are pruned by git's own word.** The prune tier runs `git worktree prune -n -v`, acts only on what that names, and only under `--confirm`. The sweep keeps no second rule for "stale".
- **A stale agent lock does not keep a worktree.** The Agent tool locks an agent's worktree with the host Claude pid, not the agent's, so the lock outlives the agent. The sweep frees the worktree only when the host pid is dead, or alive with another start time, and every other check passes. A lock with no start time is freed only when its pid is dead. The caller's own lock is the one exception for a live pid (owner, 2026-10-25, step c44). Its pid is the sweep process or one of its ancestors. It goes only when the tree is clean, HEAD is in the default branch, the tree is idle 30 minutes (read under `--attended` too), and no process or live session is inside. The idle limit keeps an agent that just started at the default tip, or that a follow-up resumes. Any other lock reason, and any unreadable fact, an ancestor read included, keeps the tree.
- **Worktree removal.** When a worktree may be removed is in `when-a-worktree-may-be-removed`.
- **Every `--confirm` run leaves a trace.** The automatic runs are the SessionEnd hook (`janitor/session_end_sweep.py`) and the daily job (`janitor/install_launchd.py`). Both pass `--confirm`. `--tier1` acts without `--confirm` and writes no run-log line. A hook may run it (`janitor/GUIDE.md`). A `--confirm` run appends one line per repository to `${CLAUDE_CONFIG_DIR:-~/.claude}/state/janitor-runs.jsonl`. The file keeps the last 2000 lines, plus each repository's newest line older than those, at most 200 such lines (`MAX_RUN_LOG_LINES` and `MAX_RUN_LOG_ROOTS` in `janitor/sweep.py`). So a preview still finds each repository's last run. A preview writes nothing. The sweep lists unregistered entries under `<root>/.claude/worktrees/` as strays and never deletes them. The sweep removes a worktree with git and never calls a repository's WorktreeRemove hook.
  - Reader: the sweep preview, without `--confirm`. The final report of a session offers this preview after the session's last merge (rule `reports-offer-sweep-after-merge`). The preview reads the file once per preview run and prints one line per repository: `last --confirm run: <time>, N worktrees removed, M branches reaped`, `none in <path>`, or `unknown (<error type>)`.
  - Cost: each `--confirm` run reads the whole file once per repository it appends for (unmeasured). Every append past the cap rewrites the file through a temp file and a replace. The lock is in-process only, so a second process that writes at the same moment can lose a line. A preview adds one read and no other work (unmeasured).
- **The daily job's logs have a reader and no cap.** The daily job runs `janitor/sweep.py --confirm` on macOS. Its stdout goes to `<config>/janitor/launchd-sweep.log`, and its stderr to `<config>/janitor/launchd-sweep.err.log` (`build_plist` in `janitor/install_launchd.py`).
  - Reader: `hooks/daily_note.py` for the err log. The note flags it when it is not empty and was last written in the window. The stdout log is read by the person who follows the note's line.
  - Cost: the daily job writes what it prints to both logs, once a day. The note adds one stat of the err log, on the first startup of a Central day. Growth per run is unmeasured.
  - No cap: launchd writes both logs, and a trim here would race the job.
- **A branch leaves "checked out" with its worktree, in the same run.** The sweep judges the freed branch by the normal no-unique-work rules. A kept worktree, or a failed removal, keeps its branch held.
- **`--tier1` is the one mode that acts without `--confirm`.** It prunes stale registrations and deletes husks, and removes only proven junk. `--branches` reaps branches only, holds every worktree's branch, and refuses the repository if git gives no worktree list.
- **Leftover folders are deleted only when proven twice.** A husk is a real folder under `.claude/worktrees/` that git does not list and that holds only names the repository gives in `huskNames`. The repository knows its own build output; the sweep does not. Only `--confirm` deletes, and only after the proof runs again right before the delete. The sweep never follows a link (`build-dirs-reaped-at-agent-end`). Any error, and an empty process table, keeps the folder.
- **The sweep never runs code a repository supplies.** A repository states its wishes in `.claude/janitor.json`, read as data. A repository that supplies code to a frozen tool can do everything that tool can do.
- **Automatic, and a repository opts out.** The sweep visits every repository that carries no opt-out file. The opt-out file is `.claude/janitor.json`, inside the repository, so it travels with a clone. The repository that pays the cost holds its own consent. An absent file means swept.
- **The default branch.** The sweep judges each repository against its own default branch, read in the order of `default-branch-read-order`. If none answers, the sweep refuses the repository out loud and reaps nothing there.
- **Two triggers.** A `SessionEnd` hook judges branches and worktrees only in the repository whose session ended (owner, Cockpit item 250 a, 2026-11-04 07:53 CST; coordinator reading, 09:47 CST). It passes `--session-end`. It stops this repository's orphaned listeners, and dead-rooted servers anywhere on the machine, so remnants do not wait for the scheduled job. It runs the simulator and temp-folder tiers. Past its deadline it runs none of the dead-rooted, simulator or temp-folder tiers; the next run does. It skips the loose-process report, which has no reader there. Cost: one hook process per session end (unmeasured). It starts two git reads (`git_reads.primary_checkout`), as `janitor/test_session_end_sweep.py` asserts. It starts one sweep process (`sweeps`), as `janitor/test_session_end_sweep.py` asserts. The dead-rooted read lists pids once; on macOS it also starts one `ps` per pid (unmeasured). Each clean worktree adds one process read for its own check (unmeasured). It writes one `janitor-runs.jsonl` line (`janitor/test_sweep.py`, class `RunLogTests`, pins one line per repository), and one restore-log line per reaped branch. `SessionEndHookStartsOneSweepProcess` (`janitor/test_session_end_sweep.py`) proves the hook's three starts. `SessionEndScopeTests` (`janitor/test_sweep.py`) proves the one pid-list read. The per-pid and per-worktree reads are unmeasured. Only that run has a deadline: a 12 s judging budget with a 7.5 s tail, so the sweep finishes inside the hook (owner, 2026-10-15 15:08 CDT, "make the janitor sweep finish"). That run judges the oldest idle tree first. Past its deadline it judges no more trees: each tree left is kept with the reason "not judged", and its folder stays. The scheduled job and a person's run have no deadline, so they judge every tree. A daily scheduled job sweeps every repository and runs every tier, the loose-process report included. The hook fails open, because a hook that can refuse the end of a session is worse than a leak. The installers write the job definition outside the repository and refuse to run from a linked worktree, except the live pin (`install-refuses-linked-tree`, the installer's linked-worktree rule). The daily job is a named exception to rule `outcomes-mechanize-rules` (owner ruling, Cockpit item 180, pick a, 2026-11-06 12:19 CST; home: the hooks rule under the `.claude` rules folder). Status: ruled (`stall-watch-exceptions-180a`). It is a timer, so its record must show the cost is less than the saving. The install's cost is pinned by tests. The saving is not measured, so the rule's timer condition is not shown. Cost of an install, per `outcomes-mechanize-rules`: the installer starts two `git` reads (the linked-worktree check) and no `launchctl` or `schtasks` (`janitor/test_install_launchd.py`, class `CostTests`, and `janitor/test_install_schtasks.py`, class `CostTests`). It writes a job file, a plist on macOS or a task XML on Windows. On macOS it also creates the log folder (note `janitor-log-dir-cost`). How often: once per install by hand. The job then runs daily at 03:17 on macOS, with no repeat interval. On Windows it runs daily with no repetition inside the day (the same two classes).
- **A reaped branch leaves a tombstone.** Before the delete, the sweep writes `refs/janitor/reaped/<branch>` at the tip and appends one line to a restore log. The commits stay reachable, so `git gc` cannot take them. The purge drops a tombstone after 90 days, aged by the restore log's own timestamp, never by the ref's mtime. The 90 days outlast git's own expiry of an unreachable reflog entry.
- **Liveness.** A record in `~/.claude/sessions/*.json` counts as live only when the id is alive and the recorded start time still matches, so a recycled id cannot inherit a dead session's claim.
- **Proof.** Each refusal gets a test arm that violates it, and the rebase ghost arm must go red against a keep rule that tests ancestry alone. Each new rule gets a row in `lint/rule_mechanisms.json`, or an argued `unmechanized` row.

- **Other tiers have their own records.** The Windows temp folder (`windows-temp-sweep`). The agent-end reap, which stops processes and reaps build folders (`agent-end-reap-stops-what-a-finished-agent-left`, `build-dirs-reaped-at-agent-end`). The process tiers (`unattended-sweep-stops-proven-orphans`). Idle simulators (`sweep-shuts-down-idle-simulators`).
