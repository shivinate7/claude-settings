# A pre-existing claim names a run on the base branch's tip

## The ruling

The pre-existing check, in the Stop hook `lint/report_guard.py` (rule `pre-existing-needs-main-run`), refuses a reply when a sentence makes a pre-existing claim and its line names no run on the base branch's tip. A false "pre-existing" lets a lane ship its own red. The batch or main then goes red. The check runs on any turn, landed or not. One refusal per turn lists the lines and joins any other reason. A rewrite after a missing-report refusal is checked too, once, as with the answered check.

**What it reads.** Each sentence of the last reply, outside fences, quoted text and inline code spans. A sentence that ends in `?` asks and claims nothing, but a claim in the sentence before a question is judged. A sentence is a claim when it holds a failure word (fail, red, broken, error, break, breaking, regress, flaky) and one of three forms:

- the word "pre-existing", "preexisting" or "pre existing", when it describes the failure. Next comes a failure noun (failure, error, regression), a preposition, or no word. A failure noun before a verb is the claim ("a pre-existing failure breaks CI"). A failure noun before a noun it modifies ("failure mode", "error handling", "regression test") is no claim, nor is a plural word before it ("tests error out"). Red, failing, broken or flaky right after the word is always the claim ("two pre-existing red tests"). A cause noun (issue, problem, bug, defect) is a claim in two cases. It is the cause of an earlier failure word, after "due to", "owing to", "caused by", "because (of)", "from", "since" or "as" ("CI is red, because of a pre-existing issue"). Or it is the subject of a failure verb, with up to four words between and no "that", "which" or "who" ("a pre-existing issue in the parser breaks CI", "the issue is breaking CI"). "Filed the pre-existing issue as a debt; it does not fail CI", "a regression test for a pre-existing bug" and "a pre-existing bug in the guard that breaks on empty input" are no claim. Or before it comes is, was or it ("the failure is pre-existing", "makes it pre-existing"). "A pre-existing test" or "the pre-existing guard" modifies another noun and is no claim. "Already red" needs "on", "at", "against" or "vs" before the base, "<base> is", "<base> branch", "<base> already" or "before this change". "The main branch is already red" names the base, and "the main job is already failing" does not (lane ruling, 2026-11-08 05:00 CST). A word joined to another by a hyphen (`pre-existing-needs-main-run`) is not the word.
- "already" and then red, fail, broken, there or present, in a sentence that names a base or "before this change". "Already red on the old code" names neither and is no claim.
- a failure word, "too", "also" or "as well", and "on" or "at" then a commit hash or a base, in one clause. A clause that starts with that ref ("fails here, on main too") takes the failure word from an earlier clause. A clause that holds only "too" after a clause with the failure word and the ref ("Lint fails on main, too") is the claim as well. A clause ends at a conjunction (and, but, so, while, because, since, although), at "as" (not "as well") and at "which", as well as at punctuation. A hash is 7 to 40 hex characters with at least one digit.

**What counts as a run on the base branch's tip.** One of these on the same line. A source inside an inline code span counts. "On <base> at <hash>", "on <base> at commit <hash>", "on <base> tip <hash>", "on <base> (<hash>)", "on <base> (commit <hash>)", "on <base> <hash>", "<base>@<hash>", or a CI run URL (`/actions/runs/<n>`) on a line that also says "on <base>". The base is main, master, or origin/<branch>. A bare "on origin/main" names no run. A hash with no base is no run. "On the PR head" is no run. Ruling: coordinator, 2026-11-08 03:52 CST.

**What is exempt.** A claim with a negator in the same clause before it (the answered check's list: not, n't, no, none, nothing, nobody, never, cannot, yet to). A claim followed by a colon, semicolon or dash, and then a clause that says only none, nothing, nil, zero or 0. "Found", "detected", "seen", "observed" or "so far" may follow, then "in", "on" or "for", "this" or "the", and one word ("Pre-existing failures: none.", "Checked for pre-existing failures; none found.", "none in this run"). Is, was or it before the claim voids this. "Pre-existing failures: none of them are mine" is a claim. A mention of the rule with an indefinite object ("a line that calls a failure pre-existing"). Quoted text and code spans are no claim. Fenced blocks are skipped.

Incident 2026-11-07: a lane report said a failure "fails on 32b5f8b8e too, pre-existing". `32b5f8b8e` was the PR's own head, not main, so the failure came from the PR. The lane had measured it on its own head.

Risk kind: likely risk. A lane that runs a failing test on its own branch can call the red pre-existing by mistake.

Cost: runs inside the Stop hook already running; no process start, no file written. `PreExistingNeedsMainRunTests` in `lint/test_report_guard.py` proves the verdicts.

Known limit: a line that names a run on main for one failure clears a pre-existing claim about another failure on the same line. The check reads the form "on main at <hash>", not that the hash is the tip of main, so a wrong hash passes. A cause noun before its failure ("Because of a pre-existing bug, CI fails") passes. A claim in other words passes (debt `pe-claims-in-other-words-pass`).
