# The reply judge reads every reply and never refuses

## The ruling

The Stop reply judge is `hooks/reply_judge.py`, a command hook (owner ruling 2026-10-12), because a prompt hook cannot exit on a field in code.

- Every Stop with a reply makes one model call, through `decision_watch.invoke_model` in `main`. A Stop with `stop_hook_active` true, or an empty reply, makes none.
- Owner ruling, 2026-11-25 12:11 CST, typed in the Sim Manager session's chat and relayed: "let's do this and just keep it log only so it doesn't interrupt anything for a day or two and we set some way to remember to review the log and decide if it should have teeth?" The idea is the owner's, 10:59 CST the same day: "maybe we keep a perpetual haiku agent for every one of my messages?" The judge reads each reply, not each owner message. The owner's review of the two newer rules is debt `reply-judge-log-review`.
- `main` sends the older prompt (`INSTRUCTIONS`: thirteen rules, eleven older and two newer) when `older` holds. `older` holds on Stop n of a session when `(n - 1) % SAMPLE_EVERY` is 0: Stops 1, 6, 11, and so on. Only Stops that carry a reply count (`count_this_stop`). It also holds on a reply that trips one of these: an Input Needed item (`has_input_needed`), the words "blocked on" (`BLOCKED_ON`), a Markdown table (`TABLE_SEPARATOR`), a GitHub search total (`SEARCH_TOTAL`), a cost ranking (`has_cost_rank`) or a claim about main (`has_main_claim`). Every other Stop sends `INSTRUCTIONS_NEW_ONLY`, with the two newer rules only. `build_prompt` adds the route rows to the older prompt only.
- Input Needed (`has_input_needed`) trips the older prompt on every Stop whose reply carries the Input Needed label (owner ruling 2026-10-25 23:40 CDT, "A"; it changes the sample-only ruling of 2026-10-13). The label is read in code from `LABEL_ORDER` in `lint/report_guard.py`; an empty or "none" item does not trip it. Reason: a handed-off step with no reason and no check was the incident of Oct 25, the ios-adblock App IDs hand-off. Cost: no call beyond the one every Stop makes; the older prompt is longer, so it costs more tokens (unmeasured).
- It also sends the older prompt on every Stop whose reply holds a GitHub search total, found in code by `SEARCH_TOTAL` in `hooks/reply_judge.py`: `total_count`, `totalCount`, `issueCount`, any `search/<endpoint>` path, or a search word (search, searched, searches, searching, as in `--search`, or joined by `_` as in `search_issues`; not `research`) within 120 characters of a count word (a digit, none, zero, no), in either order. The trigger is a code match: it cannot see a count worded with no digit or count word, and a quote past the 12000-character clip may be dropped from the prompt. The model flags a search total quoted as a count or a state (open, closed, merged, CI status). The prompt tells the model not to flag a count read from REST. A search that only finds candidates is exempt only when the reply says REST confirms each one; a search count with no REST confirmation is flagged. A reply that says a search total was not used or is wrong, and gives the REST count, is not flagged either (rule `verification-counts-from-rest`). Cost: process starts, none new; files written, none new. A Stop that holds the trigger words gets the older prompt on top of 1 in 5; a wider window means more such Stops (cost only, unmeasured). The match is one regex over the whole reply and runs before the model module loads.
- It also sends the older prompt on every Stop whose reply, outside quoted text, says a change matches main, is main's own, or is no worse than main, found in code by `MAIN_CLAIM` in `hooks/reply_judge.py`: "main's own", "same as main", "matches main", "no worse than main", "not worse than main" or "no regression". The trigger only selects the older prompt. The model flags such a claim when the reply cites no read of main (a path:line on main, a main screenshot or a read of origin/main), and never flags a claim that cites one (rule `verification-report-unknown-reads`). Reason: on 2026-11-20 a coordinator told the owner a layout was main's own without reading main; a regex refusal on reply prose cried wolf (PR 3068 and PR 3091, closed). Cost: process starts, none new; files written, none new; a Stop that holds a phrase gets the older prompt on top of 1 in 5; about 8 trigger hits in 7,500 assistant texts across the 60 newest transcripts, 2026-11-23, unmeasured beyond that sample.
- Three more triggers send the older prompt on every Stop that holds them: a Markdown table (`TABLE_SEPARATOR`, rule `style-table-gold-column`), the words "blocked on" (`BLOCKED_ON`, rule `questions-go-to-owner`) and a cost ranking (`has_cost_rank`, rule `measure-before-priority`).
- Each finding writes one line to guard.log through `log_finding` (`guard_core.record`, decision `noted`). Its rule is the first judged rule id the reason names, else `reply-judge`. Named reader of the older rules' lines: the advisor at each cull, who counts flags against owner-confirmed misses and false alarms, to rule whether the judge stays, widens or goes. Named reader of the two newer rules' lines: the owner, at his review. A failed write is swallowed. The cull reads these with `lint/guard_log_report.py`, not the never-fired list.
- Log only. A finding on a newer rule writes its line and prints nothing. On the older prompt, a finding prints its note on stdout (`hookSpecificOutput`, `additionalContext`), so the session reads it at the start of the next turn, unless its reason names only newer rules. The older rules keep their Stops and their note.
- A damaged, missing or unwritable counter means that Stop is judged. It never refuses and never crashes (`guard-hooks-fail-closed`). A frozen counter therefore means judge every Stop (owner ruling 2026-10-13 17:52 CDT).
- The model call is `decision_watch.invoke_model`, the one home. Model and effort are the reply judge row of the model table (`agent-model-cap`).
- The model call starts a second `claude` program that does not share the app's login. Every hook that calls `invoke_model` logs in with a token from `claude setup-token`, saved in `~/.claude/state/hook-token` on each machine and never in the repository. The guard refuses writes to that folder, not reads (accepted risk, debt `token-read-accepted-risk`).
- A finding never refuses (owner ruling 2026-10-13 11:33 CDT). The hook runs `async: true` and passes the finding as a note at the start of the next turn. Reason: a refusal came after the owner had read the reply, so the session sent the reply twice. The report-shape guard still refuses.
- The report guard, `lint/report_guard.py`, still refuses, but no refusal makes a session send its report twice (roadmap c101, the report guard never asks for the report again). A wrong Done label, a missing model name, a missing `Unstarted:` line or a bare record id gets a refusal that asks for only the corrected lines. Only a missing report is sent in full. Incident: on Oct 26 21:12 CDT a mailaudit session sent its whole report twice to fix one Done label and add model names.
- It fails open. An error, a timeout or an odd answer prints one stderr line, nothing on stdout, and refuses nothing.
- The model call times out at 20 s. Three runs took 6.6, 7.0 and 8.0 s on the owner's machine, and the Stop entry in `settings.json` allows 25 s.
- Cost, as the code comment states it: one model call per Stop with a reply, one guard.log append per finding, no process beyond that call, no timer. The counter is one file per session under the state folder.
- Limits: the judge reads the reply alone, not the turn, so a home filed in the turn but not named in the reply can be logged. Whether the judge's call can log in from a cloud session is unmeasured.
- Its older rules are `output-start-with-point`, `style-cut-narration`, `output-never-paste-passing-output`, `output-never-hand-off-doable-step`, `style-table-gold-column`, `questions-go-to-owner` (an Input Needed pick that can be undone), `style-limits-kept-silently` (a reply that narrates a limit kept or a check passed; a limit that blocked the work, a named skipped or dropped item, and a result line such as "tests pass" in Done pass), `style-question-form` (a recommended option that widens what a shared tool accepts, without the owner's widening label), `verification-counts-from-rest` (a search total quoted as a count or a state), `measure-before-priority` (a cost ranking with no measure, only when the same reply ranks or cuts work on it) and `verification-report-unknown-reads` (a claim that a change matches main with no cited read of main), listed in `OLDER_RULES`. The first five stay `unmechanized`; `questions-go-to-owner`, `style-limits-kept-silently` and `verification-counts-from-rest` are `judgment` in `lint/rule_mechanisms.json` until the hook catches a real defect.
- Its two newer rules, `NEW_RULES`, are judge rule ids, log only. They have no rule marker in CLAUDE.md. Both are read from `INSTRUCTIONS_NEW`:
  - `roles-finding-has-a-home` catches a reply that names a finding it made (a gap, a defect, a false alarm or a risk) and leaves it with no home (no record slug, debt, note file, PR or queued step) and no agent started for it. The fix is to file it as a debt or a note, or to start an agent for it.
  - `parallelism-wait-names-its-event` catches a reply that says it waits, holds or pauses and names nothing it waits for, such as an agent, a run, a review or a reply. The fix is to name the event the wait ends on.
  - Exempt, per the prompt: a finding or a wait that an Unstarted or Next line lists; quoted or negated finding words, such as "no false alarm", or a rule's text in quotes; a reviewer's or auditor's own report of its findings; a wait on named agents or background work the reply says it started.
