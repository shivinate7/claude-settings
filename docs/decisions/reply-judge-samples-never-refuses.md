# The reply judge samples, judges Input Needed, and never refuses

## The ruling

The Stop reply judge is `hooks/reply_judge.py`, a command hook (owner ruling 2026-10-12), because a prompt hook cannot exit on a field in code.

- It judges 1 Stop in 5 (Stops 1, 6, 11, and so on; only Stops that carry a reply count), plus every Stop whose reply carries the Input Needed label (owner ruling 2026-10-25 23:40 CDT, "A"; it changes the sample-only ruling of 2026-10-13). The label is read in code from `LABEL_ORDER` in `lint/report_guard.py`; an item that is empty or "none" is not judged. Reason: a handed-off step with no reason and no check was the incident of Oct 25, the ios-adblock App IDs hand-off. Cost: one extra model call per report that carries Input Needed, no new file, no new process, no timer.
- Each finding writes one line to guard.log through `guard_core.record`. Named reader: the advisor at each cull, who counts flags against owner-confirmed misses and false alarms, to rule whether the judge stays, widens or goes. A failed write is swallowed. A judge line carries the judged style rule id, or `reply-judge` when the reason names none; the cull reads these with `lint/guard_log_report.py`, not the never-fired list.
- A damaged, missing or unwritable counter means that Stop is judged. It never refuses and never crashes (`guard-hooks-fail-closed`). A frozen counter therefore means judge every Stop (owner ruling 2026-10-13 17:52 CDT).
- The model call is `decision_watch.invoke_model`, the one home. Model and effort are the reply judge row of the model table (`agent-model-cap`).
- The model call starts a second `claude` program that does not share the app's login. Every hook that calls `invoke_model` logs in with a token from `claude setup-token`, saved in `~/.claude/state/hook-token` on each machine and never in the repository. With no token saved, the judge gets `ANTHROPIC_API_KEY` from the calling process; with a token, the key stays out (owner, page item 541 pick b, saved 11:59-12:00 CST Nov 12, triage record 7fddabaf5; tests K1 and K2 in `hooks/test_decision_watch.py`). With neither, the child falls back to the credential file that `_judge_isolation` copies, or the `ANTHROPIC_BASE_URL` host's own auth, and the call goes ahead (test K3). A call that cannot authenticate returns an error of kind AUTH: the decision watch reports it as UNKNOWN, the reply judge fails open with one stderr line, and the streak file counts it. Limit: a token path that exists but cannot be opened (a directory, a permission error) reads as no token, so the key reaches the judge's env (`_hook_token` returns ''); no test pins it. `invoke_model` scrubs both values from error text. The guard refuses writes to that folder, so a session cannot make that path by mistake, but not reads (accepted risk, debt `token-read-accepted-risk`).
- Hidden key store (proposed, not built): a file `state/hook-api-key` beside `state/hook-token`, read for each judge call like `_hook_token`, token first, key second, then the copied credential file. A session cannot write to `~/.claude/state`, so the owner or a setup step writes it. Reads are not refused (debt `token-read-accepted-risk`, in `docs/debts/notes.md`).
- A model call that cannot log in is never quiet (owner 11:43 CST Nov 6: "It never fails quietly"). At session start `decision_watch.py --auth-check` reads the token file (one read). With no token file it makes one probe call through `invoke_model`. A cloud session logs in with no token file, so only the probe knows. With a token file, session start runs no probe: a probe costs about 2 s and $0.02 (one sample) per session start (coordinator ruling 2026-11-06 13:57 CST, process-only, on the owner's question of 11:43 CST). With a working `ANTHROPIC_API_KEY` and no token file, `auth_check` returns '' on a probe that succeeds and sets no mark. So the probe runs at every session start, about $0.02 each, billed to the key (test C2 shows one probe per start). The probe prints one `systemMessage` line when the call fails to start, times out or exits non-zero. The line names the fix when the error names a lost login (kind AUTH), and the fix shows once per missing token. A run error (kind RUN: a timeout or a failed start that names no login) prints a line with no fix, and may repeat. A reply that ran but was off-shape is a working login and stays silent. A reply that contains "/login" or "not logged in" is a login prompt, and it prints the fix line. `invoke_model` also counts each session's consecutive failures in one small file under `state/model-streak/` (one write per outcome change), and the Stop hook `stall_watch.py --stop` reads it (one read per Stop). The first failed call of kind AUTH adds the line "Model calls: N failed in a row" with the fix at once (coordinator pick 08:28 CST Nov 12). A failed call of kind RUN adds it from 3 in a row on, with no fix line. A judge call that succeeds clears the fix mark, so a login lost again shows the fix again. Known gap: a session with a revoked token and no judge call says nothing, because a session start with a token file runs no probe. No token is printed or written.
- A finding never refuses (owner ruling 2026-10-13 11:33 CDT). The hook runs `async: true` and passes the finding as a note at the start of the next turn. Reason: a refusal came after the owner had read the reply, so the session sent the reply twice. The report-shape guard still refuses.
- The report guard, `lint/report_guard.py`, still refuses, but no refusal makes a session send its report twice (roadmap c101, the report guard never asks for the report again). A wrong Done label, a missing model name, a missing `Unstarted:` line or a bare record id gets a refusal that asks for only the corrected lines. Only a missing report is sent in full. Incident: on Oct 26 21:12 CDT a mailaudit session sent its whole report twice to fix one Done label and add model names.
- It fails open. An error, a timeout or an odd answer prints one stderr line and refuses nothing.
- The model call times out at 20 s. Three runs took 6.6, 7.0 and 8.0 s on the owner's machine, and the Stop entry in `settings.json` allows 25 s.
- Its rules are `output-start-with-point`, `style-cut-narration`, `output-never-paste-passing-output`, `output-never-hand-off-doable-step`, `style-table-gold-column`, `questions-go-to-owner` (an Input Needed pick that can be undone) and `style-limits-kept-silently` (a reply that narrates a limit kept or a check passed; a limit that blocked the work, a named skipped or dropped item, and a result line such as "tests pass" in Done pass). The first five stay `unmechanized`; `questions-go-to-owner` and `style-limits-kept-silently` stay `judgment` in `lint/rule_mechanisms.json` until the hook catches a real defect.
