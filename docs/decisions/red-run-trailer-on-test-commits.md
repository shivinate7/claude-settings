# A commit that adds test lines carries the red run of those lines

## The ruling

`lint/check_red_run.py` is the one home. CI runs it on each pull request (step "Red-run trailer" in `checks.yml`), with `BASE_SHA` set to the PR base. The test-author runs `python3 ~/.claude/lint/check_red_run.py --base origin/main` before it pushes, in whatever repo it works in (`agents/test-author.md`).

1. It reads each non-merge commit in `<base>..HEAD`. A commit that adds lines to a test path needs a trailer in its message: `Red-run: <command> -> <N> failed on <sha>` (N is 1 or more, sha is 7 or more hex digits), `Red-run: mutant: <mutation> -> <N> failed on <sha>`, or `Red-run: none: <reason>`.
2. A test path is what `is_test_rel` in `hooks/guard.py` judges. The check imports it and keeps no copy.
1a. A message passes only when it has at least one `Red-run:` line and every `Red-run:` line is valid. One malformed line fails the commit, even beside a valid one. A line counts as a `Red-run:` line at line start and in any case in two ways. First, a key of `red`, any run of spaces, underscores or hyphens (or none), `run` or `runs`, then optional spaces and a colon. So `Red-Run:`, `red-run:`, `Red-run :`, `Red-runs:`, `Red run:`, `Red_run:` and `Redrun:` are malformed lines. Second, the same key with no colon, only when the line also ends in `-> <N> failed on <sha>`, so `Red-run python3 x -> 1 failed on abc1234` is a malformed line. A bare line-start "Red run" with no colon and no such tail is prose, because eleven main messages carry valid trailers and begin a line that way. Prose that mentions red-run mid-line, and words such as `Redress:` or `Reduce:`, are not judged. The failed form judges the first word of its command in two layers, so a typo is not read as a command that never ran. First, it refuses a word that starts with `mutant` or `mutation` (in any case, glued forms included: `mutants:`, `mutation:`, `mutant(A)`, `mutant-A`, `mutantA:`, `mutant=x`, a no-colon `mutant A (...)`), or is exactly `none` or `non` once a trailing colon is dropped. Second, it refuses a word that starts with `mutat` or `mutan` (`mutate`, `mutated`, `mutating`, `mutan:`), or that ends in a colon (`runner:`, `nonee:`, `mutnat:`). An environment assignment (`NAME=value`, quoted or not) is exempt from this layer. The exemption keeps real prefixes such as `MUTATE_ONLY=x` and main commit 049f8d8c0's `MUTATE_ONLY="worktree-home: ..."`; `mutant=x` stays refused by the first layer. The valid `mutant:` and `none:` lines are routed to their own forms first, so neither layer reads them. `mutant_like` in the check is the one home of the mutant-like refusal and `refused_word` of the none and colon refusals. Real commands pass (`python3 ...`, `MUTATE_ONLY='x' python3 ...`, `NONE=1 python3 ...`, `env X=1 python3 ...`, `nonstop ...`, `mutmut run`, `./mutation_probe.sh`, `make test`). The FAIL line names the mutant form when a refused line is mutant-like. Ruling, coordinator, 2026-11-07 18:45 CST; lane pick, process-only, 2026-11-07 18:55 CST: the no-colon mutant lines are refused going forward. Three main commits (408340997, 1762ec79f, b2f0fb754) wrote the no-colon mutant form.
3. `Red-run: none: <reason>` is for a change that adds no new claim, such as a re-pointed fixture. A reviewer reads each reason, because a junk reason passes. `Red-run: mutant: <mutation> -> <N> failed on <sha>` is for a pin that passes on the old code and goes red only on a mutant. The mutation is non-empty, N is 1 or more, and the sha has the shape of the failed form's (7 or more hex digits). A line whose keyword reads `mutant` is judged by this form alone. The mutant pattern takes `Red-run:`, then any whitespace or none (a tab, or no space: `Red-run:mutant:`), `mutant` in any case, any whitespace before the colon, the colon, then one or more spaces (a space, then any more whitespace). The failed and none forms need a literal space after `Red-run:`.
4. A commit that only deletes test lines needs no trailer. A merge is not judged; the commits it brings in are.
5. Rollout: when the tree at HEAD holds `lint/check_red_run.py`, a commit whose parent tree has no such file is not judged. The commits from before the check landed stay as they are. The check reads this with `git ls-tree HEAD`, never from disk. In a repo whose HEAD has no such file, each non-merge, non-revert commit in the range is judged.
6. The check reads the repo it runs in: the current directory, or the folder `--root <dir>` names. It imports `is_test_rel` from its own install (`../hooks/guard.py` beside the script), never from the repo it reads. Other repos get the check from the installed copy at `~/.claude/lint/check_red_run.py` now. Their CI runs it later, through a separate lane. This repo's CI step stays as it is.
7. A commit whose message has git's `This reverts commit <sha>.` line is not judged. Its lines were judged once already, when the commit it reverts landed.
8. A range git cannot read, or a run with no base, prints UNKNOWN and exits 2. It never exits 0, locally or in CI. This differs from the shape in `ci-unknown-is-red`, where an unknown read exits 0 locally and non-zero only when env `CI` is set.

Why: the plan found 17 red runs recorded for 29 test changes (`docs/plans/test-ci-standard.md`, standard S5, step 2). A test that was never seen red on the old code may not be able to fail. `agents/test-author.md` names the trailer as the record of the run. The mutant form came from two pins whose mutant went red but whose only valid trailer was `none` (commits 57526aaec, a regex widening, and 18b628f73, a dropped lookahead): the record said the case never failed.

Incident: three main commits, 408340997, 1762ec79f and b2f0fb754, wrote the free-form `Red-run: mutant A (...) <command> -> <N> failed on <sha>` line with no colon after `mutant`. The failed pattern read them as a command named `mutant`, so a typo passed. The history pin in `lint/test_check_red_run.py` exempts those three commits and no others; main's history cannot change (lane pick, 2026-11-07 19:22 CST).

Known limits:

- The check reads that a run is claimed, not that it ran. A reviewer re-runs a claim only when the claim is in doubt (`roles-each-layer-proves-once`).
- The mutant sha is checked for shape only, like the failed form's: never that it names a commit, that HEAD reaches it, that the mutation was made or that the named case went red. Lane pick, process-only, 2026-11-07 18:29 CST: a reach check raised false alarms after a rebase or the cherry-pick remedy, which rewrite the commit a sha names. The open note `red-run-sha-not-verified` holds the gap.
- A real command whose first word ends in a colon is refused as a keyword typo, unless it is a `NAME=value` assignment. Write the command another way, such as with a leading `env`.
- A pure rename of a test file reads as a delete and an add, so it needs `Red-run: none: <reason>`.
- A branch that merged a newer main carries main's commits in the range, and each is judged like the rest.
- A lane begun before the check landed escapes for its commits from before that, unless it is rebased.
- Conflict-resolution lines in a merge commit are not judged.
- Mutation tests are not test paths, so they need no trailer.
- The check path is fixed in the check. Renaming the check turns it off.
- In a repo whose HEAD has no `lint/check_red_run.py`, a range that reaches back past the repo's first trailered test commit judges old commits too (item 5). The test-author's `--base origin/main` keeps the range to its own lane.

Risk kind: likely risk, per `building-guard-needs-incident`. Test-author work adds new tests in normal work, and 12 of 29 recorded changes carried no red run. Landed 2026-11-01.

Cost: no long-lived process, no log, no timer. One python process per run, once per pull request run and once per test-author push. It starts these git children. One `rev-parse` and one `log` read the range, and one `ls-tree` reads HEAD. The mutant form adds no extra git child. Each non-revert commit in the range then costs one `diff`. When HEAD holds the check, each also costs one `ls-tree` first, and the `diff` runs only when the parent tree holds the check.
